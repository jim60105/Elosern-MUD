# Design

## Context

`LocalMap.vue` supplies `canvasSize=240` to `MapLattice.vue`. `use-map-lattice-geometry.js` currently owns `ISLAND_MIN_SCALE`, `islandWindow`, `windowed` and pitch iteration. The same renderer also serves MapOverlay, and variant=graph handles interiors/instances. The approved projection is isolated in the predecessor change. Existing fixture coordinates are mostly unit-spaced, so they miss metric clipping.

## Goals / Non-Goals

Cut over the coordinate-bearing island geometry/background and establish metric story evidence. Keep shared rendering, overlay lattice and radial graph paths intact. Gateway button/label collision policy and scale-sensitive animation have explicit later owners; do not duplicate those algorithms here.

## Decisions

In `LocalMap.vue`, compute projection as presentation state and retain the returned previous level by current-node map key. Changing rooms within a map must not reset hysteresis; changing grid map, wilderness map or switching out of a coordinate-bearing layer clears it. Do not persist level to local storage, game state or the authoritative model. Pass the projection into the existing shared renderer/geometry seam.

Branch only for `canvasSize != null` AND variant=lattice. Consume projection positions instead of model col/row, with a fixed 0 0 240 240 viewBox and no SVG label shrink. Remove `islandWindow`, `windowed`, `ISLAND_MIN_SCALE` and island pitch iteration when no longer referenced; preserve graph fixed-window geometry independently and `canvasSize == null` overlay calculations byte-for-behavior. Existing overlay-only `cellSize` and lattice placement remain.

Join projected IDs back to the original node models for full names, visibility and actions. Current and exit markers retain the state shape ladder; context is a small background dot, with no connecting line. Render only labelled one-hop edges from current, including blocked exits. Filter cross-layer target node groups entirely, preserving returned stub descriptors for the labels/gateway change. Keep remembered remote nodes on existing named edge-direction markers and their assistive mirror.

Replace the stationary island SVG dot pattern with the projection's bounded world-anchored dot list. At a uniform level dots are 20 user units apart and show `格距 <spacing>` at the 16 px floor separately from the unchanged current-coordinate readout. Compressed mode replaces dots with concentric readable labelled rings using projection radii; shape and text distinguish it without colour dependence. Keep decoration pointer-inert and token-driven; separate visible distance text from node audit classes. Preserve the overlay's background/pattern and existing graph decoration behavior. Existing `.elosern-root` overrides must be checked where changed component classes occur, not copied into a second convention.

Create fixed metric fixture families in `stories/fixtures/local_map.js` using exact authored source coordinates in world-map-scale design §8 (21 Altoria nodes) and §9 (10 Ciaran nodes), with current/one-hop/two-hop classification matching payload semantics. These fixtures represent data, not a request to reveal unseen nodes in production. Keep the full authored coordinate corpus in fixtures and use bounded payload views for individual current positions. Also include a wilderness 3x3, Altoria south gate and an extreme 80 m/1200 m ratio. Preserve all unit-coordinate overlay fixtures. Each gets a `World/LocalMap` story using `localMapModelFor`, with play assertions comparing actual rendered exit-marker bounding boxes to canvas bounds and one another. At this slice's gate story, same-layer exits are asserted; the dependent gateway change extends the check to cross-layer stubs. The final batch must assert the complete exit set.

## Risks / Trade-offs

The existing main requirement repeats uniform-island and fixed-window clauses across many scenarios. This delta copies its entire block and scopes those clauses to the unchanged overlay/graph or replaces them with island auto-projection clauses. The same requirement is modified cumulatively by the label change, so sync in batch order and retain predecessor scenarios. Compression is the approved island-only amendment to the parent metric design; no other metric consumer changes.

## Verification workflow (required during implementation)

Use `World/LocalMap` as the production component showcase and retain `Overlays/MapOverlay` plus the instance/interior stories as unchanged-surface controls. No `Design/...` prototype is needed for this approved algorithmic change; if an existing relevant Design story is used for token/chrome comparison, it cannot replace a production-component story or the real client.

Read the agent-browser skill, start the repository's existing Storybook command (`pnpm run serve-storybook`), navigate to the affected story, take an interactive snapshot, and capture a screenshot with agent-browser. Inspect the actual image for missing exits, clipping, label readability and shape/text mode distinction. Refresh element references after each story or payload change. Record story IDs, viewport, screenshot locations and observed results in the implementation handoff. Automation play assertions do not replace this visual step. The renderer and later changes must also inspect the real client because `.elosern-root` rules in `styles/app-shell.css` can override component styles absent from Storybook.

Run only the smallest focused Python label, Node file, Vitest file or managed-browser method/class that covers the changed assertions, one short batch per command. Python always uses `uv run --locked`; Evennia uses `uv run --locked --env-file=<test-env-file> evennia test --settings test_settings.py --keepdb <label>` with `MUD_TEST_SETTINGS=1` inside that env file. Use the single-token env-file spelling. Run a browser method with `uv run --locked python -m web.tests.browser.unittest_driver <module.Class.test_method>` and capture its output once. No local full suites, shard commands, complete showcase matrix or `spec_traceability verify --evidence`; keep each local command below ten minutes and browser files below five CI minutes.

For every requirement, map the concrete scenario to matching assertions. Obtain literal IDs with `uv run --locked python -m tools.spec_traceability list`; for newly added requirements run that tool on an equivalent spec tree with predecessor and current deltas synchronized, using its documented root option, without prematurely modifying the live main specs. Never hand-construct IDs. Decorate discoverable Python `test_*` methods with `covers_requirement` imported from `tools.spec_traceability`. JS-only behavior needs a focused Python executed-evidence wrapper that actually runs the relevant file and asserts success, reusing existing evidence patterns; a source-presence assertion cannot substitute for execution. Keep existing IDs when titles are unchanged and review their matching assertions after each modified contract. Run `tools.spec_traceability check` while editing and against the synchronized main contract at archive time; a pre-sync pass alone is insufficient.

Add/rename/move any non-browser Python test module only with an exact single-owner update in `.github/evennia-shards.json`. Add every new browser test class or method to `.github/browser-shards.json` in the same feature commit, without overlapping class/method ownership. Reusing an already registered module does not need a fabricated manifest change; record that ownership is unchanged. Run the focused shard-ownership contract if ownership changes, and finish with `uv run --locked python -m tools.contract_gate` and `openspec validate <change> --strict`. Before archive also run the focused `tests.test_evennia_test_optimization_contract` and `tests.test_webclient_frozen_contract` labels as required by AGENTS.md.

No new operational logging is needed for pure projection/render work. Preserve existing boundary observability. Any changed exception/logging path must use named imports from `world.observability`, stable English event IDs and business identifiers in context; patch the caller binding in tests and run `uv run --locked python -m tools.observability_lint check` with the focused tests. Do not add logging imports, silent swallowing, a freeze-list entry or a new telemetry subsystem.
