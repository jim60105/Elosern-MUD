# Design: remove-onboarding-tutorial

## Context

Authoritative design: `docs/superpowers/specs/2026-09-04-onboarding-removal-one-way-limbo-design.md` (approved). The onboarding subsystem spans `world/rules/onboarding.py`, the `world/onboarding/` package, four persisted character attributes, a startup sync step (`sync_guard_npc` creating the South Gate guard NPC tagged `onboarding_guard`), command/webclient call sites, and the `onboarding-guide` main spec. Future race-based starting cities make a per-city tutorial copy unaffordable, so the subsystem is deleted wholesale; onboarding meaning becomes "read the author's static material in 虛境, then leave". This change is the removal slice only: the one-way Limbo↔city gate rework (`world/maps/city_gates.py`, `bootstrap.py` exit pruning) is the sibling change `limbo-one-way-city-gates`, and the `STARTER_EPITHET` grant-hook migration is the title-system change. The project is unreleased with zero users — AGENTS.md mandates clean cutover: zero migrations, zero feature flags, zero deprecated aliases.

## Goals / Non-Goals

**Goals:**
- Delete `world/rules/onboarding.py`, `world/onboarding/`, the `OnboardingGuide` component, the four character attributes, and the `sync_guard_npc` startup step — no residue.
- Trim every production caller so behavior is otherwise byte-identical: scripted talk, guild quest flow (incl. `introductory_hunt` as an ordinary quest), movement settlement, map knowledge, webclient exploration/creation, affordances.
- Land characters born in 虛境 via *non-action*: simply stop relocating them at activation.
- Preserve scripted dialogue by moving the `guild_staff` table into its natural owner, `world/rules/dialogue.py`.
- Retire the `onboarding-guide` capability and ship 13 hook-wording trim deltas; keep `grid-room-sync`/`limbo-room`/`sample-city-altoria` bridge wording verbatim (sibling owns it).
- Trim the dead `guide` prop from the already-static HelpOverlay Vue surface (scope merged from the deleted `webclient-static-help-overlay` change).
- Keep traceability (0 uncovered / 0 errors) and observability lint (violations shrink-only) green; shards bookkeeping consistent.

**Non-Goals:**
- One-way gate exits, `city_gates.py`, `bootstrap.py` return-exit pruning (`limbo-one-way-city-gates`).
- `STARTER_EPITHET` flavor rewrite and grant-hook move (title-system change).
- 虛境 slate/stele teaching content, race→city selection, 南門→wilderness gate (explicitly not done in the design doc).
- Any player-command doc change — verified: `docs/game/commands.md` and `docs/game/command-reference.md` contain no onboarding entries, so `tests/test_command_docs.py` is untouched.

## Decisions

**D1 — Clean-cut delete list, no skeleton.** Delete `world/rules/onboarding.py` (state machine, `GUARD_NPC_KEY`/`GUARD_NPC_TAG`, `sync_guard_npc`, `relocate_to_starting_location`, `maybe_play_arrival`, `observe_room_entry`, `run_scripted_talk`, `set_onboarded`) and the whole `world/onboarding/` package; remove the startup step from `server/conf/at_server_startstop.py` and `STARTUP_STEP_ORDER`; delete `onboarded`/`guide_progress`/`onboarding_beat`/`first_arrival_seen` from `typeclasses/characters.py` and the `first_arrival_seen` snapshot field from `world/rules/movement_settlement.py`. Alternative rejected: keep the skeleton behind a flag — the skeleton's only reason to exist was serving the guard tutorial; a flag is a compat layer AGENTS.md forbids. The guard NPC stops respawning once sync is removed; dev-database residue is handled by reset, not a cleanup shim.

**D2 — `guild_staff` moves to `world/rules/dialogue.py`.** The `回報` keyword resolves the read-only reportable-quest listing — a guild function, not a tutorial function — and `dialogue.py`'s own docstring already claims ownership of that exception. Move `GUILD_STAFF_DIALOGUE_KEY`, `GUILD_STAFF_TURNIN_KEYWORD`, `GUILD_STAFF_RESPONSES` and the `DialogueDefinition` row into `world/rules/dialogue.py`, deleting the cross-package import; drop `OnboardingGuide` from `resolve_dialogue_component` (leaving `ScriptedDialogue`) and delete the component class from `typeclasses/components.py`. Alternative rejected: a new `world/rules/guild_dialogue.py` — one more module for three constants when the surviving runtime is already the declared owner.

**D3 — Birth in 虛境 via non-action.** Evennia's default first-character home is already Limbo (虛境), so removing the relocate + arrival calls in `commands/character_creation.py` *is* the new flow; no new provisioning code exists. `typeclasses/accounts.py` drops `maybe_play_arrival`, `typeclasses/characters.py` drops `advance_beat`, `typeclasses/exits.py` drops the `observe_room_entry` call. The webclient `creation.activate` adapter loses its best-effort relocation and its failure-degradation branch — activation now commits and hands off to exploration with the character still in 虛境 (delta on `webclient-character-creation-ui`).

**D4 — Scripted talk seam unifies on the read-only dialogue runtime.** `commands/talk.py` deletes the guide-prompt branch (`is_guide_host` / `current_guide_prompt`) and the `run_scripted_talk` import; every scripted answer resolves through `world/rules/dialogue.py`. The webclient `explore.talk_scripted` adapter in `exploration_actions.py` retargets from `world.rules.onboarding.talk_response` to the same dialogue seam (the spec text currently names the onboarding module — its delta rewords to the dialogue API). `service_actions.py` drops the `onboarding_completed` echo that `world/rules/guild.py`'s claim hook no longer emits; the claim transaction keeps appending `quest_id` to `guild_reward_claims` unchanged.

**D5 — Traceability follows requirements, not files.** Tests whose `@covers_requirement` anchors point only at retiring `onboarding-guide` requirements (`test_onboarding.py`, `test_onboarding_journey.py`, `world/onboarding/tests/`, the onboarding look-beat browser test) are deleted with the capability — requirements leave the index when the main spec loses them at archive sync, which is the sanctioned way coverage drops. Surviving requirements (trimmed `scripted-dialogue`, `map-knowledge`, `webclient-*`…) must keep their other carrier tests; where a deleted onboarding test was the sole carrier of a *surviving* trimmed requirement's scenario, the surviving test suite's coverage is re-anchored in the same PR (spec-wording and test anchors move together). Net: `tools.spec_traceability check` stays 0 uncovered / 0 errors — today 1230/1230.

**D6 — Shards bookkeeping is exact, not approximate.** Remove `world.rules.tests.test_onboarding`, `world.rules.tests.test_onboarding_journey`, and the `world.onboarding` entries from `.github/evennia-shards.json`; rename the shard label `quests-skills-art-ai-onboarding-lore` without the `onboarding` word (label is bookkeeping, not a spec anchor); remove the `test_look_at_room_preserves_the_onboarding_beat` entry from `.github/browser-shards.json`. Every remaining module stays registered in exactly one shard.

**D7 — Observability retires shrink-only.** The `sync_guard_npc` startup-step events retire with the step. Verified: `tools/observability_freeze.json` currently carries no onboarding-named ids, so this change is freeze-neutral-to-shrinking; `tools.observability_lint check` violation count must not grow. No new events are introduced by this change (the gate-missing warn event belongs to the sibling).

**D8 — HelpOverlay dead-prop trim (merged scope).** `HelpOverlay.vue` already renders static `controlsReferenceSection()` from `lib/controls-reference.js`, and `AppClient.vue` renders `<HelpOverlay v-else :guide="{}" />` — the `guide` prop is dead weight. Delete the prop and its template section, prune `guide` fixtures/stories/tests (`stories/Overlays/HelpOverlay.stories.js`, `stories/OverlayHost.stories.js`, `stories/fixtures.js`, `tests/overlays/help_overlay.test.js`) and the `AppClient.vue` binding. No spec delta: `webclient-contextual-hud` already mandates static truth-telling help, and the showcase manifest wording matches the post-trim state. Gates: `npm test`, `npm run build-storybook`, `npm run showcase-coverage`.

**D9 — Spec deltas are trim-only.** Each MODIFIED block is the current main-spec block copied in full with only onboarding-hook phrases/scenarios removed (e.g. settlement steps become charge/record/follow; the guild_staff turn-in scenario loses "including the onboarding-completion line"). Two requirement *titles* carry the onboarding phrase itself (`movement-settlement-atomicity` req 1 and `webclient-exploration-menu`'s `explore.look` req), so those two delta files additionally use `## RENAMED Requirements` (FROM:/TO:) ahead of the MODIFIED block so archive sync matches the new header. The `onboarding-guide` delta is pure REMOVED (all 8 requirements, each with Reason + Migration).

**D10 — Reconnect keeps the persisted location (verified fact, pinned by test).** `typeclasses/accounts.py::at_post_login` (:168-186) does exactly two things beyond the parent hook: render the pending-creation screen, and — for an activated account — play the arrival hook `maybe_play_arrival(puppet)`. It performs **no relocation**: arrival-scene playback was the only onboarding-touching behavior on the login path, and even before this change an already-`first_arrival_seen` character got nothing on reconnect. After this change the hook call is deleted, so reconnect is pure "stay where you are" — the character remains at its persisted `location` (and `home` remains whatever Evennia set at creation, i.e. the 虛境 birth room; the one-way-gate sibling re-homes it on first gate traversal). Because this is a behavior boundary nothing currently tests, the change adds one focused regression assertion (tasks 6.7): a character parked in a non-birth room before logout is in the *same* room after re-login, with no teleport.

## Risks / Trade-offs

- [Hidden import of a deleted symbol breaks a non-test module] → grep-driven cutover (`onboarding`, `guide_progress`, `first_arrival_seen`, `observe_room_entry`, `sync_guard_npc`, `OnboardingGuide`, `run_scripted_talk`, `set_onboarded`) plus the full non-browser Evennia suite once at the end; import-time failures surface immediately.
- [Trimmed delta diverges from sibling `limbo-one-way-city-gates` deltas on shared wording] → this change never edits `grid-room-sync`/`limbo-room`/`sample-city-altoria`; `webclient-character-creation-ui` activation wording ("lands in 虛境, no relocation") is exactly compatible with the one-way gate — both agree the character stays put at birth and leaves through the one-way gate.
- [Deleting an onboarding test silently orphans a surviving requirement] → run `tools.spec_traceability check` after deletion; any surviving requirement that lost its last carrier gets its anchor moved to a surviving test in the same change before merge.
- [Shard-label rename breaks a CI matrix name] → the label is a display/shard key consumed only inside `.github/evennia-shards.json`; update consumers of the exact key in the same edit and run the shard-registry consistency check the repo ships.
- [Vue prop deletion breaks a Storybook story that still passes `guide`] → story/fixture pruning ships in the same task group as the component edit; `build-storybook` + `showcase-coverage` are the gate.
- [RENAMED requirements leave stale `@covers_requirement` literals behind at sync] → the two renames (`movement-settlement-atomicity` req 1, `webclient-exploration-menu` `explore.look`) invalidate every surviving anchor carrying the old slug — verified five-file list in tasks 6.6; the re-anchor task runs after main-spec sync against `tools.spec_traceability list`, and the surviving ordinary-display test `test_look_at_present_entity_uses_ordinary_display` is named as the renamed look requirement's continuing carrier.
