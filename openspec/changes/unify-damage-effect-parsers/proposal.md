## Why

The `damage:<element>:<school>` effect-ID grammar is parsed by two independent, hand-written functions that must be kept in lockstep by hand: `world/skills/effects.py::parse_effect`'s `damage` branch (runs once, at registry-load time, inside `SkillDef.__post_init__`) and `world/rules/combat.py::_parse_damage_effect` (runs at cast time, from `_handle_damage`, and is also called directly by `world/rules/monster_behaviour.py::_damage_school`). The two parsers already disagree on strictness — `_parse_damage_effect` rejects an unknown element (against `world.lore.elements.ELEMENT_REGISTRY`) and an unknown school (outside `{"physical", "magic"}`); `parse_effect` validates neither, only the string shape. This split-brain duplication already caused a near-miss regression: the now-merged `elementless-damage-effect` change (adding a reserved `none` element token, meaning "no element") had to patch both functions independently to teach them the new token, and the second site (`_parse_damage_effect`'s `element not in ELEMENT_REGISTRY` gate) was caught only by a failing behavioral test during implementation, not by any design review — `_parse_damage_effect` is wired into `basic_attack`'s combat-session fallback attack and every monster's skill-selection scoring, so the miss would have been a core-combat-path regression, not an edge case. The same file already has the fix pattern sitting right next to the problem: `_parse_self_heal_effect` (elsewhere in the same file) delegates to `parse_effect` and asserts the returned type instead of re-implementing its own grammar; `_parse_damage_effect` is the one prefix handler that doesn't follow it.

## What Changes

- `parse_effect`'s `damage` branch additionally validates the school segment against the closed set `{"physical", "magic"}`, rejecting a malformed school at registry-load time (matching this module's own stated "fails at import, not at use" contract) instead of only at cast time. Verified against every `damage:` string in the repository today: every real school segment is already `physical` or `magic`; every other value is a fixture deliberately testing rejection, which keeps being rejected.
- `world/rules/combat.py::_parse_damage_effect` becomes a thin wrapper: it calls `parse_effect`, asserts the result is a `DamageEffect`, and layers the one cast-time-only check that stays intentionally out of `parse_effect` — the element must be a real `ELEMENT_REGISTRY` key (kept out of the registry-load-time parser because dozens of test fixtures deliberately author non-registry element tokens that must keep constructing; see `elementless-damage-effect`'s design.md D2/Context for why this line is drawn there). Its return type changes from a bare `tuple[str, str]` to the typed `DamageEffect`, matching how every other consumer in the codebase already reads parsed effects.
- The two call sites of `_parse_damage_effect` (`_handle_damage` in `world/rules/combat.py`, `_damage_school` in `world/rules/monster_behaviour.py`) update their one-line destructuring to read `.school` off the returned `DamageEffect` instead of unpacking a tuple. No other line in either function changes.
- No behavior changes for any currently-valid `damage:` effect string: identical element/school combinations parse, construct, and settle exactly as before. The only new rejection is a same-shape-but-invalid-school string (e.g. `damage:fire:sonic`), which previously passed registry construction silently and only failed the first time it was actually cast; it now fails at registry load instead, the same way every other malformed effect prefix already does.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
- `skill-effect-model`: two requirements ADDED — the `damage` prefix's school segment is validated against its closed set at parse (and therefore at registry load), and the `damage:<element>:<school>` grammar has exactly one parser (`parse_effect`); every other consumer that needs the parsed shape reads its result rather than independently re-splitting the string.

## Impact

`world/skills/effects.py` (`parse_effect`'s `damage` branch gains the school-membership check — three added lines, no signature change); `world/rules/combat.py` (`_parse_damage_effect` re-implemented as a thin `parse_effect`-delegating wrapper returning `DamageEffect` instead of a tuple; its one call site in `_handle_damage` updates one destructuring line); `world/rules/monster_behaviour.py` (`_damage_school`'s one destructuring line updates to match the new return type). `world/rules/action.py`, `world/skills/registry.py`, every rulebook YAML, and the damage settlement math itself are untouched — this is a parsing-layer consolidation, not a combat-behavior change. No test currently asserts `_parse_damage_effect`'s literal error strings or its tuple return shape (verified by repo-wide grep), so no test signature churn beyond the new registry-load-time rejection case and the new single-parser architectural test.
