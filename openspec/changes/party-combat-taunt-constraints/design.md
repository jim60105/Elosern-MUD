# Design: Initiative-priority Taunt and legal enemy decision constraints

## Context

See `proposal.md` for motivation and the batch contract in `../combat-ratio-mitigation/batch.md` for complete coverage, order and conflicts. The existing legal-candidates contract applies seal/displacement restrictions before utility; active v6 owns the exhaustive typed hostility classifier.

Inspected boundaries are listed in the proposal Impact section. These are observed starting points; all new behavior below is proposed, with no runtime result claimed. The approved 2026-10-15 document explicitly amends the base engine §6.3 where subtraction, allied autonomy and individual allied flee conflict.

## Goals / Non-Goals

This change owns initiative-priority taunt and legal enemy decision constraints. It reuses existing deterministic state owners and exact protocol conventions. Required behavior is defined by its complete delta files. There is no new LLM dependency, compatibility path, data migration, shared inventory, companion equipment-management UI or physical proficiency progression. Detailed stage geometry remains owned by the existing UI batch.

## Decisions

Reuse the typed effect hostility classifier owned by active panel-v6, including non-damage hostile effects; do not infer hostility from skill names or physical/magic school. A Taunt request picks one living eligible enemy and no success roll. Rank accepted taunts with the already-computed initiative sequence. Store one winner per enemy for this round; no runner-up promotion. Determine ordinary legal target candidates first, including presence/range/faction, seal and displacement restrictions; when the winner is legal for this single-target hostile action restrict candidates to that identity. A seal or range rule that excludes the taunter stays authoritative; Taunt grants no exception. Apply the same constrained candidates to fallback/profile and utility/rollout estimation plus final execution revalidation, never silently rewrite a resolved target. AREA, self/allied benefits and flee remain legal ordinary alternatives. Recheck winner presence/eligibility before each later enemy decision; if down/dead/absent/fled, remove restriction permanently for that round. Losing taunts remain spent actions. Enemies gain no basic Taunt.

## Risks / Trade-offs

- [Shared boundary changes] -> Implement only after declared prerequisites, integrate earlier deltas and callsites, and use the batch matrix to serialize overlapping files. No obsolete alias or duplicate implementation remains after cutover.
- [State or capability changes after selection] -> The shared rules boundary repeats authoritative validation; invalid drafts and normal mid-round invalidation follow different documented semantics.
- [Unproven arithmetic, persistence or UI behavior] -> Tasks include focused independent assertions and actual evidence where owned here. A selected constant alone is not measured balance and a fixture-only UI is not runtime acceptance.
- [Estimate depends on existing patterns] -> Scope is bounded to the listed owner and 7 hours includes its focused tests/docs/integration. Required downstream behavior is owned explicitly in the batch rather than silently deferred.

## Migration Plan

Pre-release clean cutover only. Implement code, callsites, fixtures, exact schemas and affected canonical requirement annotations together for this slice. No old/new compatibility parser, stored-data migration or deprecated entry path is added. Rollback uses an ordinary revert of the implementation change; proposal authoring performs no rollback, merge, apply or archive. The assembled client/server cutover is accepted only after change 18.

## Verification and documentation ownership

If the canonical slug changes, migrate every affected annotation. Update existing affected documentation, both player command documents for syntax/context changes, and focused schema/fixture mirrors for transport changes. Run the focused tests and `uv run --locked python -m tools.contract_gate` during implementation; logging changes also require observability lint and focused event tests. Complete managed browser and traceability-evidence execution stay CI-owned.
