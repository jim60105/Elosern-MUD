## Why

The deterministic guild economy, quest lifecycle, shops, and the WebClient OOB foundation are all live, but every guild, quest, shop, and inventory workflow still requires memorized command syntax (`guild accept <key>`, `buy <key> <qty>`, `guild show <id>`) or manual `guild log` / `inventory` inspection. Roadmap item 23e (`webclient-service-menus`) is the next independent UI slice after the combat menu: it is fully deterministic, needs no LLM or image service, depends only on the landed foundation and change-16 domain APIs, and can ship in parallel with map knowledge, exploration, creation, and art.

## What Changes

- Add a read-only version-1 `services` panel registered beside `status`, `context_actions`, and `local_map`. It is available in exploration mode and presents a display-only host reference, the player's wallet/rank/merit summary, bounded pagination totals, and up to three bounded surfaces: `guild` (registration, board, quest log, rank/examination), `shop` (open state, stock, quantity purchase, sellable inventory), and `inventory` (repeated item keys, aggregate counts, equipped state). Each surface resolves its own local host class independently with the same rule commands use (`GuildStaff` / `GuildExaminer` / `Merchant`); zero or multiple hosts of a required class produce a stable unavailable surface and different classes in one room never conflict, so the browser can never address a remote or ambiguous host dbref. A failure confined to one surface degrades only that surface; the whole panel is unavailable only in non-exploration modes or when the global summary cannot be read.
- Register exactly seven allowlisted service adapters — `guild.register`, `guild.quest_accept`, `guild.quest_abandon`, `guild.quest_turnin`, `guild.exam_start`, `shop.buy`, and `shop.sell` — that re-resolve the local `GuildStaff` / `GuildExaminer` / `Merchant` host and the referenced entity/quest/item/rank identity at dispatch time and call only the existing deterministic APIs (`register_adventurer`, `accept_guild_offer`, `abandon_guild_quest`, `turn_in_quest`, `start_guild_exam(requested_by="webclient")`, `economy.buy`, `economy.sell`). No payload accepts a host, branch, session, actor, price, or stock value; no generic `guild.command` or `shop.command` exists.
- Add a frozen, no-mutation deterministic service read model under `world/rules/` that interprets guild registration, quest log, catalog offers, merchant stock, wallet, and inventory into bounded JSON-safe data, isolating each surface so a corrupt quest log or malformed stock degrades one surface instead of the whole panel. A missing/ambiguous host, closed shop, unregistered player, insufficient funds/stock, ineligible rank, or already-claimed reward surfaces as a stable disabled reason and is always rechecked by the deterministic API at commit. Staleness is exactly the existing OOB epoch/revision dispatcher outcome — commit-time revalidation handles any price/stock/rank change between render and submit, and `guild.register` is idempotent success for an already-registered actor, matching the deterministic API.
- Add a keyboard-first service dock to the action dock shown in exploration mode: a Services root leading to per-surface submenus, bounded integer quantity forms for buy/sell (server-advertised minimum/maximum, submitted payload carries item key and quantity only), server-rendered quest detail (reusing `world.quests.describe`), and an explicit confirmation screen before the destructive `guild.quest_abandon`. `guild.exam_start` transitions the shell into the ordinary combat menu via the mode-changing update. All submission flows reuse the foundation's epoch/revision gating, in-flight lock, and never-auto-retry reconnect semantics.
- Update the production action-registry contract in `webclient-action-dispatch` from exactly the three combat adapters to exactly the three combat plus the seven service adapters.
- Extend the Node gate, the managed Playwright suite, and deterministic Evennia fixtures with guild/quest/shop/inventory success, rejection, stale, duplicate, tampered, quantity, confirmation, mode-transition, and reconnect journeys.
- Add no backward-compatibility adapter or persisted-data migration; the project is unreleased and Telnet play remains unchanged.

## Capabilities

### New Capabilities

- `webclient-service-menus`: The read-only version-1 `services` panel payload (host resolution, player summary, guild/quest/shop/inventory surfaces), the seven exact allowlisted service adapters, the deterministic no-mutation service read model, the keyboard service dock and quantity/confirmation flows, and the Node/browser acceptance boundary.

### Modified Capabilities

- `webclient-action-dispatch`: The production registry contract changes from exactly `combat.cast`, `combat.flee`, and `combat.forfeit` to additionally require exactly the seven `guild.*` and `shop.*` service adapters, each with its own exact validator and deterministic adapter.

## Impact

- New files: `world/rules/service_view.py` (no-mutation read model), `world/rules/service_messages.py` (stable rejection codes and Traditional Chinese text), `web/webclient/presentation/services.py` (panel presenter + validator), `web/webclient/actions/service_actions.py` (payload validators + adapters), a DOM-independent `service_menu.js` render model under `web/static/webclient/js/elosern/`, a `services_dock.js` GoldenLayout plugin, and their tests.
- Edits to landed implementation files: `web/webclient/presentation/registry.py` (register the `services` panel), `web/webclient/actions/registry.py` (register the seven service adapters), `web/static/webclient/js/elosern/protocol.js` (panel allowlist + `services` validator), the action-dock JavaScript/CSS, and browser fixtures.
- Reuses the locked Playwright dependency, isolated browser harness, OOB epoch/revision protocol, deterministic guild/quest/shop APIs, and `world/quests/describe` renderers; adds no runtime dependency, database migration, LLM call, image-service call, mobile scope, or backward-compatibility layer.
- `webclient-exploration-menu` (23d) later re-homes the service submenus under its Interact/Quests/Inventory root entries; this change ships the panel payloads and adapters it consumes without implementing movement, look, dialogue, or rest/wait.
