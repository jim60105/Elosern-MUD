# Proposal

## Why

Enable a small named variant set only after complete evidence and demonstrate legacy rollback. This is a bounded part of the approved monster combat AI roadmap, not a claim that configuration alone completes attack behavior.

## What Changes

- Existing production variants SHALL remain legacy until attack/tactics regressions, real production smoke, the approved manual campaign, selector threshold, complete-policy performance and repository contract gate pass. Initial utility activation SHALL name a small explicit registered variant set with independently authored intelligence.
- Expansion SHALL follow review of valid-action rates, wait/exclusion causes, resource use and observed behavior. Affected profile tuning edits SHALL rerun focused scenarios and produce new fingerprints. Old-fingerprint acceptance claims SHALL NOT be presented as evidence for changed tuning.
- Selected variants SHALL be switchable back to legacy with no destructive data migration or DB restoration. Existing sessions SHALL retain recorded tuning until termination; new sessions or deliberate restart SHALL adopt startup mode. Restart SHALL clear tactical history.
- Release evidence SHALL include exact operations, seeds, configuration, fingerprints, raw manual reports, focused test output, real smoke and rollback evidence. Every new permanent non-browser test module SHALL have exactly one existing shard owner; manual operations SHALL not become test modules.

## Capabilities

### New Capabilities

- `monster-ai-rollout`: Enable a small named variant set only after complete evidence and demonstrate legacy rollback.

### Modified Capabilities

None.

## Impact

All production variants remain legacy throughout earlier slices. Validated variant_decision_mode supports startup-only activation, and active sessions retain recorded tuning. The approved document supplies no production intelligence roster or small-set names; author those from registered variants and existing lore during this content activation slice. Implementation must update AI authoring/development documentation and the release changelog. Player command documentation remains unchanged because no command is added. No new service, package dependency, persistent AI schema or compatibility layer is authorized.
