# Design

## Context

Source of truth: `docs/superpowers/specs/2026-10-22-world-map-drawer-design.md`, introduced by approved commit `9a9200b45c406a3d28ec15b27fa4cf04380151ba`, and parent architecture `docs/superpowers/specs/2026-07-29-ai-mud-engine-design.md`. Review-driven §9 rows 4/5 prerequisite split: exact schemas, on-demand snapshot semantics and bounded part codec are moved here so neither 8h presenter depends on an undefined/later wire contract. Budget 3h schemas, 2h codec, 1h on-demand storage and 2h focused verification/docs. See proposal.md for motivation and prerequisites. The prototype is a layout/interaction reference only; its old river, forest and political geometry must never become runtime data.

## Goals / Non-Goals

Implement only the assigned slice described below. No elevation, travel automation, new quests, shipping mechanics, compatibility layer or data migration. Existing canonical identities, knowledge ownership and deterministic offline play remain intact.

## Decisions

### Exact panel wire contract

Both available logical panels are version 1. Unknown keys/types are rejected in Python and JavaScript. Unavailable remains the existing `{schema_version,available:false,reason}` union. All x/y below are finite numbers, not booleans. Node IDs use the existing canonical grammar. `gateway` is required null or exactly `{leads_to}` with upstream bounds. `action` is required null or the existing exact `{kind:"move",exit_ref,destination}` descriptor. Text bounds reuse 256-code-point labels and 128-code-point titles; exact collection/byte ceilings are measured, mirrored constants, not local_map caps.

`area_map` grid logical fields are exactly `{schema_version,available:true,layer:"grid",map_id,frame,current_node,title,nodes,edges,quest_markers}`. `map_id` is the canonical settlement/z-map key. `frame` is exactly `{key:map_id,unit:"m"}`. Each node is `{id,label,x,y,visibility,gateway,action}` with integer metre x/y and visibility current|visited|seen; each edge is `{source,destination}`. An instance/interior has the same top-level fields, layer instance|interior, `map_id` from its stable existing instance identifier or canonical enclosing interior root identity, `frame:{key:map_id,unit:"none"}`, and nodes exactly `{id,label,visibility,gateway,action}` with no x/y. Its identity must not depend on the currently visited node or knowledge set. Graph membership ends at the enclosing instance/interior boundary.

Wilderness area fields are exactly `{schema_version,available:true,layer:"wilderness",map_id:"elosern",frame:{key:"elosern",unit:"km"},current_node,title,nodes,edges,quest_markers,district_name,cell_km}`. `cell_km` comes from the provider scale. Nodes are exactly `{id,label,x,y,visibility,visited,gateway,action}` with cell-centre x/y in km and explicit visited boolean. Its 15×15 index window is derived before conversion, and true gateway nodes occupy their approved adjacent presentation position with canonical destination identity. Edges remain `{source,destination}`. Invalid cells are omitted, never traversable. All area quest markers use exactly `{id,title,tracked,destination}` where destination is the tagged union `{kind:"node",node_id}` on this area or `{kind:"bearing",bearing_deg,distance_km}` elsewhere, never both. A marker into an unknown branch carries only identity, not invented room details.

`world_map` logical fields are exactly `{schema_version,available:true,common,districts,trail,visited_places,current,quest_markers}`. All geometry uses continent km with north-positive y. `common` is `{coastline,borders,nations}`: coastline is a closed vertex list; borders is a list of polylines; nations is a list of `{id,name,x,y}`. A point is `[x,y]`, a polygon is a closed point list and an outline is a list of closed polygons (including holes under a documented winding convention). `districts` is a list with exact discriminated records `{id,lit:false,outline}` or `{id,lit:true,name,outline,landmark,nations,terrain,rivers,ridge,roads,places}`. `landmark` is exactly `{name,x,y}` with no node ID; nations is a list of common nation IDs. Terrain is a list of `{region,polygons}`; rivers/ridge/roads are lists of polylines. Places and visited_places rows are exactly `{id,name,kind,x,y}`, with kind capital|settlement|harbour|hidden. Hidden/dungeon/elven places require a visit regardless of lit state. `current` is exactly `{x,y}` derived from existing canonical enclosing geography; if that is unavailable, use common unavailable rather than inventing a room position.

Trail is exactly `{resolution_km,rows}`, where resolution_km is 1 or 5 and rows are `[row_index,[[start_column,length],...]]` sorted by row/start with positive non-overlapping integer runs in that resolution's grid. World commission rows are exactly `{id,title,tracked,x,y,approximate}`; unlit destinations have rounded 50km x/y and no hidden exact ID/distance/bearing fields. This fixed schema belongs here; later world publication implements only the presenter and uses these validators. No production placeholder presenter is registered in this slice.

### Bounded delivery and area size ownership

Logical panel collections are validated by their own finite measured bounds. Preserve all unrelated panels' generic budgets, including local_map 65536 bytes. Area publication owns measurement and adequate finite area bounds for its full graph and 225-cell window; it cannot depend on a later world transport change. Large map bodies travel through a shared bounded part codec when one existing frame cannot carry them. Part frames keep the existing ui_update metadata and contain the map panel wire variant `{schema_version:1,available:true,part:{transfer_id,index,count,byte_length,chunk}}`, where chunk is base64 of a canonical UTF-8 JSON fragment, index is zero-based and count/byte_length are finite mirrored bounds. Each fragment is at most 1536 raw bytes (2048 base64 characters); each whole frame must still satisfy the non-map 65536-byte envelope cap. All parts share one logical revision, epoch, map panel and transfer ID. Reassembly occurs before logical panel validation/revision adoption, replacing only after exact byte count, UTF-8/JSON and full schema validate. Reject conflicting/duplicate indices and over-bound counts/bytes; a newer transfer or epoch retires the old one. Keep at most one bounded assembly per map panel; missing parts never become visible. This is only map-panel delivery, not a general streaming API.

Single-frame world payload allowance and selected world bounds are measured by transport-world-map-panel; if socket delivery fails, this codec already provides the required parts. Production decoder/store adoption is exercised through a test-only registered presenter with schema-valid real geometry, never a no-op production presenter. Existing mode/dialogue metadata still adopts only with a complete valid logical update.


## Real-component visual workflow

When a consuming visual component is changed, Storybook stories MUST import the real production components and use schema-valid panel fixtures, never mount/copy `WorldMapPrototype.vue` as evidence. Reproduce approved option-A scenarios and add the slice-specific accessibility/interaction cases. Each relevant story `play` MUST assert real DOM behavior. During implementation start the project Storybook workflow, use the `agent-browser` skill to open the affected real-component stories, exercise keyboard/pointer interactions and save captures. Repeat relevant geometry in the live client under `.elosern-root`; review/remove conflicting `styles/app-shell.css` overrides. Screenshot existence alone is insufficient: inspect captures and record observed behavior. Keep component-story ownership/coverage manifests current. Run focused story/component/browser selections, never broad suites. Use shared tokens, UI scale and at least 16 CSS px labels; hide lower-priority labels rather than shrink them.


## Risks / Trade-offs

Wire bytes and logical schema validation happen at different phases. Decode all parts before revision adoption; do not relax scalar safety or other panel budgets. This slice has no new visual component; real view stories remain normative in their owners.

## Implementation verification contract

Implementation MUST run the smallest affected Evennia label, Node file, Vitest file, or managed browser class, never broad suites or CI shard commands locally. Every local test command must stay below ten minutes. Use `uv run --locked --env-file=<path> evennia test --settings test_settings.py --keepdb <focused.label>`, with `MUD_TEST_SETTINGS=1` in that env file. Pure tool tests use a focused `uv run --locked python -m unittest <module>`; client units use a single-file runner.

Register every new/moved non-browser package test module in exactly one `.github/evennia-shards.json` shard; register every new browser class/method in `.github/browser-shards.json`. Keep synthetic mechanism fixtures independent of production lore. Production content integrity tests need a first-line `Data-contract test: <reason>` and matching `tools/test_data_freeze.json` entry.

Use `uv run --locked python -m tools.spec_traceability --repo-root <equivalent-root> list` to obtain canonical IDs, never guess them. Before sync, create a disposable ordinary directory containing the complete current implementation, tests, manifests and tooling (not a git worktree), and apply all prerequisite/current spec deltas to its copied main specs in dependency order. Keep literal intended `covers_requirement` annotations in the actual implementation; they may be unknown to unsynced root specs. Run `check` with `--repo-root <equivalent-root>` and run the copied `tools.contract_gate` from that complete equivalent directory before handoff. Do not demand a root contract-gate pass before specs are synced. After sync, run the normal root traceability check and contract gate with unchanged annotations. Associate only substantive discoverable Python assertions; a focused Python wrapper that actually executes JS/browser assertions is valid, source-presence checks are not. CI alone runs complete evidence verification.

All changed server, movement and panel logging uses named imports from `world.observability`, stable snake_case events and contextual business identifiers. Changed cross-system/I/O boundaries emit the applicable catalog event; exception branches re-raise, log through the facade with `exc=`, or carry a reasoned lint exemption. Patch the caller's log binding in tests. Run the observability lint with focused tests when a logging path changes. Never add freeze-list entries.

Before implementation handoff run strict validation and the copied contract gate from the complete equivalent merged-spec directory described above. After main-spec sync run `uv run --locked python -m tools.contract_gate` at the actual root. Update existing behavior documentation; no unrelated features, migrations or compatibility aliases. Proposal creation does not run implementation tests.
