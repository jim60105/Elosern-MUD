## Context

The deterministic engine (change 16) is fully playable offline, and the WebClient suite has landed three Wave-1/2 units that this change builds on directly: `webclient-oob-foundation` (23a) owns the versioned OOB protocol, epoch/revision ordering, the read-only presenter registry, the allowlisted action dispatcher (one mutation in flight, duplicate cache, stale rejection, never-auto-retry reconnect), the keyboard router, and the desktop GoldenLayout shell; `map-knowledge-minimap` (23c) owns the persisted visited-node record and the read-only `local_map` panel whose version-1 payload already carries exact `move` action descriptors (opaque `exit_ref` + canonical `destination`) on every currently traversable adjacent Exit; and `npc-dialogue` (19) owns the guarded generative reply pipeline plus the `LLMNPC.at_talked_to(speech, character, client)` seam that injects `disguised_stats`, maps degrade to greeting/silence, and routes verified intents through the deterministic applier. The `services` panel and its seven `guild.*`/`shop.*` adapters (23e) already cover guild, quest, shop, and inventory in exploration mode.

This change implements the approved `webclient-exploration-menu` delivery unit (roadmap item 23d) from
`docs/superpowers/specs/2026-08-02-webclient-ui-design.md` (§7.3, §7.6) and
`docs/superpowers/specs/2026-08-02-webclient-map-exploration-ui-design.md` (§7, §8). It is the consuming surface: it does not re-implement movement charging, map knowledge, dialogue transport, skip safety, or service transactions — it registers the `explore.*` action adapters and the exploration/character presenters that call those existing public APIs and re-present the data the prior units already own. The browser stays a read-only renderer, Telnet play is unchanged, and the single-writer rule is preserved: no module under `world/ai/` applies a state change, and every adapter below calls a public deterministic API instead of assigning `.db`, traits, knowledge, dialogue, quests, inventory, combat, or time.

The deterministic entry points this unit consumes are all public and already shipped: `MovementCostMixin.at_post_traverse` → `charge_movement` + `record_arrival` (via the Exit's own `at_traverse`), `PlayerCharacter.at_look` (the onboarding look hook), `world.rules.onboarding.talk_response`, `world.rules.dialogue` component/keyword lookups, `LLMNPC.at_talked_to`, `world.rules.combat_session.engage`, `world.rules.skip_safety.evaluate_skip_safety`, `world.rules.clock.seconds_until_daypart`/`get_world_clock`/`AdvanceSource`, `world.rules.status_query`/`world.rules.service_view` read models, `resolve_local_service_host`, and the `local_map` presenter's `_exit_ref` convention. The `webclient-action-dispatch` contract currently fixes the production registry at exactly the combat + service + creation actions; this change amends that contract.

## Goals / Non-Goals

**Goals:**

- Present movement, look, interaction, scripted/free-form dialogue, engage, rest/wait, and the service submenus through one bounded keyboard-first exploration dock in exploration mode, composed only from server-authored affordances.
- Register exactly six allowlisted exploration adapters (`explore.move`, `explore.look`, `explore.talk_scripted`, `explore.talk_freeform`, `explore.engage`, `explore.wait`) whose payloads carry no actor, host, session, destination room, price, stock, or clock value and that call only existing deterministic APIs.
- Traverse movement through the Exit's own method so the existing `MovementCostMixin` seam charges `command_defaults.move` and records the destination node — the same 30-second cost and knowledge behavior the typed command produces.
- Preserve the onboarding look hook: `explore.look` routes through `PlayerCharacter.at_look`, so the arrival beat advances exactly as `look` does.
- Keep free-form dialogue on the change-19 seam with the client injected by a presentation composition root, degrading to authored greeting or silence when the LLM is offline.
- Re-home the existing service submenus under the Interact/Quests/Inventory roots without changing the `services` panel payload or the seven service adapters.
- Reuse the foundation epoch/revision/in-flight/dispatcher semantics, the locked Playwright harness, the Node gate, and the deterministic Evennia fixtures.
- Extend the Node, Evennia, and managed Playwright gates with movement/time-charging, look/onboarding, dialogue (offline degrade), engage-to-combat, wait/rest safety, stale/duplicate/tampered, mode-transition, and reconnect journeys.

**Non-Goals:**

- No Narrator, ScenarioDirector, SceneBuilder, art-panel, or art-queue dependency; this change waits only for 19, 23a, and 23c (the roadmap dependency set).
- No take/drop or any generic object-mutation action: the approved exploration design §8 requires an owning deterministic ownership/access API, and none exists.
- No new deterministic mutation API, no new quest/guild/shop/combat/onboarding mechanic, no client-side clock or rule calculation.
- No remote or ambiguous host/target addressing; no host/branch/dbref/session/actor/destination-room fields in any payload.
- No generic `explore.command`; no action routed through the text command parser; no parsing of narrative to infer state.
- No mobile acceptance, no new runtime dependency, no database migration, no backward-compatibility layer, no Telnet behavior change.
- No change to the `services` panel payload, the seven service adapters, or the `local_map` payload contract; the `webclient-service-menus` and `webclient-local-map` deltas here are browser-dock integration only.

## Decisions

### D1. One `exploration` panel plus one `character` panel, both read-only version-1 presenters

Two new registered panels cover the dock's needs. `exploration` (schema version 1, `kind == "exploration"`) carries the move/look/interact/character/quests/inventory affordances the dock renders, with bounded lists (12 exits, 32 look entities, 32 look objects, 32 interact targets, 8 affordances per target, 16 scripted keywords) so no unbounded room contents ever serialize. `character` (schema version 1, `kind == "character"`) is a separate read-only expanded-state panel opened by the Character root, so a trait dump never bloats the interaction payload and the Character root stays openable even when `services` is unavailable.

Rationale: a single panel would mix high-churn interaction data with a rarely-changing trait dump, forcing the Character surface to re-render on every movement. Mirroring the `services` panel's exact-field discipline, each presenter validates its own output against an exact bounded schema before returning it (the registry's common unavailable form is used outside exploration mode). The presenters read only canonical room/entity/component/object/service data through the existing `status_query` and `service_view` read models — `character` reuses the same canonical trait/equipment/disguise read model the compact `status` panel builds from, so the two panels cannot drift apart — and never mutate anything.

Alternative considered: one combined panel. Rejected — it couples the interaction dock's payload size to the expanded character surface and makes a single validator much larger, exactly what the `services` change split per-surface to avoid.

### D2. Affordances are server-authored from deterministic checks, never inferred from prose

The `interact` target list and each target's `affordances` are computed by the presenter with the same checks commands use: `is_dialogue_host`/`dialogue_key_for` for scripted talk (keywords read from the dialogue-table registry), `isinstance(npc, LLMNPC)` for free-form talk, a present living hostile `Monster` with no active session for engage, and `resolve_local_service_host` for a single unambiguous `GuildStaff`/`Merchant` host for the service navigation affordance. The browser renders only descriptors it received; it never inspects typeclass names, displayed prose, or component slots. This is the design doc §7.3's "the browser does not infer an affordance from typeclass names or displayed prose" requirement, enforced on the server.

Affordances use a distinguished shape so a navigation descriptor can never be mistaken for a submittable action: an **action affordance** carries `kind: "action"` with a real `action_id` (`explore.talk_scripted` / `explore.talk_freeform` / `explore.engage`), while the **service affordance** carries `kind: "navigate"` with a `surface` (`"guild"` / `"shop"`). `navigate` descriptors are dock-navigation only — they are not registered adapters, never enter a `ui_action` payload, and only open the already-landed `services` submenu. This makes the allowlist model unambiguous to the generic action renderer and the protocol validator, which enforce that only `action`-kind descriptors are submit-capable.

### D3. `explore.move` traverses through the Exit's own method so charging and knowledge stay in the shared seam

The adapter re-resolves the Exit from the actor's location by the opaque `exit_ref` (the same `str(int(exit.id))` form the `local_map` presenter already emits), verifies the actor's current node equals the submitted `current_node` guard, verifies `exit.location is actor.location`, that the destination exists, and the `traverse` lock, then invokes the Exit's own `at_traverse`. That single call flows through `DefaultExit.at_traverse`'s success branch into `MovementCostMixin.at_post_traverse`, which calls `charge_movement(traversing_object, movement_cost_key)` and `record_arrival(traversing_object)` — the exact seams `movement-cost-charging` and `map-knowledge` already own. The `at_pre_move` veto (the `PlayerCharacter` combat lock) is honored inside the same traversal, so an active session blocks menu movement with no extra adapter logic.

Rationale: re-invoking `charge_movement` from the adapter would duplicate the shared seam and risk a second charge; calling the Exit's own traversal keeps cost, lock, veto, and knowledge behavior byte-identical to the typed command path. A wrong `current_node` guard is checked before any traversal so a stale render cannot move the actor; the adapter publishes a full snapshot on success because location, clock, header, map, and shop/quest state all change together. The same commit-time revalidation discipline applies to every target-bearing adapter: `explore.look`, `explore.talk_scripted`, `explore.talk_freeform`, and `explore.engage` each re-resolve their `target_id`/`npc_id`/`monster_id` from the actor's **current** location's present contents and re-verify the exact eligibility before invoking the display, dialogue, or engage API, so a remote, removed, type-changed, or no-longer-eligible target rejects with no state change.

### D4. `explore.look` routes through `PlayerCharacter.at_look`

The adapter re-resolves the room marker or a present target and calls the same appearance path the `look` command uses — for the room, `actor.at_look(actor.location)`; for a target, the ordinary display path. Because `PlayerCharacter.at_look` (typeclasses/characters.py) already calls `world.rules.onboarding.advance_beat`, the onboarding look hook fires for free with no new onboarding write. The returned appearance is presented through the escaped text path and never parsed.

### D5. Scripted dialogue uses `world.rules.onboarding.talk_response`; free-form uses the change-19 seam

`explore.talk_scripted` re-resolves the NPC, verifies presence + dialogue component + registered keyword, then calls `talk_response(npc, actor, keyword_id)` — the exact API `talk <npc> <keyword>` uses — so an `OnboardingGuide` host records the seen keyword and a `ScriptedDialogue` host answers with no state change. `explore.talk_freeform` re-resolves a present `LLMNPC` and runs `npc.at_talked_to(speech, actor, client)`, which appends chat memory, builds the bounded prompt injecting `disguised_stats`, degrades to `greeting_for` or silence, and routes a verified intent through `world/rules/npc_intents`. The adapter is a Deferred-returning adapter (the dispatcher already supports Deferred adapters) and publishes a full snapshot on success so any applied intent — including a `request_guild_exam` mode change — refreshes atomically.

### D6. A presentation composition root owns the `npc_dialogue` client, constructed lazily

`web/webclient/actions/dialogue_composition.py` provides `build_dialogue_client() -> client`, mirroring `server/ai_director_service.py`'s pattern. The client is built **function-locally and only when the `npc_dialogue` profile is enabled**: the module never imports or constructs `OpenAICompatClient` at module scope, so a cold import of the composition root (or of the adapter importing it) cannot bind the guardrail's import-time logger or load the live transport when the layer is disabled. When the profile is disabled it returns a non-`None` offline stub (defined in this module, importing no transport) whose `get_response` fails loudly if ever called — the guardrail degrades before any transport work, so it never is. This keeps the "client is injected, transport ownership stays in `world/ai/client.py`" rule uniformly true, keeps the webclient free of eager AI initialization offline, and gives the adapter a single, unambiguous injection site. `web/webclient/actions/` is a presentation package not scanned by the transport-boundary test, so importing `world.ai.client` inside the enabled path is legal; the stub is the same shape change 20's `server/ai_director_service.py` already proved.

### D7. `explore.wait` reuses a single shared deterministic skip helper, never advances time itself

The `rest`/`sleep`/`wait` duration parsing, full-regen seconds, summary rendering, and safety gate currently live in `commands/skip.py` (with `_parse_duration`, `_seconds_to_full_regen`, `_render_skip_summary`, and `CLOCK_YAML["max_sleep_seconds"]`). Rather than duplicating that logic in the adapter and risking rulebook drift, this change factors a small deterministic `world/rules/time_skip.py` helper that owns duration validation, the bounded full-regen computation, and the `evaluate_skip_safety` + `WorldClock.advance(seconds, AdvanceSource.SKIP, [actor])` execution, returning the `ScheduledEvent` list; `commands/skip.py` is refactored to consume it (behavior-identical, existing `time-skip-commands` tests stay green) and the adapter consumes the same helper. The Web `seconds` payload is bounded by a documented protocol-level maximum that never changes the command behavior — `rest` still accepts any parseable duration with no cap (per `time-skip-commands`), and `sleep` still caps at `CLOCK_YAML["max_sleep_seconds"]` — while the browser cannot submit an unbounded value. The adapter rechecks safety against current canonical state, presents the returned summary through the escaped text path, SHALL NOT advance time itself or accept an unsafe/unbounded value, and publishes a full snapshot at one newer revision so the advanced header, status, shop hours, and quest deadlines refresh together. A payload `seconds` value above the documented bound or an unknown daypart is rejected before any clock call.

### D8. `explore.engage` delegates to `world.rules.combat_session.engage`

The adapter re-resolves a present monster and calls `engage(actor, monster)`, which re-verifies the `PlayerCharacter` with no active session, a living hostile `Monster` in the same room, persists the session, and records the initial overwhelm classification. The adapter publishes `status` + `context_actions` with the mode change to `combat`, so the exploration dock tears down and the ordinary combat dock mounts — the same hand-off `guild.exam_start` already uses. No action is run by the adapter and no session/battlefield/location state is assigned directly.

### D9. The dock re-homes the service submenus without touching the services contract

The exploration dock owns the action-dock surface in exploration mode with the stable root Move/Look/Interact/Character/Quests/Inventory. Quests and Inventory navigate to the unchanged `services` submenus (quest log and inventory), and Interact's `navigate`-kind service affordance opens the matching guild/shop submenu when a single unambiguous host resolves. The `services` panel payload and its seven adapters are byte-for-byte untouched; only the browser navigation entry point changes, which is why the `webclient-service-menus` delta here modifies the browser-acceptance requirement and the mode-change teardown scenario (the exploration dock now owns the surface that tears down). Mode changes (engage, exam start) unload the dock atomically exactly as the combat and service docks already do.

### D10. Shared bounded schemas in Python and JavaScript validators

Every bound in D1's payloads (12 exits, 32 entities/objects/targets, 8 affordances, 16 keywords, string/ID/portrait/identity limits, closed `kind`/`action_id` values) is a shared constant in both the `exploration`/`character` Python validators and the `protocol.js` validators, with a parity test proving the two stay in lockstep and a worst-case serialization test proving a structurally maximal payload fits the 65,536-byte OOB envelope. This mirrors the `local_map` D10a and `services` shared-bound pattern.

### D11. Portrait focus is a nullable, client-local seam

Exploration descriptors carry `portrait_ref: null` until the art capability supplies a `portrait_catalog`; the browser switches focus only among server-verified catalog values and never constructs a subject key or URL, and a `portrait_ref: null` descriptor or absent catalog never blocks look/interact/dialogue and never emits a focus packet. This is the exact contract the `webclient-art-panel` amendment (`2026-08-02-webclient-art-portrait-ui-design.md` §8, amended 2026-08-05) assigned to this delivery unit: 23d publishes the client-local focus against the opaque catalog-key contract that 23f's catalog fills in later; absence of art is a first-class, working state.

### D12. No take/drop, no generic object mutation

The exploration design §8 states take/drop actions are registered only if their deterministic ownership/access API is explicitly included in the owning OpenSpec change, and explicitly does not authorize a generic object-mutation action. No such API exists in `world/rules/` (no `CmdGet`/`CmdDrop`, no `take`/`drop` resolver). This change therefore ships no `explore.take`/`explore.drop` adapter, no take/drop affordance, and no browser control, and the acceptance suite asserts none is rendered.

### D13. Gauges store integral `current` values (float-storage fix)

Webclient acceptance exposed a latent defect in gauge persistence: Evennia's base `GaugeTrait._enforce_boundaries` returns the configured `max` verbatim when clamping at full, so a character with a float-rate gauge (e.g. `hp` rate `2.0`) at full stored `current = 200.0` as a float. Any regen settlement (`_settle_gauge_regen`) or buff rate tick (poison) then computed a float `current` (e.g. `200.0 + (−150) = 50.0`), which the strict `status_query._require_gauge` read model rejects (`gauge 'hp' current is not an integer`), taking the status panel unavailable after any time-charging action. `DeterministicGaugeTrait` now overrides `_enforce_boundaries` to round boundary writes, and `world/rules/clock.py` keeps the closed-form per-advance computation while persisting a sub-unit `regen_remainder` on each gauge, so segmented advances (two 30-second moves) equal one equal-length advance (one 60-second move) exactly and integral storage is preserved at every write. Regression tests cover fractional regen, segmented-vs-single equality, full-gauge clamps (which reset the remainder), and a full-gauge poison tick. This is a deterministic-core fix owned by this change's movement path, with no behavior change to gauge math for already-integral values.

## Risks / Trade-offs

- [Free-form dialogue is Deferred-returning through the dispatcher] → The dispatcher already supports Deferred adapters (combat preflight adapters return synchronously, but the `_invoke_adapter` path handles a Deferred result, publishes at one revision, then releases the in-flight lock). The adapter returns a Deferred that resolves after `at_talked_to` settles and maps the outcome to a safe success/rejection; the never-auto-retry reconnect rule already covers a drop during dialogue.
- [An intent applied mid-dialogue could change mode (e.g., `request_guild_exam`) after the browser already rendered the dock] → `explore.talk_freeform` publishes a full snapshot on success, so the mode change and panel teardown are atomic; the client's state store replaces panels completely and the dock unloads on adopting a `combat`-mode update.
- [`explore.move` calls the Exit's `at_traverse` directly, which could bypass the ordinary Exit command's own pre-checks] → The adapter explicitly re-checks location, destination existence, the `traverse` lock, and the `current_node` guard before traversal; the `at_pre_move` veto still runs inside the Exit path. This matches the design doc §6's "server re-resolves the Exit from the actor's location, applies locks and combat movement blocking, traverses through the existing Exit method."
- [Full snapshots after move/dialogue/wait are heavier than targeted updates] → Correctness and atomicity win: movement, dialogue, and clock skips genuinely change location, time, shop hours, quest deadlines, and (for intents) mode, so a full snapshot is the honest refresh. Targeted updates remain for `explore.engage` (status + context_actions) where the mode change defines the affected set.
- [Refactoring `commands/skip.py` to consume the new helper could regress the typed commands] → The refactor is behavior-identical by construction and the existing `time-skip-commands` tests (exact duration, sleep cap, daypart arithmetic, safety gate, summary rendering) are run unmodified as the regression gate; the shared helper is the only new code path.
- [The `services` and `local_map` deltas could be mistaken for payload changes] → Both deltas are browser-dock integration only; the payloads and validators are untouched. The `services` delta also updates the mode-change teardown scenario, which now names the exploration dock as the owner of the surface that unloads on a `combat`-mode adoption — the previous "service dock" wording would otherwise describe a dock that no longer owns the action dock.
- [A dock that loses its session mid-navigation could keep focus] → The dock teardown contract (D9 and the `services` delta scenario) requires unregistering keyboard handlers and discarding all local state on any non-exploration mode adoption, so combat, creation, or a failed snapshot cannot leave a stale exploration dock owning focus.
- [The `character` panel duplicates trait values the `status` panel already shows compactly] → It is the design's explicitly requested expanded surface (design doc §7.3 Character root) and reuses the existing no-mutation read models; it never substitutes disguised values for true traits.
- [Browser and server bounds could drift] → D10's parity test and the serialized-size envelope test lock the two sides together, exactly as the `local_map` and `services` changes already do.

## Migration Plan

No migration is required. The project is unreleased with zero users. New panels (`exploration`, `character`) and new adapters (`explore.*`) are additive to the OOB protocol and the action registry; Telnet and the deterministic game loop are untouched. The `services` dock navigation entry point changes but its payload and adapters are byte-for-byte stable. Rollback is a revert of this change's files; no persisted data or settings change is involved.

## Open Questions

None blocking. The free-form dialogue composition root's profile handling and the engage/wait/move affected-panel sets are fixed by this design; whether a future `converse` clock cost (design doc's unwired `command_defaults.converse: 60`) should charge dialogue remains a separate, explicitly out-of-scope roadmap question and is not decided here.
