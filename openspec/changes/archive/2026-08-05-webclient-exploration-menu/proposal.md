## Why

The deterministic engine (change 16), the WebClient OOB foundation (23a), persistent map knowledge with a real minimap (23c), and the guarded NPC dialogue seam (19) are all live, but ordinary exploration still runs on typed commands: players must memorize exit keys, `look`, `talk <npc> <keyword>`, `engage <monster>`, and `rest`/`wait` syntax instead of choosing finite controls. Roadmap item 23d (`webclient-exploration-menu`) is the last deterministic Wave-3 slice: it consumes the `local_map` movement descriptors and the `npc-dialogue` seam to ship movement, look, interaction, scripted/free-form dialogue, and rest/wait as one keyboard surface, with no dependency on Narrator, ScenarioDirector, SceneBuilder, or art.

## What Changes

- Add a read-only version-1 `exploration` panel registered beside `status`, `context_actions`, `local_map`, and `services`. It is available in exploration mode and unavailable in combat/creation modes. Its payload carries the exploration root categories composed from registered server affordances: `move` (a bounded list of current Exit descriptors, each with the opaque `exit_ref` from the `local_map` action form, a bounded label, and the canonical destination node ID), `look` (a room marker plus bounded present character/NPC/monster and object lists), `interact` (bounded present targets, each carrying a nullable opaque `portrait_ref` into the art panel's catalog and exactly the affordances that target legally supports), and `quests`/`inventory` availability entries that open the service panel's registered submenus. If a required capability surface is absent, the root shows no dead functional entry. The presenter reads only canonical room/entity/component/object data and never mutates location, traits, knowledge, dialogue, quests, inventory, or time.
- Add a read-only version-1 `character` panel available in exploration mode that opens the Character root: expanded state built from canonical traits (gauges and statics), passive skills, equipment slots, disguise description, guild rank and wallet, with every value read-only and the disguise described explicitly without substituting disguised values for true combat state. It reuses the existing no-mutation status/service read models where they already provide a value.
- Register exactly six allowlisted exploration adapters — `explore.move`, `explore.look`, `explore.talk_scripted`, `explore.talk_freeform`, `explore.engage`, and `explore.wait` — each with an exact bounded payload and a deterministic adapter. `explore.move` SHALL accept exactly `exit_ref` plus a `current_node` stale guard, re-resolve the Exit from the actor's location, re-check its location/destination, traverse locks, and the combat `at_pre_move` veto, then traverse through the Exit's own method so `MovementCostMixin.at_post_traverse` charges the shared movement cost and records the arrival node. `explore.look` SHALL accept a room marker or one present target ID and route through the same appearance path as the `look` command so the `PlayerCharacter.at_look` onboarding look hook still fires. `explore.talk_scripted` SHALL accept an NPC ID and a keyword ID, re-verify presence, the dialogue component, and the keyword registry, and invoke the existing deterministic dialogue API. `explore.talk_freeform` SHALL accept an NPC ID and bounded speech, re-verify presence and dialogue eligibility, and run the `LLMNPC.at_talked_to` seam through an injected `npc_dialogue` client. `explore.engage` SHALL accept a Monster ID and call the existing `world.rules.combat_session.engage` contract. `explore.wait` SHALL accept an approved daypart boundary or a bounded duration (with a dedicated sleep-to-full-regen form), recheck `evaluate_skip_safety`, and advance the clock through `AdvanceSource.SKIP` exactly like the `rest`/`sleep`/`wait` commands. Every target-bearing adapter re-resolves its referenced identity from the actor's **current** location's present contents and re-verifies the exact eligibility at commit time, so a remote, removed, type-changed, or no-longer-eligible target rejects before any display, dialogue, engage, or time change.
- Add a free-form dialogue composition root under the presentation layer that builds the `npc_dialogue` profile client once (or an offline stub when the profile is disabled, mirroring `server/ai_director_service.py`), injects it into `at_talked_to`, and maps the degraded `None` outcome to the authored greeting or silence so the game remains fully playable with the LLM entirely offline and the deterministic guardrail still discards illegal AI intent while keeping the speech.
- Add a keyboard-first exploration dock that owns the action-dock surface in exploration mode: a Move/Look/Interact/Character/Quests/Inventory root, per-category submenus, scripted dialogue keywords as finite buttons, free-form dialogue that opens the command drawer with a server-held target reference (the player types only the speech), engage and guild/shop service affordances only where a deterministic host resolves (service affordances are `navigate`-kind dock-navigation descriptors that open the `services` submenus and never enter a `ui_action` payload), bounded rest/wait duration and daypart forms whose values are parsed server-side, and the existing epoch/revision gating, in-flight lock, and never-auto-retry reconnect semantics. Service submenus (guild, quest, shop, inventory) are re-homed under the Interact/Quests/Inventory roots instead of a standalone Services root, and the mode-change teardown contract moves to the exploration dock, which unloads atomically (handlers, selection, speech, and quantity state all discarded) on any non-exploration mode adoption. Keyboard focus remains client-local; selecting an entity publishes a client-local portrait focus against the art catalog's opaque keys only when the 23f catalog supplies one — absence of art never blocks look and no focus packet is ever sent for `portrait_ref: null`.
- Wire the minimap's `node-action-ready` markers to submit `explore.move`: an adjacent traversable node whose `local_map` `action` is the exact `move` form becomes keyboard- and click-submittable, remembered remote nodes stay inert with no travel action, and the `local_map` payload contract is unchanged.
- Take/drop interaction is NOT delivered: there is no deterministic take/drop ownership-and-access API in the project, and the approved exploration design explicitly forbids registering a generic object-mutation action. No `explore.take`/`explore.drop` adapter, descriptor, or browser control ships in this change.
- Extend the Node gate, the managed Playwright suite, and deterministic Evennia fixtures with movement/time charging, look/onboarding preservation, scripted and free-form dialogue (offline degrade to greeting/silence), engage-to-combat transition, wait/rest safety rejections, stale/duplicate/tampered rejections, mode transitions, and reconnect retention journeys.
- Add no backward-compatibility adapter or persisted-data migration; the project is unreleased and Telnet play remains unchanged.

## Capabilities

### New Capabilities

- `webclient-exploration-menu`: The read-only version-1 `exploration` panel (root categories composed from registered server affordances) and version-1 `character` panel (expanded read-only state), the six exact allowlisted exploration adapters, the free-form dialogue composition root with offline degrade, the keyboard exploration dock that re-homes the service submenus, minimap movement submission, the client-local portrait-focus seam, and the Node/browser acceptance boundary.

### Modified Capabilities

- `webclient-action-dispatch`: The production action-registry contract changes from exactly the combat, service, and creation adapters to additionally require exactly the six `explore.*` adapters, each with its own exact validator and deterministic adapter.
- `webclient-local-map`: The browser minimap's currently traversable adjacent nodes become actionable — submitting `explore.move` through the `local_map` move descriptor — while the payload contract, the `未探索` unvisited-node rule, and the remembered-node no-travel rule remain unchanged.
- `webclient-service-menus`: The standalone Services root in exploration mode is re-homed under the exploration dock's Interact/Quests/Inventory root entries, and the mode-change teardown scenario is updated so the exploration dock (not a standalone service dock) unloads atomically on combat adoption; the `services` panel payload and the seven `guild.*`/`shop.*` adapters are unchanged.

## Impact

- New files: `world/rules/time_skip.py` (the shared deterministic skip helper factored from `commands/skip.py`, behavior-identical and consumed by both the commands and the `explore.wait` adapter); `web/webclient/presentation/exploration.py` and `web/webclient/presentation/character.py` (presenters + validators) with package-local tests; `web/webclient/actions/exploration_actions.py` (six payload validators + adapters) and `web/webclient/actions/dialogue_composition.py` (injected-client root + offline stub, no transport import at module scope) with tests; a DOM-independent `exploration_menu.js` model and `character_menu.js` model under `web/static/webclient/js/elosern/` with Node tests; `exploration_dock.js` and `character_dock.js` GoldenLayout plugins; and extended browser fixtures/journeys under `web/tests/browser/`.
- Edits to landed implementation files: `commands/skip.py` (delegate to `world/rules/time_skip.py`, no behavior change), `web/webclient/presentation/registry.py` (register `exploration` and `character`), `web/webclient/actions/registry.py` (register the six explore adapters), `web/static/webclient/js/elosern/protocol.js` (panel allowlist + `exploration`/`character` validators + action payload validators), `web/static/webclient/js/plugins/goldenlayout.js` (wire `node-action-ready` map nodes to submit `explore.move`), `web/static/webclient/js/plugins/services_dock.js` (re-home under the exploration dock), and the action-dock JavaScript/CSS.
- Reuses the locked Playwright dependency, isolated browser harness, OOB epoch/revision protocol, `local_map` move descriptors, `world.rules.dialogue` and `world.rules.onboarding` scripted dialogue, `world.rules.combat_session.engage`, `world.rules.skip_safety`, `world.rules.clock`, and the `LLMNPC.at_talked_to` seam; adds no runtime dependency, database migration, LLM call, or image-service call, and never registers a take/drop or generic-object mutation action.
- The `context_actions` combat panel, `services` panel, `local_map` panel, Telnet commands, and all deterministic gameplay remain unchanged; this change is the consuming surface for the dialogue seam and map descriptors those units already ship.
