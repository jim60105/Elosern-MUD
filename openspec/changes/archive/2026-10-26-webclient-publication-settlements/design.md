# Causal commit groups and independent ingress

## Context

B defines the single coordinator queue and always-Deferred public receipt contract. Existing server/conf/inputfuncs.py::text calls cmdhandler without a graphical busy gate; multiple text Deferreds and a graphical Deferred can overlap. Existing on-commit dialogue, party, lore and scene/option callbacks can publish to several watchers. Holding one session token until a domain Deferred resolves cannot model that runtime. This slice owns the complete grouping solution; M adds movement identity/facts and S adds combat/skip facts.

## Goals / Non-Goals

Preserve ordinary independent command execution, bind presentation side effects to actual synchronous committed work, and coalesce checkpoint facts with ordinary pushes for every lawful watcher before rendering/sending. No command rejection, command queue, session-wide active token across Deferreds, persistent causal log or general game event bus.

## Decisions

### Exact synchronous group API

Add world/rules/presentation_events.py with frozen `PublicationGroup(id:str)` using a unique 32-hex ephemeral ID, `publication_group()` context manager, `current_publication_group()`, `on_publication_commit(callback, *, using=None)` and `register_alignment_observer(callback)`. A nested publication_group reuses the active group. The dynamic binding exists ONLY while a synchronous callable or on-commit callback is executing, is reset in finally before returning a Deferred, and is never left active while an external operation is pending. A callback registered by on_publication_commit captures its group and rebinds it only for that callback's synchronous execution, delegating actual commit/rollback handling to Django transaction.on_commit. Callback exceptions preserve existing reporting and transaction behavior.

P enrolls ordinary callback registrations below; M/S wrap their actual deterministic mutation owners in publication_group and register checkpoint facts through on_publication_commit. An asynchronous continuation starts/reuses a fresh group around the actual synchronous deterministic call when it resumes; it never infers ownership from which session has a pending request. This is a narrow publication-context helper, not a game-state writer or generic event dispatcher. No group identity goes over the wire or into persistent state.

P also defines frozen `AlignmentIdentity(layer:str, area_key:str, instance_key:tuple[int,str]|None)` and `PresentationAlignmentFact(group_id:str, actor_id:int, cause:Literal["movement_boundary","combat_terminal","skip_completed"], source:AlignmentIdentity|None=None, destination:AlignmentIdentity|None=None)`, plus the complete emit_alignment_fact observer delivery API. M supplies the read-only identity reader and first production movement fact producer; S supplies terminal/skip producers. These are fully functional value/observer APIs with no no-op fallback. Ordinary enqueue requests accept internal optional group_id, captured from current_publication_group at the call boundary. A group-less ordinary publisher is assigned a new standalone group, never attached heuristically to a pending action. The same committed group_id is forwarded unchanged to every current lawful watcher; each coordinator retains its own baseline and receipt.

### Coordinator grouping and bounded outcomes

B already schedules every publication intent on the next reactor turn. Extend that queue with one pending group entry per group_id, preserving first enqueue order. Candidate names, explicit removals and unknown-scope flags merge within that entry; force_snapshot/checkpoint promotion wins. A fact can arrive before OR after the ordinary push callback: both target the same pending group, and no frames have been sent because all intents wait for the drain. All on-commit callbacks of the synchronous owning transaction execute before returning to the reactor, so the entry is complete before drain. Nested wrapped callback registration preserves the same ID. A group's immutable action-local round/context may be attached by completion before drain. Ordinary push callbacks do not render payloads eagerly while grouped; they submit names and a fresh context factory.

No source may publish synchronously outside private _publish_now. This applies to direct art updates, guarded helper, explicit synchronization and observer publication. Public methods ALWAYS return Deferred[PublicationReceipt|None] per B. All waiters in one group resolve with its actual receipt after all frames and attached result send, or None on sequence retirement; errors and64-entry overflow errback explicitly. The64 bound counts group entries and pending waiters; overflow invalidates baseline and reports safe failure. Remove completed group metadata after resolving its waiters, so no history grows. Buffers/pending groups clear on detach/reset. Failed source transactions enqueue no committed intent.

Explicit ui_sync is an independent forced-snapshot queue entry, never merged into a command group. It may execute while any number of domain Deferreds remain pending; it cannot interleave a prepared presentation/result batch. Async options/art generation completing later starts a new standalone group. Sources cannot reuse a completed group ID to suppress a later change: late publication is a distinct group and fresh comparison.

### Independent ingress and result attribution

Do NOT begin or hold a session-wide token before cmdhandler or an adapter Deferred. Ordinary text commands execute exactly as before, and their callback/errback observer enqueues a separate current-state unknown-scope refresh only when each command settles, preserving the original value/Failure. Two pending text commands may finish in reverse order; each refresh runs in completion enqueue order against then-current canonical state. If that command's domain commit group already published the same presentation, the refresh is unchanged and consumes no revision. This gives deterministic independent completion without merging command lifetimes or blocking text behind graphical work.

Graphical synchronous adapter invocation is wrapped in publication_group for capture; private adapter-result `publication_group_id` names that group. For adapters resuming after asynchronous work, wrap their final synchronous deterministic call and result normalization in publication_group and set that private field explicitly. M/S own the affected move/combat/wait/continuation adapters. Dispatcher _normalize_result MUST strip the internal field; no group is serialized. The dispatcher completion attaches its canonical candidates, frozen round context and matching result to that still-pending group. Terminal result normalization must occur synchronously after the core returns, before yielding to asynchronous narration/network work; any later narration remains a separate text side effect. If no core group exists, completion makes a standalone group. Result-only/sequence-retiring actions retain B's existing exceptions.

A committed domain callback outside any graphical completion, including text-driven combat, another session's action, or server dream/sleep continuation, simply finalizes its causal group at the next drain. Every watcher gets one final promoted snapshot with no preceding group delta; no initiating-session token is required. Text post-completion refresh is separate and normally unchanged. Later actual changes remain independently ordered, rather than being hidden until an unrelated Deferred finishes.

### Exact caller and callback migration

Own coordinator.py queue grouping, dispatcher.py synchronous adapter/result group capture, ingress.py text observer and observer fan-out, presentation/push.py and art_push.py name-based enqueue, and server/option_proposal_service/state.py plus title_nomination_service.py queue consumers. B already migrated all methods to the Deferred return contract; P adds group_id propagation, not another return type.

Replace ONLY presentation-relevant callback registrations with on_publication_commit so their current committed grouping survives callback execution: typeclasses/npcs.py at_object_delete and at_post_move cleanup callbacks (including nested _clear_dialogue_sessions_naming_me push); typeclasses/characters.py::_schedule_action_options_after_move and scene activation projection callback; world/rules/lore_knowledge.py::_schedule_lore_codex_push and its second deferred reveal_lore_best_effort registration at current lines229-231; world/quests/encounter_dispatch.py::_refresh_after_commit; and server/title_nomination_service.py committed trigger scheduling. Active dialogue availability/reading/unread and lifecycle work must capture the same helper at their own queue_dialogue_refresh registration when it exists, preserving all owner discovery and authorization. P does not create those unimplemented domain features. Options/art actual asynchronous generation completion intentionally gets a new group; immediate generating/current-state options pushes inherit the captured current group. Keep art queue writes and unrelated world state callbacks unchanged.

Wrap each callback registration's fallback outside a transaction with the same captured group. Do not blanket-monkeypatch Django/Twisted scheduling or globally intercept every on_commit. When M/S later enroll movement/terminal/skip owners, all existing nested presentation callbacks now inherit their causal ID without new callback-order assumptions. This slice is runnable on current ordinary grouped push behavior before those checkpoint causes are introduced.

## Risks / Trade-offs

The one-shot next-turn drain is publication batching, with no elapsed-time alignment timer or new ACK. Correct causal capture requires the enumerated callback registrations, so those are implementation tasks rather than an investigation. Synchronous dynamic scope resets before every pending Deferred; independently resumed core work uses its explicit new group. This avoids a session-wide exclusion policy and keeps command execution unchanged. No performance measurements are required.
