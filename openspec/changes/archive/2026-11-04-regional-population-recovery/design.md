# Design

## Context

`WorldClock.advance` snapshots registered owner surfaces before its transaction and restores mutable caches on failure. `register_event_source(kind, source, surfaces, *, next_boundary=None)` is the current seam. Combat time remains terminal-only; `_finalize_resolved_round` knows the completed-round ordinal, while `settle_combat_result` advances all accumulated seconds at battle end. Its regional-population capability is introduced by the required predecessor and becomes the authoritative target before this dependent change archives.

## Goals / Non-Goals

Deliver this proposal's bounded regional-population prerequisite or cutover, using existing deterministic owners and real runnable operations. Do not implement adjacent field movement/aggression/escape or independent monster content. No compatibility paths or save conversion.

## Decisions

### Exact transition, timeline and projection contracts
Manual-monster-compositions is a real prerequisite: its durable site member IDs, composition API and seed contract must exist before the chronological site adapter here. Whole-cell admission consequently lands before this timing cutover.
The map owner adds frozen values `PopulationPosition(wilderness: str, x: int, y: int)`, `PopulationPresence(alive: bool, position: PopulationPosition | None, home_zone: str | None, site_key: str | None)` and `PopulationTransition(source_id: str, individual_id: int, occurred_tick: int, before: PopulationPresence, after: PopulationPresence)`. Position is the actual coordinate registration, never a pooled room ID. Capture before facts before HP/removal/location writes and after facts after successful owner mutation. A deleted object has after.alive=False and position=None; retain its before home/site/cell even when the ORM object is gone. A local foreign loss affects the physically containing zone, and a home-owned loss outside that zone also affects its home ceiling. Record once globally, deduplicate by source_id/individual_id while pending, and use set IDs so the two measures never double-count an individual.

Implement `record_population_transition(wilderness, transition: PopulationTransition) -> None`, `population_counts(wilderness, zone_key: str, *, at_tick: int | None=None) -> PopulationCounts`, and extend `plan_population_wave(wilderness, zone_key: str, *, tick: int) -> PopulationWavePlan` to project counts/protection at that tick. `at_tick=None` means actual current state and is the public read default. Historical projection starts from actual current IDs and reverses pending transitions later than at_tick using their complete before facts. This restores deleted/out-of-zone home members for accounting without recreating objects or public presence. Apply transition batches at equal ticks in stable source/individual order, then evaluate deficits from the resulting set, avoiding iteration-order transient deficits.

Persist `wilderness.db.population_timeline` as a whole-value JSON-safe mapping with `settled_through_tick: int`, `transitions: list[dict]` and `protection: list[dict]`. Each transition dict has source_id, individual_id, occurred_tick, before and after; each presence dict has alive, position (null or {wilderness,x,y}), home_zone and site_key. Each protection dict has engagement_id, cell {wilderness,x,y}, start_tick and end_tick. It is a closed protected interval [start_tick,end_tick]. Active sessions carry an open end, as specified below. All numeric fields reject bool. Timeline serialization and compensation belong to regional_population; a missing malformed timeline is a named owner-state refusal, never a best-effort reconstruction from old records. The explicit fresh seed/provisioning operation creates an empty timeline at its current tick without enabling ordinary births. Existing incompatible development worlds require explicit repair/reset.

Pending facts are consumed only after the chronological coordinator has applied their boundary and advanced settled_through_tick; closed protection is retired only after progress passes its end. Persist projection baselines needed by any still-unsettled future fact. Duplicate committed combat replay is stopped by the existing session revision/completion receipt before notifying again; do not create an unbounded second receipt system. Noncombat caller retries follow their existing owning receipt or named missing/deleted-target refusal. Snapshot the timeline and all referenced owner/cache surfaces before mutation and include it in every enclosing rollback registry.

### Combat occurrence and protection storage
Add required `started_tick: int` and `population_cell: dict | None` to new CombatSessionRecord storage, where population_cell is null for abstract/staged nonwilderness combat or exactly {wilderness: str, x: int, y: int} for mapped wilderness combat. Strict serialization validates the fields; no current-tick fallback or old-record reader. Candidate and engagement builders set them once from the actual map registration. An active record protects that cell from started_tick through the logical current battle endpoint, independent of pooled-room reuse. Preview writes nothing.

In `_finalize_resolved_round`, compare captured HP-before/after for newly defeated Monster IDs, including upkeep, and record complete transitions inside the same round transaction. `occurred_tick = started_tick + completed_round * existing_round_duration`, preserving the existing six-second clock contract. source_id uses engagement ID, round provenance and individual ID. Do not parse EventLog prose, predate a later-round death to the precombat tick, notify a simulated exam/knockout/flee as defeat, or advance fatigue/time during a live round.

Before clearing any terminal mapped session, copy its exact cell and closed [started_tick, started_tick + rounds_elapsed*round_duration] protection into population_timeline, in the same transaction before catch-up. Include existing historical active session records during nonterminal reload. The maps coordinator receives protection from the durable timeline plus currently active strict session records, never from a mutable room ID or an untrusted malformed session. A terminal/GM cleanup that removes an otherwise valid session copies its lawful interval before clear_session; existing malformed-record quarantine derives no untrusted time/protection. A restart during combat or after a committed terminal receipt retains these facts until catch-up passes them. Births at a protected endpoint tick remain blocked; the next positive retry can use the cell after protection ends.

Example: start100, round3 death118, delay10 means earliest due128. A wave at110 cannot count the later death as free local or home headroom, even if the defeated object was deleted before catch-up. No participant is replaced and no enemy is appended to a persisted session.

### Merged chronological population lifecycle
Create `world/maps/population_lifecycle.py` with `settle_population_lifecycle(start_tick: int, end_tick: int) -> list[ScheduledEvent]`, `next_population_lifecycle_boundary(start_tick: int, end_tick: int) -> int | None`, `snapshot_population_lifecycle_surfaces(start_tick: int, end_tick: int) -> dict[int, SurfaceSnapshot]` and `register_regional_population() -> None`. It is a coordinator inside the existing player-driven clock stage, not a second time authority. Registration idempotently installs this coordinator under the existing `monster_site_lifecycle` stage kind, replacing that stage's whole-interval site-only callback. It combines site and regional snapshots. Do not register a second independently whole-interval regional stage. Production activates this registration only in the final runtime cutover before restoration.

Refactor the existing site owner to expose pure `next_site_boundary(start_tick: int, end_tick: int) -> int | None` and `settle_monster_sites_at(tick: int) -> list[ScheduledEvent]`. Its state/conditions remain site-owned. An uninitialized site's first creation boundary is the interval start; recovered sites use their exact cleared_at_tick + recover_after_ticks. Last-member clear-out uses the committed loss occurrence boundary, not end_tick and never mere absence. It reads the same projected owned-ID presence at the evaluated tick. Do not alter one-shot conditions, resurrect old members or move site writes into the coordinator. Migrate existing site source registration/callers without a legacy whole-interval side path.

The coordinator merges interval-start initialization, pending transition occurrences, site lifecycle boundaries and regional recovery due times. Select the earliest boundary, apply all presence/loss facts at that tick, establish/cancel appropriate deficit episodes, settle site clear/create/recover operations in stable site-key order, then recompute counts and settle due regional waves in zone-key order. Any transitions/boundaries created there re-enter the same ordered queue before proceeding. Same-tick explicit site births precede ordinary regional births. No later site recovery is visible to an earlier regional wave. Stop at end_tick and persist exact progress; repeated intervals do not reapply settled boundaries. The pure next-boundary query shares planning but consumes no sequence/draw/state. Preserve other clock stage order, terminal-only combat settlement and rollback contracts.

### Recovery episode state machine
At each chronological population transition boundary, compute the before/after local deficit using projected counts. A first below-L state at T sets due=T+delay only if no episode remains. Further losses leave a pending due unchanged. Initialization blocked below L establishes an episode at its initialization tick. A later loss boundary MUST establish a fresh episode if an earlier wave or restored density ended the old episode, even when that loss was recorded while the old episode was pending. Publishing a future transition never prematurely consumes that boundary.

At a due tick, recompute local/home counts first. If local>=L cancel without birth, draw or generation-sequence change. Otherwise commit only fitting complete compositions within all four ceilings and wave budget. If local remains below L after births or lawful blockage, set next due=that due tick+positive replenishment_interval; otherwise clear. Blockage leaves generation_sequence unchanged and emits one bounded outer-commit `monster_population_recovery_blocked` reason event. Explicit arrivals/restoration can end an episode at their actual transition boundary, with no birth or sequence increment. Reaching L does not require an exact count or deletion.

Required counterexample: L3, projected local2, due110, and a future loss at118 already recorded. The110 wave reaches3 and clears recovery; at118 the loss creates a NEW due128 with delay10. Repeat with an explicit restoration/cancellation before118. Both outcomes must hold under one advance or equivalent partition. Also place a site inside the zone that recovers at140: compare [100,160] with [100,125],[125,160], proving its later births do not consume the110 headroom prematurely. Compare birth plans/retained-ID relationships across separate test DBs, not equal allocated dbref numbers.

### Existing mutation-route cutover
Route these existing lawful mutations through registration plus transition recording, within their CURRENT deterministic ownership and atomic/cache rollback boundaries:

| Existing caller | Required integration | Real controls |
| --- | --- | --- |
| world/maps/gm.py::spawn_monster | Already map-register via owner prerequisite; record absent-to-live presence after creation | Spawn/view/count/recycle/reload |
| world/maps/gm.py::delete_entity | Capture complete presence/home/site before deletion and before session clear; record removal with actual current logical tick | Delete below L, delayed recovery, deleted-home history, fault after delete |
| world/rules/gm.py::{set_gauge,set_trait_base} | Capture before/after Monster HP; notify only a real live/dead crossing, retaining lawful explicit restoration | HP0 deficit, restoration cancellation, trait-cache rollback |
| world/rules/movement_settlement.py::settle_relocation | Record exact old/new map presence for existing GM relocation; retain home ownership; departure can create local deficit but is no defeat | Local/home independence, legal explicit destination, rollback |
| world/quests/materializer.py::spawn_monster and scene_builder callers | Map-register real wilderness placements and record actual arrival; retain quest authority and explicit-placement exception | Quest real placement/view/rollback |
| combat_session/rounds.py and shared mapped noninteractive action/upkeep commits | Record once at provenance-owned occurrence; abstract pure combat has no world notification | Late-round death, upkeep, duplicate receipt, no flee/KO notification |
| world/maps/monster_sites.py | Record site creation/recovery/clear transitions at coordinator tick through site owner | Exact site due boundaries and regional headroom |

Use `record_population_transition` for additions/removals/relocations, not only defeats. Birth transitions do not recursively schedule extra clock advances. Explicit raw repair remains the documented exceptional raw owner; it creates no normal guarantee and must be followed by the explicit operator repair workflow, never a hidden ecology reset. No new command, GM verb, movement policy or ecology system is introduced. Update affected command documentation if existing availability changes, and document these mutation/compensation contracts in the population developer document.

### Scope
Own regional_population, population_lifecycle, monster_sites chronological adapter, combat record/round/settlement fields, the enumerated existing mutation integrations and their tests. Do not implement wandering, aggression, journeys, flee relocation, new content or live-round fatigue. Full source activation and old ambient deletion remain the final runtime slice.

## Risks / Trade-offs

The existing display-name, coordinate-slot and supply contracts have broad callers. Complete the named semantic caller cutover within this slice; do not add a parallel legacy path. Candidate-world validation and mutable Evennia cache restoration are part of correctness. Use synthetic independently known mechanism outcomes and real-owner integration controls instead of production data-echo tests.

## Verification and requirement traceability

Focused command: `uv run --locked --env-file=/tmp/mud-population-test.env evennia test --settings test_settings.py --keepdb LABELS`. Replace LABELS with one affected focused method or class from the module inventory below, keeping the single-token env-file form; run independent focused invocations, never concatenate the whole inventory or exceed 100 discovered tests in one command. Use fixed synthetic inputs and independently known outputs. Production checks establish references, ownership/topology and profile obligations without copying shipped values or prose. New nonbrowser modules require exact ownership in `.github/evennia-shards.json`; browser methods, if added, require `.github/browser-shards.json` ownership. Run observability lint alongside focused tests when logging changes. Full managed browser and complete evidence verification remain CI-owned.

Before changing annotations, record each affected assertion's synthetic-mechanism, registry-contract or representative-smoke role and substantive replacement in `docs/development/regional-monster-population.md`. Canonical IDs below came from `uv run --locked python -m tools.spec_traceability list --json-output /tmp/regional-population-requirements.json`. ADDED requirements have no current IDs; never fabricate one. Before archive, use the tool on an equivalent merged spec tree, then replace provisional nearest-current claims with generated IDs. After the completed slice run `openspec validate <change> --strict` and `uv run --locked python -m tools.contract_gate`. This gate does not establish coverage of unarchived deltas; the assertion-role ledger and focused evidence remain required. The runtime slice owns the cross-system real smoke; each earlier slice still owns real-owner integration and reload/fault controls.

## Deployment and rollback boundary

No migrations, legacy readers, aliases, implicit reset or compatibility setting are authorized. New ordinary runtime activates only at regional-population-runtime-cutover; earlier APIs are fully implemented and independently exercised through real owners. Operation failures restore durable and live surfaces through deterministic owner compensation. An incompatible development save requires documented explicit GM save/repair/reset procedures, never startup mutation. A source/code rollback requires its matching explicitly saved development state, with no incompatible-record reinterpretation.
