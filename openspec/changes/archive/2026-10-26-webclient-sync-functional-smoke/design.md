# Integrated changed-path functional verification

## Context

All preceding implementations are required, including S/I's transitive dependencies. Existing managed-browser patterns are BrowserAcceptanceTest in test_vue_transport_mount.py and actual WebSocket capture/coordinator fixture in test_map_transport.py/world_map_transport_fixture.py. Full managed-browser suites and evidence verification remain CI-only. This change supplies focused end-to-end functional acceptance; component and unit tests must already accompany each owning runtime slice.

## Goals / Non-Goals

Prove the real modified publication path reaches the real browser reducer/view after committed gameplay actions and recovers safely under deterministic delivery faults. No production-only test action, mock protocol store, fake baseline, special-case acceptance schema or second synchronization coordinator. No benchmarks, latency comparisons, browser long-task profiling, allocation measurement or no-stutter claim.

## Decisions

### Exact fixtures and new test labels

Add `web/tests/browser/test_incremental_sync.py::IncrementalSyncBrowserTests` with four focused methods and test-only `web/tests/browser/incremental_sync_fixture.py`. Use the existing managed server, synthetic seed kit, authenticated browser and production coordinator/registry. Add seed data to `web/tests/browser/seed` only for these exact cases; register under the existing fixtures runner. No shipped NPC/lore/balance assertions. Test-only fixture callable invoked through existing superuser @py mechanism may seed canonical inventory, guild/quest or scene state, then call real coordinator; it cannot bypass panel validation, set a fake client revision, stub session.msg or introduce production wire verbs. Small transport fault interception is restored after each test.

1. `test_graphical_and_text_checkpoint_sequence`: capture incoming socket command/args and subscriptions. Perform actual same-area graphical move and ordinary nonterminal combat action, assert changed panels only with exact current B and preserved untouched eager panel data. Traverse an authoritative different map/instance boundary through text, then finish combat or a rest/sleep operation through their normal callable command/UI route, assert one fresh complete eager checkpoint per settlement and its result revision/order. Include unchanged read action and metadata-only skip-free publication controls via real coordinator. Ordinary text action may be unchanged and consume no revision. Record command success/output as well as presentation.

2. `test_oversized_snapshot_and_delta_adopt_once`: the server fixture builds valid production registry payloads whose aggregate UTF-8 bytes exceed65536, calls real publication preflight and sends through Server->AMP->Portal->WebSocket. Use repeated bounded CJK quest/service or gallery/character rows within existing field and panel budgets; validate fixture through Python production validators first. A single-panel case uses a legal <=65536-byte panel sufficiently close to that ceiling that its envelope/header cannot fit; this proves panel-boundary splitting cannot solve it without relaxing the panel's own byte cap. General codec tests separately use a synthetic schema with an explicitly larger panel-local limit to prove raw byte fragmentation is panel-agnostic; never widen production schema for the fixture. Browser must receive ui_publication_part and commit once at final part, with no intermediate revision/mode/time/panel change. Assert each actual part envelope <=65536, exact bounds/header consistency, target revision/result order and complete content equality. These are functional byte-bound checks, not a payload measurement/benchmark project. An intact specialized world_map regression stays on its existing scoped path, with no general wrapper or unopened map load.

3. `test_missing_publication_recovers_complete_baseline`: intercept ONE genuine delta on the real socket before the app reducer sees it, then allow the next genuine delta or matching newer result to reach production receive. Assert prior complete state remains, mutations lock and exactly one ui_sync is sent. Recovery must re-render and adopt all eager panels. To demonstrate correction of missing invalidation, the server fixture changes a canonical field and deliberately omits its owning panel from one known-candidate publication in test scope only; the next real semantic checkpoint must restore that panel. Also drop one general part and trigger the assembly deadline using injected scheduler in unit tests; in browser use a contradictory/missing-predecessor real part fault for immediate deterministic recovery without a 30-second wait. Preserve action dedup and no automatic mutation retry.

4. `test_failed_recovery_and_alignment_preserve_local_state`: fail the one recovery snapshot with a deterministic transport corruption, assert no repeated sync loop and graphical lock/unavailable state while text input/output still works. Restore real delivery, explicitly sync or reconnect and verify new epoch/base establishment. Before a same-mode checkpoint open a valid drawer/menu, focus an item and enter unsaved local text; assert that state survives checkpoint, while an actual mode/identity/availability change invokes existing teardown. Keep a reference from a subscriber and attempt mutation, then verify committed content remains correct.

The producer fixture must return its actual PublicationReceipt target and expected committed field values, never invented expected revision numbers or a digest scheme. Compare independent fixture-known values; do not invoke the comparator under test to manufacture expected results. Record exact frames and browser state in existing assertion output. Do not assert a fixed number of unrelated legitimate later async publications; identify the completing publication by receipt/result revision and exclude separately ordered asynchronous options/art pushes by their own revisions.

### Integration ownership and acceptance commands

Own only new focused browser tests/fixture/seed, browser/Python shard registrations and traceability declarations needed for those tests, plus implementation documentation notes. Avoid adding production code in this final slice. If smoke exposes a runtime defect, return the failing behavior to the owning earlier change's implementation work, fix it before acceptance and retain the scenario; no weakened fixture or narrowed scenario.

Add each browser method to exactly one `.github/browser-shards.json` owner. Nonbrowser fixture/unit modules under web/webclient go in exactly one `.github/evennia-shards.json`; do not register browser support as a nonbrowser test. Maintain requirement decorators and fixture data-independence ledger only when a new tagged data-contract test is truly required (none is expected).

Run the four methods as separate local unittest_driver commands (labels in tasks), each under five minutes, followed by focused existing map transport regression if affected. Use pnpm/Vite managed harness build from source, never hand-author dist. Execute `uv run --locked python -m tools.contract_gate` once at final integration and report observed results. Complete CI-owned full browser/evidence suites are not local prerequisites to invent or run. No runtime verification is claimed by proposal creation.

## Risks / Trade-offs

Synthetic fault injection must exercise the real transport/reducer without persistent production seams. Keep fault scope bounded, unsubscribe listeners/restore interception after each case and release both general/map assemblies on disconnect. The real changed-path smoke is mandatory functional evidence, independent of any measured performance.
