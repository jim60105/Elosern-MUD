# Proposal

## Why

Dream collaboration currently generates PhaseTopic keyword/response records which the dialogue resolver reduces to a host line. These NPCs require the complete shared scene, qualification, reading and playback pipeline without source-file writes or a parallel generated dialogue engine.

## What Changes

- **BREAKING** Replace generated PhaseTopic response payloads with shared actor-first topic scenes, variants, requires/refusal, predecessor and disclosure declarations; remove all old response/keyword-action consumers without migration or compatibility paths.
- Amend the actual dream dispatch/scenario-director prompt and inline output schema, permissioned reference context, deterministic package compiler and immutable DB publication together.
- Resolve stable package-role/phase-local topic IDs through the common provider, selection, effect, reading and playback APIs.
- Preserve phase/knowledge/escort provenance, existing allowlisted commission authority, freeform generation, offline/reload and atomic settlement. No LLM-invented effects.

## Capabilities

### New Capabilities
- `generated-dialogue-scenes`: End-to-end generated scene publication and participation in the common dialogue engine.

### Modified Capabilities
- `story-phase-dialogue`: Complete scene declarations within existing authoritative phases and stale-work retirement.
- `scenario-director`: Production dream scene prompting/schema carries the common dialogue model and permitted references.

## Impact

Exact observed production symbols and five 60-90 minute implementation units are in design/tasks. Reuse existing immutable ScenePackage DB storage, publication_scope and deterministic world/quests owner. No new tables, migrations, file registration, generated YAML, global static-registry publication or new scene player. Existing model/private authoring remains non-authoritative.
