## Fixture and classification mechanics

Use existing `world/testing/` test-data kit and file-local scoped fixtures. Keep DB identity cases under the repository's existing Evennia fixtures; pure schema/arithmetic tests remain pure unittest cases. Do not add a second fixture registry, a copied balance helper or a second numerical lint engine. Scope registry/rulebook patches with guaranteed restoration so shared tests remain isolated.

Classified files intentionally retaining generic real-content checks keep their first-line `Data-contract test:` reason. If a file becomes solely synthetic, remove its contract classification and move any still-needed generic content checks into an existing registered file. Update the matching `tools/test_data_freeze.json` and the corresponding contract entries/reasons in `tools/test_data_lint_seed.json` atomically. The existing loader compares seed contract reasons and rejects registrations outside its seeded classification. Do not modify/add `seedDebtPaths`, re-seed debt, add arbitrary exemptions, or delete a seeded file without retiring its contract metadata. No gate-code redesign is required.

Keep current requirement IDs stable when headings remain unchanged; add IDs for the four new test-design requirements. Update IDs only for intentional renames, with a complete mapping. Each migrated requirement association must point to an assertion property from this plan. Do not hide missing coverage with a waiver, source-count metric or bulk decorators on an echo smoke.

## Scoped acceptance perturbations for implementation

Run these after the migration, restoring each temporary perturbation in `finally`/fixture teardown. They are acceptance evidence, not a new permanent exhaustive suite per species.

1. Increase one valid crocodile HP or MP value within its existing tier constraints; tune one positive skill cost/coefficient, a finite rider duration, a negative accuracy magnitude, a positive defense magnitude, a nonzero spell magnitude, a price/stock value, a daily budget and a valid unlock threshold. Choose values preserving all existing explicit comparative/quality invariants. Relevant generic/content/integration tests remain green without editing expected data. Re-run unchanged shared synthetic tests.
2. Break one effect/status/modifier/profile reference at a time: named integrity checks fail. Break owner identity or ability binding: owned selection/construction fails.
3. Change an enemy-only rider to self, or a self-guard to enemy: integrity or representative smoke fails on recipient state while the untouched control remains unchanged.
4. Set a hit dependency to a wrong/out-of-range/forward occurrence, or bypass miss qualification: integrity/shared hit tests fail. Gate crab self-guard incorrectly on damage: its hit-independent smoke/shared composition fails.
5. Skip MP/SP deduction or incorrectly credit requested instead of actual drain: independent synthetic end-state/resource assertions fail.
6. Inject a failure after a gauge/buff write and after practice claim acquisition: resources, buffs, practice/evidence, world time and reloaded DB state match the pre-action snapshot, and a retry proves the claim was released.
7. Lose the durable depleted gauge/buff/source state on reload or reapply a fresh profile during startup: representative persisted-state observations fail.

Record the changed field, expected property, observed assertion failure/pass and restoration for each experiment. Passing benign tuning does not excuse violations of intentional invariants. No production balance changes are committed.
