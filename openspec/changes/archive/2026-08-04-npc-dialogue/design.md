## Context

The deterministic engine is complete and playable (change-16 milestone). Change 17 supplied the generative foundation: `OpenAICompatClient`, per-layer `LLM_PROFILES` (including the `npc_dialogue` layer), the validation–retry–degrade guardrail with per-layer semantic-validator and degrade-fallback registries, `FakeLLMClient`, and the schema registry seam. Change 18 built the Narrator as the first consumer; NPC dialogue is the second.

Design §7.4 fixes the contract: an LLM reply is a `{"speech": str, "intent": {...}}` object. The intent kind is restricted to a seven-kind whitelist — `give_item` / `take_item` / `offer_quest` / `request_guild_exam` / `adjust_relation` / `reveal_lore` / `none` — and the deterministic engine verifies each intent against the world before applying it. **Illegal intent is discarded while the speech is kept**; that is the accepted failure mode. The examination intent (`request_guild_exam`) carries exactly one payload field, `target_rank`, and is passed to change 16's `start_guild_exam(..., requested_by="npc_intent")`, which rechecks co-location, the GuildExaminer component and branch, the exact next rank, true cumulative merit, and absence of active combat/exam. Design §7.5 fixes the degradation: the `npc_dialogue` layer falls back to greeting or silence. Design §10 fixes the test rule: generative tests use `FakeLLMClient` and never contact a real endpoint.

Two architectural constraints shape every decision here:

1. **The single-writer / transport boundary.** No module under `world/ai/` may import a state writer (`world.rules`, `world.maps`, `world.quests`, `typeclasses`, spawner, create) or a live transport (`evennia.contrib.rpg.llm`, `twisted.web`, `twisted.internet.reactor`), and no module under `world/ai/` may import `typeclasses` (a state writer). The repository-wide contract test (`tests/test_ai_transport_contract.py`) enforces this by AST scan with no edits. Consequences: the generative reply layer must consume the client through an injected protocol and cannot know about `NPC`, `LivingEntity`, `disguised_stats` attributes, or the authored greeting table.
2. **Design §4's reuse row must be amended.** The §4 table says `ai/npc_dialogue.py` **Subclasses** `evennia.contrib.rpg.llm.llm_npc.LLMNPC`. This is not implementable: (a) importing `evennia.contrib.rpg.llm` from any `world/ai/` module except `client.py` violates the frozen transport contract; and (b) the project's `NPC` is `LivingEntity`-based — `LivingEntity(ComponentHolderMixin, ObjectParent, DefaultCharacter)` — and the contrib `LLMNPC` is also a `DefaultCharacter` subclass, so the two cannot be combined by multiple inheritance (a Django model MRO conflict). The amendment: the generative logic (prompt, schema, validators, sentinel, guarded call) lives in `world/ai/npc_dialogue.py`; the entity typeclass `LLMNPC(NPC)` lives in `typeclasses/npcs.py` and *ports* the contrib's chat-memory and thinking-state behaviors rather than subclassing the contrib — the same "extend/author, not subclass-of-existing" amendment the project already recorded for `OrderedLevelTrait` and `PyramidMapProvider` in §4's verified note.

The deterministic surfaces already exist and are consumed, never rewritten: `world/rules/guild_exams.start_guild_exam` (change 16), `world.rules.equipment.plan_inventory_delta`/`apply_inventory_plan` (change 16), `world.rules.dialogue.greeting_for` (scripted-dialogue/onboarding), and `world/rules/onboarding.py`'s authored greeting tables.

## Goals / Non-Goals

**Goals:**

- Provide `world/ai/npc_dialogue.py` with `generate_npc_reply(...) -> Deferred[NPCDialogueReply | None]`, mapping an NPC dialogue context to a validated frozen `NPCDialogueReply(speech: str, intent: dict)` through the `npc_dialogue` layer's guarded pipeline, resolving to `None` on any degrade trigger. The client is a **required** injected argument: a call with `client=None` must errback with a named `NPCDialogueClientRequiredError` as the first statement, before any prompt construction or transport work.
- Provide `build_npc_dialogue_prompt(...)` — deterministic, bounded, entity-key-only prompt construction that injects the speaking player's `disguised_stats` so the model describes the player as the NPC perceives them, and instructs the model to reply with a `{speech, intent}` object in 正體中文 without inventing outcomes.
- Register the `npc_dialogue` layer's guardrail hooks: the `{speech, intent}` output jsonschema, semantic validators (speech shape, seven-kind intent whitelist, per-kind payload shape), and a sentinel degrade fallback. Provide `register_npc_dialogue()` so production wires the hooks from the registration site, atomically with rollback, idempotent, and boot-tolerant — exactly like `register_narrator`.
- Provide `world/rules/npc_intents.py` with `apply_npc_intent(npc, player, intent) -> IntentOutcome`, the deterministic verifier-and-applier: `request_guild_exam` delegates to `start_guild_exam(actor=player, examiner=npc, target_rank=..., requested_by="npc_intent")`; `give_item`/`take_item` verify holdings and transfer both sides atomically through a dedicated dual-snapshot transfer primitive; unverifiable intents are discarded while the speech is kept; `offer_quest`, `adjust_relation`, and `reveal_lore` are whitelisted but rejected behind forward-declared seams until their capability surfaces land.
- Provide `LLMNPC(NPC)` in `typeclasses/npcs.py` with per-character chat memory, thinking-state feedback, and an `at_talked_to(speech, character, client)` seam that builds the prompt, runs the guarded pipeline with a **required injected client** (never constructing transport itself), maps the degraded outcome to the authored greeting or silence, and routes a verified intent to the deterministic applier. The seam imports `world.ai` and `world.rules` only inside the server-ready call path, never at module scope.
- Preserve the single-writer and transport boundaries exactly as the existing contract test enforces them, and keep every generative test offline via `FakeLLMClient`.

**Non-Goals:**

- Wiring the `talk` command or webclient menus to `LLMNPC`. `commands/` is a deterministic package that may not import `world.ai`, and the roadmap assigns exploration/dialogue presentation to change 23d. This change ships the consumable seam (typeclass `at_talked_to`, guarded reply layer, deterministic applier), not the command splice.
- Implementing deterministic capability surfaces that do not exist yet. `offer_quest` needs a quest-issuer capability (no `QuestGiver` component exists), `adjust_relation` needs the unbuilt relations handler (`LivingEntity.relations` is an unassigned placeholder), and `reveal_lore` needs a lore-reveal API. These intents are whitelisted in the schema and rejected by the applier behind forward-declared seams with guarded tests; no fake implementation is shipped.
- Structured tool calls, streaming, or re-parsing the speech back into state. The speech is display-only; only the validated `intent` may reach the deterministic applier.
- Any change to `world/ai/guardrail.py`, `world/ai/client.py`, `world/ai/profiles.py`, `world/rules/guild_exams.py`, `world/rules/equipment.py`, `world/rules/dialogue.py`, or the deterministic game loop.
- New settings keys, dependencies, container changes, or persisted-data migrations. `LLM_PROFILES["npc_dialogue"]` already exists with the local-first default.
- Backward-compatibility adapters; the project is unreleased.

## Decisions

### D1. `generate_npc_reply` is a thin guarded mapping with an explicit public result type

`generate_npc_reply(client, *, npc_context, player_context, memory)` builds a `ChatRequestDescriptor` whose `messages` come from `build_npc_dialogue_prompt(...)` and whose `schema_id` is `"npc_dialogue"`, then yields the `npc_dialogue` layer's `guarded_call("npc_dialogue", client, descriptor)`. **`client` is a required keyword argument and is validated as the first statement**: an explicit `None` errbacks with a named `NPCDialogueClientRequiredError` before any prompt build or transport work, so an injection failure can never surface as `None.get_response()` inside the guardrail. The module never constructs, imports, or defaults a live client (the transport contract forbids it).

Because the output is structured, `guardrail.guarded_call` validates the returned text against the registered `{speech, intent}` jsonschema (the guardrail already parses JSON when an output schema is declared). On success it returns the accepted JSON **text**; `generate_npc_reply` `json.loads` it into a frozen `NPCDialogueReply` dataclass carrying `speech: str` and `intent: dict`. The public return type is therefore `Deferred[NPCDialogueReply | None]`: on disable/transport-failure/exhaustion the guardrail returns the layer's registered fallback, `generate_npc_reply` detects its internal sentinel and resolves to **`None`** — the single public degraded marker. Consumers branch on `None` (render greeting or silence) instead of inspecting a private sentinel, so the offline path is a first-class, type-honest outcome rather than a violation of the declared `Deferred[dict]`. The module imports only `guardrail`, `profiles`, `schemas.descriptor`, `schemas.registry`, `json`, `defer`, and `dataclasses`, so the existing contract test stays green with no edits.

Alternative considered: returning the raw text and letting the caller parse. Rejected — the caller would re-parse JSON that the guardrail already validated, duplicating the schema contract and risking drift between schema and consumer. Alternative considered: returning a private module-level sentinel object to signal degradation. Rejected — a caller holding a `Deferred[dict]` contract would crash on `reply["speech"]` when offline; the explicit `NPCDialogueReply | None` union makes the degraded branch structurally unavoidable and documented.

### D2. The prompt is deterministic, bounded, faithful, and injects `disguised_stats`

`build_npc_dialogue_prompt(npc_context, player_context, memory)` returns a `(system, user)` message pair. The system message fixes the role (the NPC named, described, and located in 伊洛瑟恩大陸), the language (正體中文), and the output contract (reply with a JSON object `{"speech", "intent"}`; never invent outcomes, numbers, dialogue, or state; express only what the NPC could perceive). The user message serializes the player's identity and `disguised_stats` — the values the NPC actually sees — plus the bounded chat-memory window, with stable JSON serialization (`sort_keys=True`, `ensure_ascii=False`).

Hard bounds mirror the Narrator: a fixed maximum memory-line window (oldest dropped with an explicit marker), per-field string-length caps, and a bounded total size, so a long conversation or pathological input cannot produce an unbounded request. The prompt contains only plain JSON-compatible data — no live entity references — consistent with the entity-key-only rule. Determinism makes identical input always produce byte-identical prompts.

**The `disguised_stats` injection is the D2 payoff.** `disguised_stats` is display-only and the NPC is a display-layer observer: by serializing the player's disguised values as what the NPC perceives, a disguised elf genuinely reads as weak to the model, and the narrative consequence falls out with no special case. The true traits never appear in the prompt.

Alternative considered: sending the raw chat transcript only. Rejected — the model needs the NPC identity and the perceived-player framing to stay in character and to understand what it could legally perceive.

### D3. Degradation is a public `None` outcome, mapped by the caller to greeting or silence

Design §7.5 fixes the `npc_dialogue` degradation: fall back to greeting or silence. The guardrail's registered degrade fallback is a zero-argument, global-per-layer callable and cannot know which NPC or player the failing call served. `world/ai/npc_dialogue.py` therefore registers an **internal module-level sentinel** as its fallback:

```python
_NPC_DIALOGUE_DEGRADED = object()
register_degrade_fallback("npc_dialogue", lambda: _NPC_DIALOGUE_DEGRADED)
```

`generate_npc_reply` detects the sentinel on any degrade trigger (profile disabled, transport failure, exhausted retries) and resolves to the public degraded marker **`None`** (D1). The caller — the `LLMNPC` typeclass in `at_talked_to` — branches on `reply is None` and maps it to the NPC's authored greeting via `world.rules.dialogue.greeting_for(npc)` when one is available, or to silence when it is not. The internal sentinel is compared only inside the module (identity comparison can never collide with a legitimate `NPCDialogueReply`); callers interact solely with the documented `NPCDialogueReply | None` union. The greeting lookup stays outside `world/ai/` (which may not import `world.rules`).

**Registration gate.** `generate_npc_reply` begins by checking, against the **guardrail's actual registry state**, that the `npc_dialogue` layer is registered with this module's sentinel (inspecting `guardrail._degrade_fallbacks`), rather than trusting a module-level flag. If the layer is genuinely absent, it raises `NPCDialogueNotRegisteredError` before ever reaching `guarded_call`. This mirrors the narrator's D3 gate exactly: a test that clears the shared registries automatically makes the gate fire again, and the next `register_npc_dialogue()` genuinely reinstalls the hooks.

Alternative considered: registering a per-call degrade closure that emits a greeting. Rejected — the guardrail registry is global per layer, the greeting lives in `world.rules`/`world.onboarding` (unreachable from `world/ai`), and a sentinel plus caller-side mapping keeps the guardrail contract intact. Alternative considered: exposing the sentinel object itself as the public degraded marker. Rejected — a private object leaks across a module boundary as an untyped contract; the documented `NPCDialogueReply | None` union is the public contract and the internal sentinel stays an implementation detail.

### D4. Semantic validators enforce the intent whitelist and per-kind payload shape

The `npc_dialogue` layer registers semantic validators under stable names so the shared pipeline retries on shape violations and degrades on exhaustion. Validators operate on the parsed `{speech, intent}` object and reject:

- empty / whitespace-only speech, or speech exceeding a fixed length cap;
- speech containing no CJK Unified Ideograph (`\u4e00`–`\u9fff`), i.e. the model did not reply in 正體中文 as the output contract requires;
- an `intent` that is not a dict, or whose `kind` is outside the seven-kind whitelist;
- per-kind payload violations: `request_guild_exam` must carry **exactly one** payload field, `target_rank` (a non-empty string) — any extra or missing field is rejected; `give_item` and `take_item` must carry `item_key` (non-empty string) and a positive integer `qty`;
- speech or intent containing leaked template-placeholder syntax (`{actor}`, `{target}`, `{...}` field patterns), indicating the model echoed a deterministic template rather than writing finished prose.

The output jsonschema already constrains the top-level shape (object with string `speech` and object `intent`; `intent.kind` is an enum of the whitelist), and the semantic validators carry the per-kind payload logic the schema cannot express cleanly without a `oneOf` matrix. Each failure appends a concrete message and retries within `1 + max_retries`; the final fallback is the sentinel (D3). These are deliberately conservative shape checks, not quality scoring — the CJK check only requires *at least one* ideograph and the whitelist check only rejects unknown kinds, so legitimate speech is not penalized. The fidelity guarantee comes from the prompt instruction (D2), and the speech is never parsed back into state, so a slightly off-tone sentence must not trigger an unbounded retry storm.

### D5. `register_npc_dialogue()` wires hooks atomically and idempotently from the registration site

`register_npc_dialogue()` installs the output schema (via `schemas.registry.register_output_schema("npc_dialogue", NPC_DIALOGUE_OUTPUT_SCHEMA)`), all semantic validators, and the sentinel degrade fallback in one operation, and marks the layer registered only after every hook is installed. It is **atomic with rollback**: if any individual hook registration fails mid-way, already-installed `npc_dialogue` hooks are removed so the layer is never left partially registered. Idempotence is defined precisely: a **second call is a no-op** that keeps the first registration and swallows only this module's own duplicate-registration errors (`GuardrailRegistrationError` and `DuplicateSchemaError` for the `npc_dialogue` schema id) — it does not silently override an incompatible registration.

Production calls it once from `server/conf/at_server_startstop.py`'s `at_server_start()` hook (after `evennia._init()` has populated `evennia.logger`), inside a boot-tolerant wrapper identical in shape to `_register_narrator_layer` but also tolerant of a foreign leftover `npc_dialogue` output schema (which surfaces as `DuplicateSchemaError`, not `GuardrailRegistrationError`):

```python
def _register_npc_dialogue_layer():
    from evennia import logger
    from world.ai.guardrail import GuardrailRegistrationError
    from world.ai.npc_dialogue import register_npc_dialogue
    from world.ai.schemas.registry import DuplicateSchemaError

    try:
        register_npc_dialogue()
    except (GuardrailRegistrationError, DuplicateSchemaError) as exc:
        logger.log_warn(f"npc_dialogue registration skipped at server start: {exc}")
```

This is the same post-`evennia._init()` seam change 18 uses: `world.ai.guardrail` performs `from evennia import logger` at import time, so registering during settings load would permanently bind `logger` to `None` and break every degrade path. Tests that reset the shared registries between cases re-call `register_npc_dialogue` in `setUp`; because the D3 gate reads the actual registry, a reset automatically forces the next call through the not-registered path.

### D6. The deterministic intent applier verifies, then applies, through existing APIs only

`world/rules/npc_intents.py` owns `apply_npc_intent(npc, player, intent) -> IntentOutcome` (`IntentOutcome` is a frozen dataclass with `applied: bool` and `reason: str | None`). It performs **verification and application only through existing deterministic APIs**; it never constructs or mutates state itself:

- `none` → applied no-op.
- `request_guild_exam` → validates `target_rank` present, then calls change 16's `start_guild_exam(actor=player, examiner=npc, target_rank, requested_by="npc_intent")`. That API rechecks co-location, the GuildExaminer component and branch, the exact next rank, true cumulative merit, and absence of active combat/exam, and is the sole examiner trigger. Any `GuildExamError` is caught and mapped to `IntentOutcome(applied=False, reason=...)` — the intent is discarded and the speech kept. The AI cannot choose examiner stats, waive a gate, promote the player, or start combat directly. The actor/examiner order is explicit: the player is always the `PlayerCharacter` actor and the NPC is always the examiner, matching the real signature.
- `give_item` / `take_item` → verifies the giver's `db.inventory` actually holds `item_key` × `qty` **before constructing the removal tuple** (so a pathological `qty` can never allocate an unbounded tuple), then transfers through a **dedicated transfer primitive** in `world/rules/npc_intents.py` rather than two independent `apply_inventory_plan` calls. The primitive precomputes both plans (`plan_inventory_delta(giver, removals=...)` and `plan_inventory_delta(receiver, additions=...)`), snapshots **both** entities' affected surfaces (inventory, quest log, and any ACQUIRE pin state, mirroring the snapshot/restore helpers `apply_inventory_plan` already uses), then applies both plans inside one outer `transaction.atomic()`. Because Django nested `atomic()` joins the outer transaction, a second-side failure rolls the first side's database write back with it; the explicit dual-side snapshot restore then rewinds **both** in-process Evennia attribute caches, so no partially-committed transfer is observable in the DB or in-process. A deliberate-failure integration test (a second-side apply or ACQUIRE-delta failure) asserts both sides' database and in-process state return to pre-transfer. Missing holdings or quantity → `IntentOutcome(applied=False, ...)`, no inventory change.
- `offer_quest` / `adjust_relation` / `reveal_lore` → whitelisted in the schema but **rejected** by the applier behind forward-declared seams: `apply_npc_intent` documents each as "no deterministic capability surface yet" and returns `applied=False`. The quest-issuer capability (`QuestGiver` component), the relations handler, and the lore-reveal API are all unbuilt; a deliberate rejection with a guarded test is preferable to a fake implementation (AGENTS.md's forward-declared-seam rule). Whitelisting in the schema means the *shape* is accepted for extraction — it does not imply executability, and the spec states this explicitly.
- Unknown kinds → rejected defensively (schema/semantic validation should already have stopped them).

`world/rules/npc_intents.py` may import `world.rules.guild_exams`, `world.rules.equipment`, `django.db.transaction`, and read entity attributes — it is a deterministic package and the sole writer of any state this change causes, so the single-writer invariant is preserved. It never imports `world.ai`.

### D7. `LLMNPC(NPC)` is the consumable entity seam in `typeclasses/`, with required client injection

`typeclasses/npcs.py` gains `LLMNPC(NPC)`, porting the contrib `LLMNPC`'s behaviors (per-character `chat_memory` with a `max_chat_memory_size` window, `thinking_timeout`/`thinking_messages` feedback) as project code rather than subclassing the contrib — the design §4 amendment from the Context section. The memory is keyed by the character's **persistent primary key** (serialized), not the display name, so two same-named characters can never share or read each other's private conversation history. **The class is declared with `__applabel__ = "typeclasses"`** (the metaclass's documented per-class app-label seam) so its Django proxy model registers under the installed `evennia.typeclasses` app instead of `objects`; without it, the same-named contrib model (`evennia.contrib.rpg.llm.llm_npc.LLMNPC`, eagerly imported by `evennia.contrib.rpg.llm` whenever `world.ai.client` is imported in the same process) and this class collide in Django's app registry with `Conflicting 'llmnpc' models`. It exposes:

```python
def at_talked_to(self, speech, character, client, *, reactor=None):
    # 1. append the player's line to per-character memory (trim to window)
    # 2. build npc_context (name/desc/location) and player_context (identity + disguised_stats)
    # 3. yield world.ai.npc_dialogue.generate_npc_reply(client, ...)
    # 4. reply is None -> greeting_for(self) or silence
    # 5. reply -> present speech, append NPC line to memory, route intent via
    #    world.rules.npc_intents.apply_npc_intent(self, character, reply.intent)
```

**The client is a required injected argument.** `at_talked_to(speech, character, client)` has no `client=None` fallback and the typeclass never constructs `OpenAICompatClient`, lazily or otherwise. This keeps the "client is injected; transport ownership stays in `world/ai/client.py`" rule uniformly true across every generative seam and gives change 23d a single, unambiguous responsibility: its presentation composition root constructs the profile-driven client once and injects it into `at_talked_to`. Tests therefore always pass `FakeLLMClient`; a missing client surfaces as a named `NPCDialogueClientRequiredError` from the seam itself rather than an accidental live transport.

**Deferred imports are mandatory.** `typeclasses/npcs.py` MUST NOT import `world.ai.npc_dialogue`, `world.ai.client`, or any guardrail-dependent symbol at module scope. `world.ai.guardrail` performs `from evennia import logger` at import time, so any module-scope import chain that reaches it before `evennia._init()` permanently binds `logger` to `None` and breaks every degrade path — the same class of bug the narrator change documented for settings-load imports, but reachable here through typeclass discovery and early test imports, not just settings. The seam therefore performs function-local imports of `world.ai.npc_dialogue` and `world.rules.npc_intents` inside `at_talked_to`'s server-ready execution path. This also resolves the import cycle that module-scope imports would create (`typeclasses/npcs.py` → `world.rules.npc_intents` → `world.rules.guild_exams` → `typeclasses.npcs`). A subprocess regression test locks the ordering contract: the settings-load path stays clear of the guardrail pre-`_init()`, importing `typeclasses.npcs` pulls in no generative module, and a post-`_init()` guardrail import binds a real logger (see the pre-init-import note above).

**Thinking-state feedback has a verifiable contract.** Porting the contrib's thinking timer, the seam SHALL: send at most one thinking message to the current speaker only when the reply takes longer than `thinking_timeout`; cancel any pending timer on the terminal reply or degrade; and swallow the resulting `CancelledError` so no cancellation error leaks to the player. A deterministic-clock test asserts the one-message-then-cancel behavior and that a fast reply never emits a thinking message. The seam takes an optional keyword-only `reactor=None` argument (defaulting to the global reactor, imported lazily) so the thinking timer runs on `twisted.internet.task.Clock` in tests; the client remains the only required injected argument.

**Pre-`evennia._init()` import regression.** Importing `typeclasses.npcs` literally *before* `evennia._init()` is impossible today — Evennia's own `evennia.contrib.rpg.buffs` (pulled in by `typeclasses.entities`) defines bases against `evennia`'s pre-`_init` `None` globals — so the regression test instead proves the ordering contract that is implementable: in a fresh subprocess, the settings-load path (which runs before `_init()` in real startup) does not reach `world.ai.guardrail`, and importing `typeclasses.npcs` after `_init()` pulls neither `world.ai.guardrail` nor `world.rules.npc_intents` into `sys.modules` (the deferred-import rule), while a fresh `world.ai.guardrail` import binds a real logger. The clean greeting-or-silence degrade is locked by the in-process seam tests, which run with the guardrail's real logger.

`typeclasses/` is not a deterministic package and not under the `world/ai` transport scan, so importing `world.ai` and `world.rules` here is legal; the seam is what change 23d (and future command wiring) will call. The typeclass never touches `world/ai/` internals beyond the documented `generate_npc_reply`/`NPCDialogueReply | None` surface.

## Risks / Trade-offs

- [The guardrail's zero-arg registered fallback cannot know which NPC/player a failing call served] → D3's sentinel-then-map: the registered fallback returns an internal sentinel, `generate_npc_reply` maps it to the public `None` degraded outcome, and the typeclass maps `None` to that NPC's authored greeting or silence. The guardrail contract ("return the layer's registered fallback") is satisfied and the greeting lookup stays in the package that owns it.
- [`world/ai` cannot import `typeclasses`/`world.rules`, so it cannot read `disguised_stats` or the greeting table] → D2 takes `disguised_stats` as plain data from the caller and D3 leaves the greeting lookup to the caller; the generative layer stays free of entity and rules imports and the existing contract test passes unmodified.
- [Design §4 says subclass Evennia `LLMNPC`, which the transport contract and Django MRO forbid] → explicit amendment: generative logic in `world/ai/npc_dialogue.py`, entity typeclass in `typeclasses/npcs.py` porting chat-memory/thinking-state behaviors. Precedented by §4's own verified notes for `OrderedLevelTrait` and `PyramidMapProvider`.
- [`client=None` would crash inside `guarded_call`] → D1 makes the client a required keyword argument and rejects an explicit `None` with `NPCDialogueClientRequiredError` as the first statement; the missing-client path is tested at both the generative layer and the typeclass seam (D7).
- [A two-entity item transfer could leave a partial state if the second side fails] → D6's dedicated transfer primitive precomputes both plans, snapshots both entities' affected surfaces, applies inside one outer `transaction.atomic()`, and restores both in-process caches on any failure; a deliberate-failure integration test asserts both sides roll back in the DB and in-process.
- [The typeclass could silently construct its own live transport] → D7 makes the client a required injected argument with no lazy fallback; `typeclasses/` never imports `world.ai.client`, and the presentation composition root (change 23d) owns client construction and injection.
- [Early typeclass imports could break the guardrail's import-time logger] → D7 mandates function-local imports inside the server-ready call path and adds a pre-`evennia._init()` import + disabled-profile degrade regression test.
- [The model could emit an intent that changes the world illegally] → D4's whitelist + per-kind validators bound the output shape, and D6's applier re-verifies every intent against the deterministic world through `start_guild_exam`/inventory planning; illegal or unverifiable intent is discarded while the speech is kept. The AI never gains elevated authority.
- [`request_guild_exam` could be gamed] → D6 delegates entirely to `start_guild_exam`, which rechecks every gate regardless of `requested_by`; `requested_by="npc_intent"` is audit metadata only, and the actor/examiner order is explicit (`actor=player, examiner=npc`).
- [A long conversation could blow up the prompt] → D2 caps the memory window, per-field lengths, and total prompt size deterministically, with an explicit truncation marker; the memory window is consumed through a fixed-length deque so the cap applies before the input is materialized.
- [A disabled/offline LLM must not break play] → D3's `None` outcome maps to greeting-or-silence; the deterministic game loop never imports `world.ai` and is byte-identical, so offline playability holds by construction.
- [Duplicate registration could silently override hooks] → D5 defines idempotence narrowly: only this module's own re-registration is a no-op retaining the first registration; incompatible registrations surface the guardrail's error.
- [Rollback on a failed registration could remove own hooks that pre-existed the call] → `_uninstall_all_own_hooks` removes every own hook by identity, exactly like `register_narrator`; on a partial-failure rollback the layer is guaranteed to end unregistered (never half-registered), and the D3 gate fails loudly on use — the startup wrapper's skip is boot tolerance, not silent correctness loss.
- [Overlapping talks to one NPC could each emit a thinking message] → each `at_talked_to` schedules its own per-reply timer, mirroring the contrib and the serialized single-player command model (one command awaits before the next input is processed), so the "at most one thinking message" contract is enforced per reply and locked by the deterministic-clock test.
- [Registration order at server startup] → `register_npc_dialogue` runs from `at_server_start` after `evennia._init()` (so the guardrail's import-time logger bind is real), is idempotent, and is boot-tolerant to foreign leftover registrations; one startup integration test locks the seam.
- [The three forward-declared intents could be mistaken for shipped capabilities] → the delta spec whitelists them for the *schema* (shape accepted for extraction), while D6's applier and its tests assert they are rejected with `applied=False` and no state change, keeping the gap visible rather than faking it.

None.
