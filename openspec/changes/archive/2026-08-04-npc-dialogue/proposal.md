## Why

The change-16 milestone left the deterministic game fully playable offline, and change 17 delivered the generative foundation — `OpenAICompatClient`, per-layer `LLM_PROFILES` (including the `npc_dialogue` layer), the validation-retry-degrade guardrail, `FakeLLMClient`, and the schema registry seam. Change 18 built the Narrator, the first generative consumer. NPC dialogue is the second: design §7.4 fixes its contract — an LLM reply carrying `speech` plus a whitelisted `intent` that the deterministic engine verifies before it changes any state — and change 19 must ship that layer now so change 23d (webclient exploration menus) and the deterministic intent gates consume one guarded, degradable path instead of each re-inventing transport handling.

## What Changes

- Add `world/ai/npc_dialogue.py` with a guarded `generate_npc_reply(...) -> Deferred[NPCDialogueReply | None]` that runs the `npc_dialogue` layer's pipeline (design §7.5) and resolves to a frozen `NPCDialogueReply(speech: str, intent: dict)` on success, or to `None` — the single public degraded marker — when the layer is disabled, unreachable, or retry-exhausted. The client is a required injected argument (mirroring the guardrail's own callers); the caller maps `None` to the NPC's authored greeting or silence, so the game stays fully playable offline and no consumer crashes on a sentinel where a reply dict was promised.
- Add `build_npc_dialogue_prompt(...)` that serializes the NPC's identity (name, desc, location), the speaking player's identity and `disguised_stats`, and a bounded chat-memory window deterministically, instructing the model to reply in 正體中文 with a `{speech, intent}` object. Injecting `disguised_stats` makes a disguised elf genuinely read as weak to the NPC (the D2 narrative payoff for free), and the memory/prompt bounds keep pathological inputs from producing unbounded requests.
- Register the `npc_dialogue` layer's guardrail hooks: the `{speech, intent}` output jsonschema under the `npc_dialogue` schema id, semantic validators (speech non-empty/CJK/bounded, intent kind inside the seven-kind whitelist, per-kind payload shape — `request_guild_exam` carries exactly one payload field, `target_rank`), and a sentinel degrade fallback. `register_npc_dialogue(...)` wires all hooks atomically with rollback and is idempotent and boot-tolerant, exactly like `register_narrator`.
- Add `world/rules/npc_intents.py`, the deterministic intent verifier-and-applier: `apply_npc_intent(npc, player, intent)` validates the intent and applies it through existing deterministic APIs only. `request_guild_exam` delegates to change 16's `start_guild_exam(actor=player, examiner=npc, target_rank=..., requested_by="npc_intent")`, which rechecks co-location, GuildExaminer component and branch, exact next rank, true cumulative merit, and absence of active combat/exam — the AI gains no elevated authority. `give_item`/`take_item` verify the giver's holdings and transfer through a dedicated dual-snapshot primitive (both plans precomputed, both entities' inventory/quest surfaces snapshotted, one outer transaction, both caches restored on failure) so no partial transfer is ever observable. **Illegal or unverifiable intent is discarded while the speech is kept** — the NPC said something it could not do, but the world was not changed. `offer_quest`, `adjust_relation`, and `reveal_lore` are whitelisted in the schema (shape accepted for extraction) but have no deterministic capability surface yet, so they are rejected (intent discarded, speech kept) behind forward-declared seams.
- Extend `typeclasses/npcs.py` with an `LLMNPC(NPC)` entity typeclass carrying persistent per-character chat memory, a bounded thinking-state feedback contract, and an `at_talked_to(speech, character, client)` seam that builds the prompt, runs the guarded dialogue with a **required injected client** (the typeclass never constructs transport itself), maps the degraded outcome to the authored greeting or silence, and routes a verified intent to the deterministic applier. The seam imports `world.ai` and `world.rules` only inside the server-ready call path so early typeclass imports cannot break the guardrail's import-time logger.
- Keep the single-writer and transport boundaries intact: `world/ai/npc_dialogue.py` imports no state writer, no typeclass, and no live transport; it consumes the client through the injected protocol exactly like `narrator.py`, so `tests/test_ai_transport_contract.py` stays green with no edits. The entity typeclass lives in `typeclasses/` — not `world/ai/` — because `world/ai/` may not import the `evennia.contrib.rpg.llm` contrib (transport boundary) nor `typeclasses` (state writer), and this is a documented amendment to design §4's `ai/npc_dialogue.py` reuse row.
- Add no backward-compatibility adapter or persisted-data migration; the project is unreleased. NPC dialogue is delivered as a consumable seam; command and webclient presentation wiring belongs to change 23d, not this one.

## Capabilities

### New Capabilities

- `npc-dialogue`: The generative NPC reply layer — deterministic, bounded prompt construction injecting `disguised_stats`; a guarded, Deferred-returning reply entry point resolving to a `NPCDialogueReply | None` outcome; the seven-kind intent whitelist with per-kind payload validation; the deterministic intent verifier-and-applier routing `request_guild_exam` through `start_guild_exam(requested_by="npc_intent")` and item intents through an atomic dual-snapshot transfer; and degrade-to-greeting-or-silence so the game remains fully playable with the LLM offline.

### Modified Capabilities

- None. The `llm-profiles` spec already names `npc_dialogue` as one of the four layer keys, the `guardrail` spec already supports per-layer semantic-validator and degrade-fallback registration, and the `scripted-dialogue` spec governs authored `ScriptedDialogue`/`OnboardingGuide` hosts (unchanged; the new `LLMNPC` is a distinct dialogue path, not a modification of scripted hosts). The repository-wide transport-boundary contract (`tests/test_ai_transport_contract.py`) already scans every production module under `world/ai/` and will enforce the new module's compliance without modification.

## Impact

- Adds `world/ai/npc_dialogue.py` and package-local tests under `world/ai/tests/test_npc_dialogue.py`.
- Adds `world/rules/npc_intents.py` (deterministic intent verifier-and-applier) and package-local tests under `world/rules/tests/test_npc_intents.py`.
- Extends `typeclasses/npcs.py` with the `LLMNPC(NPC)` entity (chat memory, thinking state, `at_talked_to` seam) and adds tests under `typeclasses/tests/`.
- Adds `npc_dialogue`-layer hook registration (output schema, semantic validators, sentinel fallback) to `server/conf/at_server_startstop.py`'s `at_server_start()` hook — the earliest point guaranteed to run after `evennia._init()`, because `world.ai.guardrail` captures `evennia.logger` at import time (same seam change 18 uses).
- Consumes the change-17 `guardrail`, `profiles`, `schemas.descriptor`, and `schemas.registry` seams, and change 16's `start_guild_exam` and `world.rules.equipment` planning APIs; subclasses the project `NPC` typeclass (amending design §4's "subclass Evennia `LLMNPC`" row — the contrib class is a `DefaultCharacter` sibling that cannot merge with the `LivingEntity`-based `NPC`, and `world/ai/` may not import the contrib).
- No container, dependency, settings-schema, or persisted-data change; `LLM_PROFILES["npc_dialogue"]` already exists with the local-first default.
- Establishes the NPC dialogue seam consumed by change 23d (webclient exploration/dialogue menus) and by future command wiring; those consumers remain outside this change.
