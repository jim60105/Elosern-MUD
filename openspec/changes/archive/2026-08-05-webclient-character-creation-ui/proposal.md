## Why

A freshly registered account currently meets the game through a text-only `character` command wizard: the WebClient login shows the world introduction and the bare creation start screen, and completing creation requires typing `character preset <key>` or answering a long `character create` prompt sequence. Roadmap item 23g (`webclient-character-creation-ui`) is the last independent UI slice after the service menus: it is fully deterministic, needs no LLM or image service, depends only on the landed foundation plus the `login-creation-ux` and `onboarding-guide` changes, and gives the first graphical surface a proper preset/custom form that invokes the exact same all-or-nothing creation service as the command wizard.

## What Changes

- Add a read-only version-1 `creation` panel registered beside `status`, `context_actions`, `local_map`, and `services`. It is available only in `creation` mode and presents the pending character's server-persisted wizard draft plus the complete creation form derived entirely from immutable registries: preset cards (key, display name, race, race description, subrace, allocation emphasis, one-line background) and a custom-form descriptor (name field, bounded adult age/apparent-age fields, race options with descriptions, per-race subrace options, and per-race/subrace allocation axes with bounds and budget from `resolve_starting_profile`). The presenter never exposes persona/import-only fields merely because a character-card schema defines them, and a failure confined to the creation panel degrades only that panel.
- Add a server-owned creation wizard draft under `world/rules/creation_wizard.py` that persists the pending character's accepted values and stage through the deterministic core only, so the browser can reconnect at any saved stage and no client can hide a field, skip a step, or activate an incomplete character. Saving a preset or custom draft re-runs the existing public `preflight_character_creation` (adult gate, registry membership, name rules, allocation bounds and budget); activation clears the draft inside the all-or-nothing transaction.
- Register exactly four allowlisted creation adapters — `creation.preset` (exactly `preset_key`), `creation.custom` (exactly `display_name`, `age`, `apparent_age`, `race`, `subrace`, `allocations`), `creation.activate` (empty payload), and `creation.reset` (empty payload) — that resolve the owning account from the authenticated session's puppet, validate through the existing deterministic creation service, and never accept an actor/account/session/calculated-stat field. `creation.activate` runs the same `activate_player_character` all-or-nothing transaction the command uses, then the unchanged best-effort South Gate relocation and onboarding arrival, and publishes a full `exploration` snapshot so the creation dock hands off atomically.
- Add a keyboard-first creation dock to the action dock shown in `creation` mode: preset cards and a custom form with arrow-key list/button navigation, Tab/Shift+Tab field navigation, Enter submit, Escape pop, confirmation screens before activation and before the destructive custom reset, bounded integer allocation and adult inputs, field-associated validation messages announced through the live region, and disabled reasons that remain focusable. The dock owns the action dock exclusively in creation mode and unmounts synchronously when an `exploration` snapshot is adopted.
- Enforce the non-negotiable adult invariant at the server: both `age < 18` and `apparent_age < 18` are rejected by the deterministic creation service through `creation.custom` even when the browser's client-side constraints are disabled or bypassed. The panel advertises the 18 minimum; the adapter cannot be routed around it.
- Extend the Node gate, the managed Playwright suite, and deterministic Evennia fixtures with preset/custom/activation/reset success, rejection, stale, duplicate, tampered, confirmation, underage-bypass, reconnect-at-saved-stage, and mode-transition journeys.
- Add no backward-compatibility adapter or persisted-data migration; the project is unreleased and Telnet play remains unchanged.

## Capabilities

### New Capabilities

- `webclient-character-creation-ui`: The read-only version-1 `creation` panel payload (preset cards, custom-form descriptor, server-persisted wizard draft), the four exact allowlisted creation action adapters, the deterministic creation-wizard draft service, the keyboard creation dock and confirmation flows, the server-authoritative adult gate, and the Node/browser acceptance boundary.

### Modified Capabilities

- `webclient-action-dispatch`: The production registry contract changes from exactly the three combat plus seven service adapters to additionally require exactly the four creation adapters `creation.preset`, `creation.custom`, `creation.activate`, and `creation.reset`, each with its own exact validator and deterministic adapter.
- `player-character-creation`: The "Character creation offers preset and custom modes" requirement is amended to explicitly permit the deterministic core to persist a bounded, versioned `creation_draft` staging attribute on the pending character (server-owned, cleared by atomic activation) while keeping canonical identity attributes and the trait set untouched by rejected or cancelled drafts, so reconnect-at-saved-stage does not contradict the existing "invalid draft changes no character state" guarantee.

## Impact

- New files: `world/rules/creation_wizard.py` (server-owned draft + activation finalization), `world/rules/creation_messages.py` (stable rejection codes and Traditional Chinese text), `web/webclient/presentation/creation.py` (panel presenter + validator), `web/webclient/actions/creation_actions.py` (payload validators + adapters), a DOM-independent `creation_menu.js` form/preset model under `web/static/webclient/js/elosern/`, a `creation_dock.js` GoldenLayout plugin, and their tests.
- Edits to landed implementation files: `web/webclient/presentation/registry.py` (register the `creation` panel), `web/webclient/actions/registry.py` (register the four creation adapters), `web/static/webclient/js/elosern/protocol.js` (panel allowlist + `creation` validator + dual-parity constants), the action-dock JavaScript/CSS, and browser fixtures. `typeclasses/characters.py` gains one `creation_draft` AttributeProperty with its single-writer rule documented (all writes route through `world/rules/creation_wizard.py`); the `player-character-creation` main spec is amended to permit this staging attribute.
- Reuses the locked Playwright dependency, isolated browser harness, OOB epoch/revision protocol, immutable `PLAYER_PRESET_REGISTRY`/`RACE_REGISTRY`/`SUBRACE_REGISTRY`, `world.rules.character_creation` activation service, and `world.rules.onboarding` relocation/arrival; adds no runtime dependency, database migration, LLM call, image-service call, mobile scope, or backward-compatibility layer.
- `webclient-service-menus` (23e) already returns its unavailable form in creation mode; `webclient-exploration-menu` (23d) later re-homes the exploration dock that takes over after activation. This change ships only the creation-mode surface and the activation hand-off.
