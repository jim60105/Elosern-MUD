# Design

## Context

See proposal.md for scope and the eight-hour integration allocation. The source of truth is the whole approved escort design, including sections 2 and 10. Engine ownership and deterministic-before-generative implementation order remain unchanged. Upstream `quest-scene-encounters` artifacts are available; its implementation is an apply prerequisite, not a proposal prerequisite. No artifacts for dream dispatch are required.

Observed code stores roster IDs and one NPC back-reference; `_escort_ready()` reads protected IDs and room/HP presence. `bind_stage_runtime()` accepts only actual instance rooms for pinning. The service refuses requested escort classification before transport; ScenarioDirector semantic validation and deterministic compilation refuse ESCORT objectives; generated registration independently refuses compiled escorts. Quest state currently has three values and per-record reward claims cannot exclude two alternative record payouts. Upstream supplies durable exact role bindings, independently activated encounters, scoped issuer provisioning, retained actors and phase-aware conversations.

Main capabilities and requirement headings were read before drafting deltas. The downstream extension to proposed `quest-scene-encounters` adds requirements without changing its change directory. The lifecycle state's misleading three-state heading is explicitly renamed; implementation must remount its retired traceability ID using the equivalent post-delta tree. Existing constraints not amended here remain in force.

## Goals / Non-Goals

Provide one executable escort acceptance-to-movement-to-exclusive-result-to-payment cutover. Reuse current combat, possession, map position/traversal, private issuance, registry reward, narrative knowledge and presentation boundaries. Preserve real actor identity and state across release and reload.

Exclude dispatch requests/decision orchestration, production story content, autonomous searching, pathfinding, arbitrary predicate/action languages, another follow roster, a new control UI, retries, compatibility transforms, migrations and database-reset execution. Current schema initialization may declare outcome tables/constraints; deployment's fresh-database decision remains downstream.

## Decisions

### Canonical membership metadata, no consumer exceptions

Keep `player.db.party` as one ordered ID list and NPC back-reference as its owner. Add persistent party-owner metadata for general identity plus deduplicated temporary sources keyed by accepted record and protected package/role reference. Validate the full bidirectional binding and sources using the quest-owned read boundary. An effective source requires an active owned record retaining that exact protected identity. Treat invalid metadata as no membership; do not repair or adopt nearby actors in reads. Ordinary current construction defaults to general membership, including starting companion binding. There is no deployed-data adapter.

Party mutation owns roster, metadata and back-reference changes. General joining counts valid general sources and applies existing eligibility; temporary joining skips the quota count but checks ownership. Convert every reader/writer and consumer together, including safe readers, owner lookup, follow, combat/affiliation, possession gates, quest credit, affinity auto-leave, presentation and deletion hooks. Existing general invite/join callers remain normal defaults; escort acceptance gets a dedicated temporary-source party API rather than calling general join with caller exceptions.

Valid escort sources suppress affinity departure while preserving relationship writes. General dismissal can remove that source while an escort keeps the actor bound. Removing an escort reason uses abandonment, with existing mission choices identifying affected commissions; multiple reasons require a selection. Ordinary possessed manual dismissal retains handback-first behavior. Follow precedence suppresses routine schedule movement while sources remain. Release restores applicable behavior from current tick/location without replaying skipped movement or returning to the encounter.

Temporary actors enter combat and incoming targeting through the same safe member set and ordinary lawful policy. The current companion nonlethal knockout contract is preserved for both kinds. Death handling consumes actual lawful committed death, including hostile/environmental sources outside that ordinary knockout policy; no exception manufactures lethal damage to satisfy a test. Knockout alone never produces protected-death failure.

### Typed completion declarations and real physical identity

Extend existing immutable objective/payload definitions with one `completion` discriminator, protected package/role references, and discriminator-specific destination or meeting/relation fields. Destination uses current ANCHOR/GRID/BOUND_INSTANCE locators. Rendezvous has no destination and compares exact live roles at authoritative map positions. Use maps-owned ordinary room identity or wilderness provider plus coordinate identity, never room keys or recycled wilderness room objects. Typed relations are validated against published roles. No generated numeric mechanics, typeclass choice, or extra objective family is introduced.

Consume upstream `lookup_story_role` to resolve definitions and exact bindings; do not spawn protected clones. Acceptance checks each declared protected role at the actual interaction actor's location, using existing physical actor/original quest-owner mapping during possession. Meeting roles may remain unmaterialized at acceptance when independently eligible later; protected roles may not. Evaluation revalidates bound actor identity and availability every time. An unknown/missing protected role refuses acceptance. Missing/dead essential meeting roles produce explicit objective unavailability when their owning lifecycle declares that fact; a pending not-yet-eligible encounter is pending rather than fabricated removal.

Separate protected-role binding from destination materialization and instance pinning. Permanent rooms never enter `bind_stage_runtime`'s instance-only room parameter. Instance destination materialization retains existing eligibility and pins; rendezvous needs no invented destination. Protected membership survives intermediate stages only where the immutable definition explicitly retains that identity; obsolete stage pins still release.

### One atomic acceptance/release with session compensation

Extend existing `accept_quest` so every existing offer path dispatches to `accept_escort_commission` for an escort. No caller may create an unbound escort record directly. Under deterministic owner/group/actor locking, revalidate issuance scope, phase/capability, availability, group state and all protected actors; allocate monotonic acceptance sequence; write record, exact bindings, party reasons, dialogue phase and narrative acceptance through their owners in one outer transaction. Return the persisted bound record. Preserve ordinary hunt/site preflight behavior.

Terminal completion/failure/abandonment/invalidation calls `release_escort_bindings` for that exact record. Precompute remaining legitimate sources and affected pins. Call `release_for_party_change` only when actual removal is necessary. A retained general member or another valid temporary reason preserves unrelated possession. No actor deletion, persona reset, memory erasure or temporary-to-general conversion occurs.

Database rollback cannot undo puppet/session effects. Extend the existing possession compensation seams to capture session puppet and account grant, cmdsets, mirrors and relevant presentation sequencing before handback. Use verified existing transfer/recovery to restore the original session control on any later failure, together with Attribute/component/dialogue caches and process registration views. A refused handback aborts the entire transition; no successful terminal record can leave dangling control. Presentation and notifications use post-commit callbacks; durable acceptance/outcome identity is never callback-only.

### Indexed settled observations and consumed sources

Add owner/package/role/group reverse references on acceptance and published groups. Index published groups even with no accepted records so physical unaccepted reunion is observable. Maintain/reconstruct these references through publication, activation, acceptance, terminal transitions and reload; authoritative data revalidation guards stale entries. Per-role movement or living-state changes look up relevant bindings/groups without scanning all players/stories.

Wire successful Exit traversal, wilderness movement, direct NPC and possessed movement, follower completion, encounter activation, acceptance/binding and living-state boundaries into `evaluate_escort_event`. Consolidate final evaluation after applicable movement and followers settle. Preserve actual moved/bound protected identities for attribution. Encounter activation for the current location must settle before that final predicate pass. Upstream activation and movement observation use one stable authoritative source; intermediate receive/activation hooks collect affected identities without consuming final stage-transition eligibility. Standalone activation/acceptance invokes final evaluation inside its own transaction after bindings settle.

Persist consumed `(owner, record, source)` transition identity and `(owner, package, group)` resolution source through the existing deterministic persistence style, with database uniqueness. Only final settled evaluation consumes event transition eligibility. Repeating or restarting a source cannot advance the next stage. Do not invent a source from prose or accept arbitrary caller-supplied observation mappings. Source provenance is resolved through the owning movement/activation/binding/living-state event boundary.

### Explicit final-result arbitration precedes settlement

Extend upstream package planning data with separate commission IDs, definition/issuance references and optional exclusive group references. A group declares a concrete terminal result, role/relation references and the distinct alternatives it obsoletes; story thread membership alone carries no exclusion. Validate bounded references and closed result semantics at publication. Each record retains its own issuer/deadline/reward/protected bindings.

Persist unique owner/package/group unresolved/resolved state, resolution source, winner or explicit no-commission result and monotonic next acceptance sequence under the same deterministic lock. Use the supported quest-owned normalized persistence pattern introduced upstream; no list scan stands in for database uniqueness. Lock/revalidate group and all relevant records before reward-effect planning. Evaluate candidate stage eligibility from pre-event state and its consumed source identities; select terminally satisfying records attributable to the actual participating protected bindings, then order by acceptance sequence and stable record identity. For meeting-role movement or activation, the owner resolves indexed meeting/protected pair references to stationary protected participants in that actual event; physically satisfied unrelated alternatives are not attributed. Same-tick acceptances remain distinguishable. A physical final result with no active alternatives may commit an explicit no-commission result without payout or retroactive reward for terminal history. When active accepted alternatives exist but none is terminally eligible and attributable, return result_unsatisfied and keep the group unresolved. In particular, a source advancing an intermediate stage cannot trigger a no-winner fallback or evaluate the later stage, including on restart replay; a later distinct source can evaluate its then-current stage.

Commit winner completion, accepted-alternative `INVALIDATED` state with structured obsolete-outcome reason, closed unaccepted offers, exact source/pin release, narrative result/participant knowledge, phase revisions and automatic settlement together. Invalidation is terminal without penalty or payout; update strict serialization, every planner/terminal check, tracking, deadlines and detail/objective/log presentation. Completed/failed unrelated definitions retain existing retry rules; resolved group alternatives have no acceptance path.

The per-record ledger remains the exactly-once reward writer. Group arbitration adds cross-record eligibility before automatic planning or counter claim. Automatic winner reward commits in the result transaction; counter winner keeps a later claim through the current actual issuer gate. Private rewards stay merit-free and registry-derived. Existing item-reward ACQUIRE cascades and then-in-party affinity semantics remain. Intermediate stages never resolve the final group or pay its final reward. An unaccepted reunion writes participant facts/phases and closes offers without quest record, acceptance or claim.

### Named downstream contracts

These names define new public operations, not existing implementation claims. Export them from the deterministic quest-owned boundary; internal file organization follows current conventions. Inputs carry exact IDs/registered references and bounded capability/source tokens, never authoritative prose.

Consume upstream `publish_scene_package` for validated immutable definitions, `lookup_story_role` for exact binding/availability, `activate_scene_encounter` for independent role activation and actual authorized commission references, and `transition_story_dialogue` for participant-limited phase revisions. Keep their signatures/authority semantics intact; extend accepted payload fields and supported committed escort observations. This change owns real escort/reunion observations and releases their upstream forward guards after proof.

Later design 3 must preserve both encounter orders, use the complete extended payload, activate relevant roles before final movement-result observation, publish without autoaccepting, and distinguish publication from acceptance/completion/settlement. It can query explicit outcome status and named operation results; a textual quest proposal never proves execution. No dependency on its artifacts or database deployment boundary is introduced.

### Guard cutover is the final feature step

Keep service, semantic validator, compiler and registration rejections while building/proving deterministic owners with synthetic definitions/fixtures. Validated fixture construction may register immutable synthetic definitions through supported test-only setup, but may not monkeypatch guard results to claim publication coverage. After acceptance, real movement/combat/possession, result arbitration, payment and reload pass, replace blanket guards at all four boundaries with complete-contract validation. Add a full publication smoke through the actual service/schema/compiler/registration path. Existing unsupported templates keep named refusal; no general request context gains an invented role binding. No fallback template expansion or retry subsystem is required.

### Presentation and observability within existing surfaces

Extend version-2 party payload once in the unreleased server/client cutover, retaining current NPC fields and adding membership/commission references plus general quota usage. Update server and mirrored validators and existing drawer consumers together; display all effective rows without four-row slicing. Preserve input/layout and existing controls. Extend current version-2 quest_log rows with nullable bounded terminal_reason and abandon descriptor fields, accept invalidated in quest/service state validators, and show it in a fourth state tab inside the existing quest drawer. Disable tracking/payout for that state and show its deterministic reason. Private active escort abandonment uses the existing guild.quest_abandon action with its unchanged quest_id payload, a host-independent quest-log descriptor and two-step confirmation; the adapter revalidates owner/current record and invokes compensated quest abandonment. Ordinary guild counter business retains its host gates. Party dismissal selects affected existing mission records and uses those same descriptors; no new screen or action ID is added. Text and browser capabilities share owner/phase/group freshness. Refresh open mission/dialogue capabilities after committed source, phase or offer changes; stale choices reject. Update both command docs for changed invite/leave availability and source-aware abandonment.

Every changed join/release, progress, control handback, outcome/invalidation, payout and named failure boundary uses `world.observability`, stable English event names and available player/quest/issuer/package/group/role/NPC/room-or-position/tick/source context. Participant prose follows existing bounded context/transcript policy. Persistent narrative result identity and participant memories remain narrative-owned; global group state grants no uninformed NPC knowledge or hidden coordinate clue.

## Risks / Trade-offs

Cross-system cache/session compensation and event ordering are the dominant risks. One roster prevents divergent escort membership, while reverse references bound evaluation cost. Durable uniqueness plus deterministic locks prevent same-tick or restart double outcomes; the repository uses SQLite, so reuse its serialized write discipline rather than claim row locks alone solve concurrency. Current companion nonlethal behavior constrains legitimate death fixtures. Real hostile/environmental failure consumers must still be tested without weakening lawful combat rules.

The allocation assumes upstream role persistence/phase authorization is implemented before apply and existing movement/session/settlement seams can be reused. It authorizes no reduced acceptance or fake scaffold. Any upstream contract mismatch discovered during apply must be surfaced rather than solved with a compatibility shim.

## Verification and traceability plan

All fixtures are synthetic and fixed, with no live model/SD. Cover every approved section-9 criterion through owning behavior tests. For each MODIFIED requirement retain its canonical ID and review old assertions; for the explicit state-heading rename retire/remount the old ID. Generate new IDs from `tools.spec_traceability list` against the equivalent post-upstream/post-delta tree, never manually concatenate them. Include tests for all four rejection boundaries and the supported publication runtime smoke, not validator-only proof. Register new non-browser modules and browser methods in exact shard manifests. Local focused gates use current repository commands; full browser and evidence verification remain CI-owned. No implementation tests are run by proposal creation. Proposal validation is this change's own strict OpenSpec validation.
