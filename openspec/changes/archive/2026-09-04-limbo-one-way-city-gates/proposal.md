# Proposal: limbo-one-way-city-gates

## Why

The approved design (`docs/superpowers/specs/2026-09-04-onboarding-removal-one-way-limbo-design.md` §4) defines 虛境 (Limbo) as a **one-way threshold**: players leave it through a city gate and can never return. Today `sync_grid()` bridges the two directions — it creates both the forward 「南門」 exit and a persisted return exit 「離開王都」 (aliases 「回虛境」) from the South Gate back to 虛境 — which directly contradicts the one-way semantics. At the same time, future race-based starting cities require a multi-city-capable gate mechanism, so the bridge must become registry-driven rather than hard-coded to the single capital.

## What Changes

- **NEW** `world/maps/city_gates.py`: a frozen `CityGateDef` dataclass (`map_id`, `gate_xyz`, `exit_key`, `exit_aliases`) and a `MappingProxyType` `CITY_GATE_REGISTRY` carrying exactly one row today — `capital_altoria` (gate xyz `(2, 0, "capital_altoria")`, key 「南門」, aliases 「王都」/「城門」). The registry is the seam for future cities: adding a city means adding a registry row, no code change. Race-based gate routing is explicitly **not** implemented (other cities do not exist yet).
- **BREAKING** `bootstrap.sync_grid()` becomes forward-only and registry-driven: per registry row it `_ensure_exit(虛境→gate)` with the existing idempotent converge semantics (pre-existing exits get key/aliases rewritten in place); the `EXIT_TO_LIMBO` constant and its `_ensure_exit` call are **deleted**, and the `EXIT_TO_CITY` surface moves into the registry row so the registry is the sole authored source of gate exits.
- **BREAKING** New idempotent **pruning**: on every sync, `sync_grid()` deletes every persisted `Exit` object whose destination is the 虛境 room — declarative convergence of the synchronizer's own exit surface, symmetric to `_ensure_exit`, not a migration shim (the design doc §4 names the legacy 「離開王都」/「回虛境」 exits as dirty data this prunes). Each prune logs `bootstrap_grid_exit_pruned` via the observability facade (`from world.observability import log_info`).
- A registry row whose gate room is missing logs `log_warn` (`bootstrap_grid_gate_missing`, context carries `map_id`/`xyz`/`action`) and is skipped — other rows still converge, no raise (the current bootstrap degrade pattern).
- The one-way guarantee is **two-layer**, and this change implements **both** layers: layer 1 is forward-only creation plus pruning (primary); layer 2 is a NEW 虛境-entry hard gate. Verified against master, the gate the design doc originally described as pre-existing is a **gap** (the repo's `Room` is a bare `pass` class — the "existing hard gate" was upstream Evennia docs behavior, not this repo; the design doc §4 is amended accordingly). This change adds `LimboRoom` to `typeclasses/rooms.py`: its `at_pre_object_receive` aborts every character move into 虛境 for non-superusers with a zh-tw localized refusal (superusers bypass, per repo builder-tool convention), and `sync_limbo()` declaratively converges the 虛境 room onto that typeclass on every sync (in-place typeclass rewrite — same convergence philosophy as exit pruning, zero migration).
- Spec deltas: `grid-room-sync`, `limbo-room`, and `sample-city-altoria` lose their return-exit («離開王都») wording in favor of the forward-only registry bridge; the new `limbo-one-way-gates` capability carries the registry requirements.
- **HOME POLICY (new decision — `home` would otherwise strand players in 虛境).** `server/conf/settings.py` defines no `DEFAULT_HOME` override, so Evennia's default home is the creation location — for post-sibling characters that is the 虛境 room itself — and `CmdHome` (contract-tested at `commands/tests/test_localized.py:130-134`) would then teleport players into the room the layer-2 hard gate refuses to re-admit. Approved policy: **the first traversal of a registry city gate by a character whose `home` is the 虛境 room re-anchors `character.home` to the arrival gate room**; later traversals and later gates never overwrite an already-non-Limbo home, and `home` after the threshold lands the player in their start city, never 虛境. Implementation seam: the shared movement-completion boundary `after_successful_movement` (`typeclasses/exits.py`), rules-side helper in a NEW `world/rules/city_gates.py` (single-writer rule; see design D7). No command surface changes — `CmdHome` itself is untouched, so `docs/game/commands.md` / `docs/game/command-reference.md` need no edit.
- Tests in `world/maps/tests/` are extended/adjusted: forward-exit idempotent converge, seeded reverse exit pruned on next sync, 虛境 exits equal registry rows, warn+skip on a missing gate room, character entry into 虛境 refused through the real `move_to` seam (exit traversal and forced `move_to` alike), `sync_limbo()` typeclass convergence idempotency; new requirement ids get `@covers_requirement` anchors.

## Capabilities

### New Capabilities

- `limbo-one-way-gates`: the authored city-gate registry (`world/maps/city_gates.py`), sync-side forward-only gate convergence, idempotent pruning of every exit pointing into 虛境, per-row degrade on a missing gate room, the add-a-row-to-add-a-city extension rule, and the first-gate-traversal home re-anchor that keeps `home` out of the refused 虛境 room (design D7).

### Modified Capabilities

- `grid-room-sync`: the bridging-exit requirement drops the return 「離開王都」 exit and becomes "one forward exit per registry row + prune every 虛境-destination exit" (1 requirement).
- `limbo-room`: the bridge naming requirement keeps the forward 「南門」 zh-tw key/alias wording and loses the return-exit clause and its scenario; the `sync_limbo()` requirement additionally converges the 虛境 room's typeclass onto the hard-gate `LimboRoom` (2 requirements).
- `sample-city-altoria`: "exactly one bridging exit" becomes "exactly one **forward** bridging exit per registry row, and no city room leads back to 虛境" (1 requirement).

## Impact

- **New code**: `world/maps/city_gates.py` (registry module only — no framework) plus `world/rules/city_gates.py` (rules-side `reanchor_home_on_gate_arrival` writer — the home-policy seam, design D7). `LimboRoom` is a new typeclass in the existing `typeclasses/rooms.py` module, not a new module.
- **Modified code**: `world/maps/bootstrap.py` (import registry; delete `EXIT_TO_CITY`/`EXIT_TO_LIMBO` constants and the reverse `_ensure_exit` call; per-row gate ensure; prune pass; `sync_limbo()` typeclass convergence; two observability events). `typeclasses/rooms.py` gains the `LimboRoom` hard-gate typeclass (layer 2; amended design doc §4). `typeclasses/exits.py` gains the one-line `reanchor_home_on_gate_arrival` call inside `after_successful_movement` (home policy, D7) — the only behavioral touch to the shared movement boundary.
- **Observability**: new events `bootstrap_grid_exit_pruned` (`log_info`) and `bootstrap_grid_gate_missing` (`log_warn`, replacing the single `bootstrap_grid_south_gate_missing` site with a per-row warn); `tools/observability_lint check` violations must not grow.
- **Tests**: `world/maps/tests/test_bootstrap.py` and `test_limbo_room.py` adjusted for the forward-only bridge; new gate/prune tests; any new test module must sit in exactly one `.github/evennia-shards.json` shard (the `maps-webclient-imports-prompts-tests` shard already registers the `world.maps` package prefix).
- **Database effect**: legacy 「離開王都」/「回虛境」 exits in developer databases are deleted by the next `sync_grid()` — runtime convergence, zero migration scripts (unreleased project, clean cutover).
- **Sibling dependency / file ownership (declared)**: `remove-onboarding-tutorial` (birth in 虛境 + relocate deletion) touches **disjoint files**; this change may land before or after it. One behavioral note stated explicitly: while the old relocate step still moves fresh characters to the South Gate, pruning the 「回虛境」 exit changes nothing for the guard flow — the tutorial never used the return exit; after the sibling lands, the fresh character born in 虛境 leaves through the forward 「南門」 gate, and the D7 home re-anchor is what makes `home` land them in the city instead of 虛境. **Exclusive ownership**: `world/maps/bootstrap.py` and everything under `world/maps/tests/` are edited ONLY by this change; `server/conf/at_server_startstop.py` is edited ONLY by `remove-onboarding-tutorial`; `.github/evennia-shards.json` is edited ONLY by `remove-onboarding-tutorial` (this change extends the already-registered `world.maps` test modules in place — a new test module under `world/maps/tests/` would be the one exception and is deliberately avoided, see task 4.10). This change extends `typeclasses/exits.py` and `typeclasses/rooms.py`, which the sibling also touches (`exits.py`) or never touches (`rooms.py`): the `exits.py` hunks are additive and non-overlapping (sibling deletes the `observe_room_entry` call; this change adds the home re-anchor call). Integration tests asserting the FULL one-way flow (birth in 虛境 → gate traversal → `home`) are easiest to write post-c1 and are sequenced accordingly (task 4.11).
- **Explicitly not done** (design doc §10): 南門→wilderness gate, 虛境 slate teaching content, race→city selection.
