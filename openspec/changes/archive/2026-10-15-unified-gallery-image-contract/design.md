# Design

## Context

world/art/descriptors.py; web/webclient/presentation/gallery.py; protocol/panels/gallery.js and version tables; Vue gallery components/store/stories; lib/image-attempts.js, composables/useArtwork.js, components/ArtworkFailure.vue and ArtworkPreview.vue.

Observed current panel contracts are art v2, roster v2, gallery v2 and dream v2. The official catalog indexes external monster/preset/npc content, while figures/scenes/avatars/editors own separate loading flags. The approved design and proposal.md define the named slice; planned later versions are batch contracts, not existing implementation claims.

## Goals / Non-Goals

**Goals:** Deliver this complete independently testable production boundary with exact source ownership and objective acceptance.

**Non-Goals:** Gameplay, generation scheduling, new production commands, global cache/retry/store, telemetry transport, GM previews, compatibility/migrations and hot reload. Text clients/favicons/unrelated icons remain unchanged.

## Decisions

### Canonical interface owned by this change

Add `world/art/descriptors.py` as the single frozen descriptor/fact vocabulary and `web/webclient/presentation/artwork.py` as the single bounded wire serializer/validator. New active JS validation lives in `web/static/webclient/js/elosern/protocol/artwork.js`, imported by existing panel validators. These are production-used immediately by gallery v3, not a second business-data API.

The exact descriptor object is `{subject_id, revision, generation_subject, generation_state, attempts, terminal, retention_sources}`. `subject_id` is a nonempty stable bounded string (128 code points). `revision` is a 64-character lowercase SHA-256 digest of ordered source/fault facts, source versions, geometry, binding/access applicability and generation facts. `generation_subject` is the existing validated full generation key or null; `generation_state` is null or `missing|pending|done|failed`, with existing `in_progress` normalized to pending. It describes recorded generation independently of visible origin. Deliberately disabled/no-record state is factual missing/null; it cannot claim an active job or erase recorded failures.

`attempts` has at most 16 entries. An image entry is exactly `{type: "image", source_id, rank, resource}`. A fault entry is exactly `{type: "fault", source_id, rank, reason}` and never has a URL. A resource is exactly `{resource_id, version, url, origin, geometry}`. `resource_id`/`source_id` are bounded canonical identities (256 code points), `version` is a 64-character fingerprint/source digest, URL stays within existing same-origin and source-specific ceilings (generated gallery 129; official/general media 256), and origin is `runtime|official|bundled_official|silhouette`. `geometry` is exactly `{image_size, face_rect, stage, aspect_ratio}`, nullable as applicable to that resource; positive integer decoded size uses existing image resource limits, face/stage use existing finite validation, and scene resources have null face/stage. Preserve global safe-number, string/surrogate and 65,536-byte envelope limits. Do not bypass them to emit oversized filenames; emit a bounded `source_rejected` fault for an applicable unusable source.

`terminal` is null or exactly `{kind: "alpha_mask"|"scene_image", source_id, rank, resource}`. Figure/gallery preview policy permits alpha. Avatars and original editors consume the same descriptor but their load request permits no terminal image. Scenes permit only their declared scene terminal. Terminal resource identity/version deduplicates against attempts. Sources are admitted by the backend; no frontend demographics, filenames, room-key inference or job scheduling occurs.

Closed reasons are `generation_failed`, `generated_output_missing`, `source_unavailable`, `source_rejected`, `explicit_reference_missing`, `metadata_invalid`, `required_resource_missing`, `configuration_invalid`, `panel_unavailable`, `image_load_failed`, `image_decode_failed`. Backend emits only its applicable reasons; browser owns actual load/decode results. UI mapping lives in one shared module, renders restrained zh-TW category text and never displays raw roots, credentials, exceptions or prompts. Optional undeclared sources add nothing. Source-scoped catalog faults occur before the corresponding default/substitute candidate, not as a directory-wide taint.

The production-integrated loading-core dependency owns `lib/image-attempts.js` and `composables/useImageAttempts.js`. This change binds canonical panel descriptors through `composables/useArtwork.js`, without a second resource driver or old/new shape adapter. Public load result is `{subjectId, revision, phase, selected, reachedFaults, exhausted}`; selected contains the actual successful resource, stable source_id/rank and observed natural dimensions. Phases are loading/success/exhausted. Consumers may retain separate display content but cannot set load success or reset reachedFaults. Reached backend faults and browser faults deduplicate by source/reason; image attempts deduplicate by resource identity/version. The unchanged descriptor reuses its local results; subject changes dispose local success; revision changes create a fresh cursor/fault epoch but reuse already decoded successful identical resource_id/version, including geometry-only changes; unmount cancels listeners and temporary Image references. No global cache, timer retry or new telemetry transport.

### Wire cutover ownership

Gallery changes v2→v3 here, with exact card rows `{image_id,status,label,artwork,is_default,chips,requested_fields,binding_present,created_at}` and official rows `{identity,artwork,is_current,is_catalog_default}`. Preserve mutation action ids/parameters and truthful card/pending/failed statuses. All Gallery*.vue, store, fixtures, stories, active UMD/Node and Python readers ship on this one shape. Existing original editors change their reads to the exact candidate here; their independent editing lifecycle is removed by the explicitly dependent original-editors slice, not by an adapter accepting old fields.

Portrait cutover changes art v2→v3, roster v2→v3. Art portrait values are exactly `{artwork,context}`; roster `portrait` is the complete descriptor rather than a field subset. Art scene stays its existing shape until the scene owner changes art v3→v4. Portrait owner migrates every figure and avatar reader to the single canonical shape and shared loading; the later avatar change consolidates avatar presentation and grapheme policy, with no second wire transition. Party v2/exploration v4 keep their bounded portrait_ref syntax while removing real-URL eligibility gates and joining admitted descriptors coherently.

Scene cutover changes art v3→v4. Scene wrapper is exactly `{archetype,label,alt,artwork}`. Portrait vocabulary remains canonical. Its descriptor identity is logical-place identity and generation_subject stays the shared archetype key. Dream independently changes v2→v3 and replaces state.scene_art raw URL with the same descriptor. Full envelope/panel allowlists, split active validators, registry registration constants, Vue mirrors, protocol fixtures, worker-completion push and relevant parity tests change in each owning cutover. No old/new dual shape, aliases, re-exports, data migrations or unrelated protocol deletion.

### Stable ranks and authorized retention

Source order is independent of attempt-array index. Image/fault entries both carry source_id and rank. Scene ranks are room=10, generated=20, operator type=30, bundled type=40, terminal=100. Portrait ranks are selected bound card=10, personal official=20, record default=30, classic=40, official default=50, alpha=100. Exact gallery original/ruler requests rank 10; alpha terminal ranks 100. A metadata fault and its candidate share the same source_id/rank; adding faults never changes source priority. Canonical source ids are `scene.room:<room-art-key>`, `scene.generated:<generation-subject>`, `scene.operator:<scene-key>`, `scene.bundled:<scene-key>`, `scene.terminal:<terminal-key>`, and analogous `portrait.bound:<image-id>`, `portrait.personal:<official-identity>`, `portrait.default:<image-id>`, `portrait.classic:<generation-subject>`, `portrait.official:<kind>/<key>`, `portrait.alpha:<fallback-key>`. All use existing validated bounded keys; resource_id/version identifies bytes independently of source layer.

retention_sources is a bounded list (at most 16) of exact `{source_id, token}` entries, token being a 64-character SHA-256 of subject/generation subject, current authorized binding/source applicability and access policy, excluding geometry and pending/failed regeneration state. The backend includes a source only while its prior known-good output is still authorized/applicable and readable; requeue preserves old valid output today. It may include the generated source during pending/failed regeneration even when no current generated candidate exists. Remove its entry or change token on binding removal/change, subject/access revocation or prior output known missing/invalid. Job-failed alone does not invalidate an old readable generated output. Never authorize retention from a hash revision alone or a stale descriptor.

Retained content stores subject_id, generation_subject, source_id, token, stable rank, resource id/version and decoded pixels. After each new descriptor, retain only if subject and generation subject match, the new retention_sources explicitly includes matching source_id/token, and no local resource failure invalidated it. A newly successful current resource replaces retained display iff its rank is <= retained rank. Otherwise current attempt processing and reached failures continue while retained display stays. Fault positions/counts do not enter this comparison. Same resource id/version success reuses decoded pixels; new geometry applies immediately without refetch, loading flash or source crossfade. New resource bytes may crossfade under existing motion tokens. No retained authorization is invented by the client.

### Shared availability input

useArtwork accepts descriptor-or-null plus an explicit availability input `{state: "ready"|"expected_absent"|"failed", view_subject_id}`. A single `artworkAvailability` helper receives the committed panel and existing required-surface visibility/admission facts. A surface not required in the committed mode (creation art, closed dream/gallery), or an available panel with intentional no-admitted reference, is expected_absent. A required panel missing or available:false (presentation_unavailable or internal_presenter_error), or a dangling admitted ref, is failed. ready requires the canonical descriptor. Never synthesize pending from an unavailable panel.

On failed availability, the shared lifecycle invalidates current callbacks/original save eligibility, discards real retained pixels unless current authorization and same-place identity can be established from current committed inputs, and records local panel_unavailable. This batch chooses conservative scene handling: the common unavailable art panel supplies no trustworthy logical identity or retention authorization, so immediately discard all prior-scene pixels and show a safe non-image background plus availability indication, including first render or movement coinciding with failure. Avatar uses the currently supplied displayed name initial; figure uses identity text or a still-applicable admitted public alpha resource, never guessed source metadata; editors cannot save. No extra API or unvalidated synthetic descriptor is introduced. Recovery to a new ready input recomputes attempts normally. Integration tests cover available-success→unavailable, first-render failure and movement+unavailable, with expected creation/exclusion controls.

Backend tests use `uv run --locked --env-file=/tmp/mud-unified-image-tests.env evennia test --settings test_settings.py --keepdb ...`, with an env file containing MUD_TEST_SETTINGS=1. Pure modules use unittest without importing Evennia state. New non-browser modules have exactly one .github/evennia-shards.json owner and new browser methods exactly one .github/browser-shards.json owner. ### Concrete browser fixture ownership

Do not set an explicit environment override for normal absence. Configured-root fault journeys deliberately set ART_OFFICIAL_ROOT to an unavailable runtime child. The built-in root continues to actual repository files. For live state transitions, implement `web/browser_support/unified_image_transitions.py` plus a bounded test-only Command/CmdSet installed only by the browser seed/settings flag. ### Resource-version derivation and bounded identities

Snapshot-admitted operator/bundled/default resources use startup content fingerprints. Immutable gallery identities use a stable digest of their admitted immutable stored identity; replacement is a new card/identity, not mutation of its old bytes. Classic generated resources use a digest of validated output identity and successful generation token, not pending job status or stage geometry. Generated candidates whose path can be republished use a bounded `?v=<digest>` cache version on the same-origin art URL; the active canonical validators accept only this closed query form and existing URL/envelope ceilings, while media identity admission is unchanged. Do not hash whole image bytes or scan catalogs on each presentation. A new completed generation changes version; pending/failed regeneration does not authorize replacing retained pixels. Exact gallery subject_id is a bounded stable hash-based id plus image UUID, not concatenation that exceeds the 128-character ceiling. Resource/source ids remain within their declared bounds and invalid applicable fields become attributed source_rejected facts rather than an unvalidated URL.


## Risks / Trade-offs

- Cross-surface shape mismatch: every wire owner ships its serializers, active schema/version/validators and all production readers together. Internal loading/source prerequisites keep one current wire until its named cutover.
- Unsafe retention or hidden fault: stable layer ranks and explicit authorized retention tokens distinguish priority/regeneration from removal/access loss; availability failure is separate from expected absence.
- Asset rights/budget uncertainty: all real artwork production has a complete owning pack, including two terminal images; catalog assumes no uncertain promotion/reproduction branch.
- Shared files/manifests: obey Batch dependencies and serialize overlapping edits; unrelated asset bytes have disjoint ownership.

## Migration Plan

Apply only after listed prerequisites land. This pre-release project has no compatibility/data migrations. Keep the current single wire shape until its atomic owning serializer/client cutover; remove obsolete internal projections/readers in that owner, never aliases/re-exports. Each named slice delivers its tests/docs/runtime boundary within the itemized 6.5 hours. Rollback reverts the complete owning slice and consumers together. Planning does not apply or archive these artifacts.
