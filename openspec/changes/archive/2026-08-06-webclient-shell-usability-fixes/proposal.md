## Why

The version-1 desktop shell mounts and the OOB protocol works, but the surfaces a player actually touches are broken in four ways that make the WebClient effectively unplayable: the narrative log prints Evennia's ANSI→HTML markup as literal source text, every action-dock row is inert under the mouse, the minimap draws all of its nodes inside a 128×64 pixel box so the labels pile on top of each other and spill over the legend, and the command drawer throws focus at the action dock after every send so the player must click the field again before each command. All four are browser-side presentation defects in landed code; no server payload, adapter, or deterministic rule is implicated.

## What Changes

- **Render the narrative transport stream as markup instead of literal text.** Evennia's portal already converts ANSI to HTML with `parse_html` before the `text` message leaves the server: player-authored content is HTML-escaped there, and the remaining markup is a small closed grammar (`<span class="color-NNN bgcolor-NNN underline blink">`, optional truecolor `style`, `<br>`, and `<a>`). The shell currently drops that whole string into a text node, so players read `<span class="color-008">~</span>` instead of a map. Add a DOM-independent strict allowlist parser that tokenizes exactly that grammar and a renderer that builds the corresponding elements with `createElement`/`createTextNode` — never `innerHTML`, never `DOMParser`. Anything outside the allowlist (unknown tag, unknown class, `onclick`, any other attribute) is degraded to literal text rather than executed, so the shell's existing "no trusted HTML" contract is preserved by construction rather than by refusing to render at all.
- **Ship the ANSI/xterm-256 palette the shell deleted.** The project replaced Evennia's stock `webclient.css` with a 77-line file and dropped the 512 `.color-NNN`/`.bgcolor-NNN` rules with it, so even correctly built spans would render unstyled. Add a deterministically generated palette stylesheet with a minimum-contrast floor against the ink-night background, plus a repository test that regenerates it and compares byte-for-byte. Switch the narrative surface to a monospace-first font stack so the server's box/ASCII map art aligns.
- **Make every action-dock row activatable by pointer through the same gate as the keyboard.** No dock — exploration, services, creation, character, or combat — attaches a click handler to the buttons it renders; the entire graphical surface is keyboard-only and a mouse click is silently discarded. Add a shared dock surface helper that renders rows uniformly and installs exactly one delegated `click` listener on the stable `#action-dock` element, plus a router `focusItemByKey` + explicit pointer-sourced `confirm` so a click walks the identical path as Enter: disabled rows still only explain, in-flight and awaiting-revision submissions are still suppressed, and exactly one `ui_action` is still emitted. Rows adopt a real `listbox`/`option` composite-widget pattern (`tabindex="-1"` rows, a container tab stop, `aria-activedescendant`) so a focused button can never double-fire from the native Enter-to-click behavior, and a stale-row guard stops a second rapid activation of a *navigation* row — which pushes a menu frame instead of submitting, and is therefore not covered by the in-flight mutation lock — from double-pushing.
- **Render the router's current menu frame in every dock.** The combat dock renders only its five root actions; opening Skills, a target list, a shorthand choice, or the Forfeit confirmation pushes a router frame that has no DOM at all, so the player navigates blind. Pointer activation cannot be correct while a dock's rendered rows disagree with the router's current frame, so the shared helper makes "the rows on screen are exactly the current frame's items" a dock-wide invariant.
- **Route keydown through Evennia's plugin contract.** `elosern_ui` binds a raw `document` keydown listener instead of exposing `onKeydown`, so `plugin_handler` logs `NO plugin handled this Keydown` on every keystroke and the project's routing sits outside the documented dispatch order. Move the handler onto the plugin object and return `true` exactly when the router consumed the key, leaving Shift+Arrow history and the stock plugins their turn.
- **Keep drawer focus after an ordinary send.** Both send paths call `closeDrawer(true)`, which moves focus to `#action-dock` after every command; sending two commands in a row requires a mouse click in between. An ordinary text send now clears the field and keeps focus, so consecutive commands are typeable; Escape is the explicit, documented way back to the dock. A free-form dialogue send still returns focus to the dock, because there the drawer was borrowed by a dock action that has completed. Consolidate the two near-identical duplicated send implementations (`elosern_ui.sendDrawerText` and the drawer component's `sendCurrent`) into the single drawer-owned path they already race against, and release the exploration dock's pending free-form reference whenever the drawer closes without that dock's own send — today it is cleared only on a successful consume, so a cancelled dialogue silently converts the *next* unrelated command into NPC speech, which the new multi-command drawer session would turn from a rare surprise into a routine one.
- **Give the minimap a real layout.** The render model normalizes every node — including remembered nodes many cells away — into `x ∈ [-64,64] / y ∈ [-32,32]`, and the renderer places them at `left: x+64px / top: y+32px`, so the whole graph is crushed into 128×64 px while each Chinese room label is 60–90 px wide; the absolutely positioned nodes then escape the canvas (which reserves only `min-height: 3rem`) and overprint the legend. Replace the pixel normalization with a bounded integer lattice (`col`/`row` plus `cols`/`rows`) computed in the DOM-independent model, size the canvas from the lattice so the pane scrolls instead of overlapping, move remembered remote nodes out of the coordinate canvas into a bounded focusable list (their coordinates are meaningless relative to the local view and are exactly what distorts the normalization), and draw edges as an SVG line layer built with `createElementNS` instead of the current bounding-box `div` rectangles.
- No backward-compatibility shim, stored-data migration, or dual rendering mode ships: the project is unreleased, and the old text-node narrative, pixel-normalized map layout, and focus-stealing drawer are removed outright.

## Capabilities

### New Capabilities

- `webclient-narrative-markup`: The strict allowlist tokenizer and DOM builder for Evennia's ANSI→HTML narrative stream, the degradation rules for everything outside the allowlist, the generated ANSI/xterm-256 palette with its contrast floor, and the narrative typography that keeps server-rendered map art aligned.
- `webclient-pointer-activation`: The dock-wide contract that every action-dock surface renders exactly the keyboard router's current menu frame and that pointer activation traverses the identical focus, disabled-explanation, and submission-gating path as the keyboard, together with the composite-widget focus model, the single delegated listener on `#action-dock`, the plugin-contract keydown routing, and the pointer browser-acceptance journeys.

### Modified Capabilities

- `webclient-desktop-shell`: The narrative surface changes from "server text inserted as a text node" to "server markup rendered through the allowlist pipeline", with the theme requirement's text-only rule narrowed to structured panel labels (which stay text-only) so the narrative transport stream is an explicit, bounded exception. The keyboard-routing requirement additionally requires pointer parity and dispatch through the plugin `onKeydown` contract. The command-drawer requirement changes from "close on successful send and restore action-dock focus" to "clear and retain focus on an ordinary send, close and restore action-dock focus on Escape or a dock-borrowed send".
- `webclient-local-map`: The browser minimap's rendering contract changes from unspecified pixel placement to a bounded integer lattice with a canvas sized from that lattice, remembered remote nodes presented as a bounded focusable list outside the coordinate canvas, and edges drawn as connector lines; the `local_map` payload contract, the visibility states, the `未探索` rule, the remembered-node no-travel rule, and `explore.move` submission are all unchanged.
- `webclient-browser-verification`: The Playwright shell journey's "keyboard-only drawer open/send/close and focus restoration" changes to match the new drawer contract (focus retained after an ordinary send, restored on Escape) and gains the pointer-activation and narrative-markup coverage points.

- Because `covers_requirement` attaches only to a Python `test_*` while nearly all new behavior is verified in JavaScript, `web/webclient/tests/test_node_suite_evidence.py` gains one subprocess bridge test per new or modified JS-verified requirement, following the pattern it already uses for the protocol reducer and keyboard router. This is planned work, not an annotation pass.
- Edited implementation files: `web/static/webclient/js/elosern/keyboard_router.js` (`focusItemByKey`, pointer-sourced `confirm`, exported `confirm`), `web/static/webclient/js/elosern/local_map.js` (lattice model, remembered-node split), `web/static/webclient/js/plugins/goldenlayout.js` (narrative markup rendering, minimap lattice + SVG edges, drawer focus retention and single send path), `web/static/webclient/js/plugins/elosern_ui.js` (`onKeydown` plugin hook, drawer delegation, pointer wiring), `web/static/webclient/js/plugins/exploration_dock.js`, `services_dock.js`, `creation_dock.js`, `character_dock.js`, and `combat_dock.js` (adopt the shared row renderer; the combat dock additionally renders its submenu frames), `web/static/webclient/css/elosern.css` (dock rows, minimap lattice, narrative typography), and `web/templates/webclient/base.html` (load the two new modules and the palette).
- Existing Node contract tests are affected and updated in place: `ui_contract.test.js` keeps asserting no `innerHTML` in the shell plugins (the new pipeline satisfies it by construction) and gains assertions for the allowlist parser; `local_map.test.js` moves from pixel coordinates to the lattice model; `keyboard_router.test.js` gains the pointer-source cases.
- No change to any presenter, adapter, panel payload, validator, protocol version, action registry, Evennia setting, Python dependency, or deterministic game rule. No LLM, image-generation, or other network call is added. Telnet play is untouched.
