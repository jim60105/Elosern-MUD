## Context

See proposal.md for motivation. The approved `docs/superpowers/specs/2026-10-03-gallery-stage-transform-design.md` is authoritative; its D1–D7 are retained, not reopened. Backend is Evennia 6.1.0 / Python 3.13; Vue 3 is presentation-only. Gallery writes already converge in `world/art/gallery.py`, gallery actions share exact payload admission and three-panel publication, and `StageActor` delegates image rendering to `ReferenceArtwork`.

Existing visual references studied: `gallery.css` (ink/paper/gold controls, gold focus and selected states), `GalleryFaceRectModal.vue` (scrim, bounded two-column editor and local draft lifecycle), `GalleryDetailRail.vue` (card-only controls and cover crop), `ReferenceArtwork.vue` and `StageActor.vue` (bottom-contained imagery, grounded placeholders, contour shadows and source-only crossfade), `DrawerHeader.vue` (registry glyph, serif heading, hairline and 36px close), AVG redesign §5.4 A10/A11 and §8 portraits, and `docs/design/elosern-redesign2/gallery-storyboard.md`. ## Goals / Non-Goals

**Goals:** One card owns one atomic, finite, bounded presentation triple. Server storage/delivery remains separate from browser interpretation. Preview math matches live full-figure rendering and provides keyboard equivalents to dragging. All exact-field producers/validators deploy together.

**Non-Goals:** No automatic age/proportion inference, subject defaults, inheritance, rules/appraisal effects, SD prompt changes, image generation/cropping, face-rect changes, new assets/routes/packages, animation of transform edits, shadow adaptation, player commands, migrations or compatibility layers. Integer-copper money remains untouched. The existing inline SVG stage placeholder is unchanged and is never reused as the modal reference.

## Decisions

### D1 / D2 / D7: Card contract and sole writer

Add `stage` to `CARD_KEYS`, bringing the stored contract from eleven to twelve keys. `validate_stage` accepts an exact mapping `{scale, x, y}` with real finite values, rejecting bool, NaN, infinity, extra/missing keys and wrong types. Inclusive bounds are scale 0.2–2.0 and x/y −0.5–0.5. Return a new plain dict without adjusting accepted numbers. `validate_card(api_defaults=True)` may omit stage and fills `{scale: 1.0, x: 0.0, y: 0.0}`; strict `api_defaults=False` requires all twelve keys. Existing image-size provenance and face-rect rules remain intact.

Tolerant reads normalize only missing/malformed stored stage into identity on a copied entry before strict card validation; unrelated card corruption remains skipped and logged. The approved document calls this the `_consolidate` path; live code places entry validation in `cards_for` and `_update_card_field`, while `_consolidate` selects records. Apply identical stage-only normalization wherever those tolerant entry reads locate cards, so an old eleven-key card stays visible and editable. Do not persist defaults on a read or loosen the strict validator. This is tolerant read behavior, not migration or a second schema.

`set_stage(subject, image_id, stage) -> dict` validates before persistence and routes through `_update_card_field` under `gallery_lock`, replacing the entire triple. Preserve other card fields, order, default id, unrelated entries and files. Preserve the existing helper's `gallery_card_updated` event and additionally emit `log_info("gallery_stage_set", context={"subject": ..., "image_id": ..., "scale": ..., "x": ..., "y": ...})`. All mutations remain inside the gallery module.

### D4: Action and rejection discipline

`validate_gallery_stage_update_payload` uses `_payload` for exact `{subject_key, image_id, stage}`, shared subject grammar and canonical lowercase UUID, then calls `gallery_api.validate_stage` for early syntax rejection, mirroring face-rect admission without rewriting values. Register the seventh action and add `_mutate`'s `gallery.stage.update` branch calling `gallery_api.set_stage`. Add stage entries to success/rejection message maps and the existing error-code ladder; accepted saves report bounded zh-TW prose. Unknown card, unresolvable subject and record errors preserve existing localized rejection semantics. Success/domain rejection declares `AFFECTED_GALLERY_PANELS = ("gallery", "art", "roster")`, retains idempotency and emits exactly one adapter `gallery_action` info/warn event. No partial coordinate update is admitted.

### Wire lockstep and degradation

Gallery `CARD_FIELDS`, row builders and `validate_gallery` gain stage: real rows validate via the gallery API, pending/failed rows require null. Update the mirrored Node gallery validator and all row fixtures in the same change. Exactly one face chip stays required; no stage chip, filter or schema-version bump.

`world/art/presenter.py::_card_payload` carries validated stage. Defensive malformed stored input degrades to identity with one bounded `art_stage_invalid` warning carrying subject; a malformed value never fails payload construction. Classic done-record/fallback and scene asset branches carry identity; placeholders carry `None`. Keep the dedicated defensive presenter branch even though the normal tolerant gallery read already supplies valid stage.

Update Python `web/webclient/presentation/art.py` exact portrait/scene shapes, dependency-free `web/static/webclient/js/elosern/protocol/panels/art.js` `requireExactFields` and stage/dialogue actor portrait production in lockstep. Dialogue currently references art catalog portraits via `host.portrait_ref`, rather than embedding a separate bitmap contract: thread stage through that resolved catalog path without inventing a new host field. Audit roster exact portrait validators/producers because the player actor and drawer also consume roster portraits; shared art validation must accept stage, and any duplicated exact shape must change simultaneously. Scene rendering does not interpret stage. Fixtures and parity snapshots must include the new field throughout.

### D3: One rendering seam, two separate modes

In `ReferenceArtwork` stage mode bind `--stage-scale`, `--stage-x`, `--stage-y` to portrait.stage with null/missing identity defense. Keep a full-frame img box (`width/height: 100%`) with contain/bottom positioning, so percentage translation refers to frame width/height rather than the visible alpha silhouette. Apply exactly:

```css
transform: translate(calc(var(--stage-x) * 100%), calc(var(--stage-y) * 100%)) scale(var(--stage-scale));
transform-origin: 50% 100%;
```

Translation is independent of scale; positive y is down. Bottom-center origin preserves the feet anchor at y=0. The ground ellipse remains at the frame anchor; the image's existing drop shadow follows the image transform. Preserve stage overflow-visible, including a scale-2 figure extending outside its box. Do not transition transform, add stage to `StageActor`'s `portraitKey`, or restart crossfade for same-URL stage changes. Existing combat gestures stay on the outer actor wrapper. Switch only the drawer full-figure art slot to stage mode; gallery/detail thumbnails, roster avatars and party strip keep their `faceObjectPosition` cover path.

### D4 / D5 / D6: Local editor geometry and lifecycle

`GalleryStageTransformModal.vue` mirrors face-modal props `card`, `disabled`, `rejected` and events `close`, `submit`, `log`. Initialize a copied local triple. Left is one fixed 3:4 stage frame; the current card.url uses the same full-frame contain/bottom transform. Right has paired range/number controls 比例 (0.2–2.0), 水平 and 垂直 (−0.5–0.5), all step 0.01. `clampStage`, `moveStage`, `editStageField` live in pure `stage-transform-edit.js`; handle transient invalid numeric input without emitting non-finite drafts. Drag captures one pointer on the preview frame, uses pointer deltas divided by measured frame width/height, clamps offsets, preserves scale and ends on pointerup/cancel/lost capture. Use `touch-action: none`; neither drag nor range input sends traffic. 重設 resets locally to identity; save is still required.

The adult reference is an independent element whose displayed box fits the asset's 9:16 ratio inside the 3:4 frame (75% of frame width at full frame height). CSS mask and `-webkit-mask` use `/art/defaults/man.webp`, contain, bottom center, no repeat; fill is exactly #17191f. Its own `translateX(-50%)` moves half that element's displayed width (about 37.5% of frame width), not half the frame. Identity scale stays 1.0, independent of editable values. Bottom anchors coincide. No stroke, chest text or ground ellipse; `aria-hidden`, noninteractive. Use the committed alpha asset and existing /art route only.

Save is gated on current image loaded and not disabled. Load failure keeps the adult reference plus a truthful error line and prevents save. Save emits once `{stage: {...}}`; `GalleryPanel.send('gallery.stage.update', $event)` adds the committed subject/card identity. `GalleryDetailRail` emits `stage` from 比例調整; panel uses `openEditor('stage')`. Reuse existing connected/locked/one-in-flight and request/result/revision correlation unchanged: close only after own successful result and its presentation revision; rejection preserves values and 查看伺服器訊息. Non-card rows cannot open/send this mutation, and subject change/card disappearance/unavailable panel invalidates the draft.

### Dedicated visual-craft pass

**Surface and rhythm.** Keep the face-modal bounded scrim/two-column structure, not a new fullscreen gallery or generic white form. Reuse `DrawerHeader` presentation for the gallery registry glyph, serif 比例調整 heading, restrained subtitle and scaled 36px close control, while the modal owns its focus trap. Opaque panel gradient #1a1c24 → #0b1017, gold edge #d4b979 and subdued dividing hairlines #bda66b55 tie it to gallery chrome. Use existing `--gold-*`, `--paper-*`, `--ink-*`, `--f-serif`/display, `--f-sans`, `--f-num`, `--text-*`, radius and focus tokens. All fixed geometry uses `calc(... * var(--ui-scale))`: 24px body inset, 28px column gutter, 18px between instrument groups and 10px within label/value rows. Header and footer remain visually distinct from the only body scroll region. At the face-modal 800px breakpoint stack preview above controls; retain 3:4 ratio, bounded viewport height and no horizontal overflow.

**Cinematic diorama.** Recess the preview on near-black stage ink with a subtle radial lift behind the subject and a faint gold horizontal floor hairline at the bottom anchor; the floor is decorative, not an extra reference ellipse. The adult mask sits behind the current figure, fill #17191f at opacity 1, its low contrast supplied by its fill against the background rather than a bright stroke or wash. The current card stays at normal opacity in the foreground with its existing contour shadow. Leave the adult reference/overflow visible within the preview well's breathing room; a scale-2 test must not silently introduce a new figure crop. Plain paper-muted text outside the bitmap names the comparison and drag affordance, never text on the silhouette. The subject remains the visual focus even when the reference is taller.

**Instrument-dial controls.** Each axis is a compact ink instrument plate, divided by a fine gold hairline: serif label above a thin gold range track, quiet endpoint/default ticks and an aligned numeric readout. Numeric values use tabular lining numerals (`--f-num`), consistent field widths and visible signs on offsets; supplementary readouts show scale × and offset frame percentages while number boxes retain the exact stored fractions. Identity markers are scale 1.00 and x/y 0.00; do not add selectable presets or new mutations. Gold thumb/edge emphasis is reserved for hover, active and visible focus; reset is secondary and 儲存調整 uses existing `gallery-primary` treatment. Native range/number semantics remain intact. Existing `aria-pressed` selected controls retain gold selection styling; this editor does not invent a toggle group.

**Complete states.** Idle shows the live subject and all three values. Hover/drag emphasizes the active instrument with gold, without changing the static adult. Focus uses the established focus ring, not only a color shift. Loading displays 「圖片載入中，暫時無法儲存。」 with stable layout and save disabled. Image failure displays 「圖片載入失敗，無法儲存調整。」 and reference only, with seal-red confined to the error line. Action pending retains the draft/preview, disables inputs, drag, reset and save, and shows textual saving feedback. Rejected keeps the same triple with role=status feedback and the existing log link; never overwrite it with the committed old value. Disconnected/locked uses the same disabled contract and existing connection feedback; no new retry machinery. Cancel/Escape/scrim close discards without submission. Use the explanatory prose 「僅影響舞臺與全身呈現，不會變更頭像裁切。儲存的只有數值，不會產生新圖片。」

**Access and motion.** `role=dialog`, `aria-modal`, title association, explicit labels and described bounds for each pair; number inputs are the keyboard alternative to pointer drag. Initial focus is the header close control; tab order is close → scale range/number → horizontal range/number → vertical range/number → reset → rejection log link when present → cancel → save. ## Risks / Trade-offs

- Exact-field drift breaks snapshots: update all gallery/art/roster/actor producers, Python and Node validators and fixtures in the same deployable, not a staged protocol migration.
- Strict reads would hide old cards: stage-only tolerant normalization must precede strict validation in both reads and writer lookup; do not normalize unrelated corruption.
- CSS percentage offsets depend on the element box: use a full-frame subject img, but a contained-width adult mask element for the adult's own half-width displacement. Test with 9:16 media in a 3:4 frame.
- Shadow and overflow remain intentionally unchanged; an enlarged source background remains a supplied background, never browser-generated alpha.
- Scope stays one bounded engineer-day by reusing existing dispatch/focus/publication/chrome/test patterns. No compatibility strategy, alternate editor architecture or extra settings surface.
