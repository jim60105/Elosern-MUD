## Post-implementation review (rubber-duck, dispositions)

- **Fixed (blocking): a stale stored rectangle locked the player out of every later stage-only edit.** `_merge_official_geometry` re-validated an OMITTED (stored) rectangle against the image's current decoded dimensions, so after an artwork update replaced the bytes every `gallery.official.geometry.set` that carried only `stage` — i.e. every 比例調整 save from the shipped surface — raised and returned the generic `gallery_rejected` with zero write, contradicting the change's own update tolerance. Only a SENT component is validated against the image now; a stored omitted component is carried through verbatim (the writer validates its shape/bounds and the payload boundary degrades a stale rectangle at render time). Regression test: `OfficialPreferenceActionTests.test_a_stale_stored_rectangle_never_blocks_a_later_stage_edit` (4×4 rectangle stored, bytes replaced with 768×1024, then a stage-only set succeeds and the stale rectangle is retained).
- **Fixed (major): an untouched official save could silently overwrite the player's own override.** The pinned official row carries only the catalog rectangle and no stage, so the shared editors are seeded from those facts and cannot display a stored override; a no-edit 儲存 therefore destinated a stored override with the seed value. `GalleryPanel.vue::submitOfficialGeometry` now refuses to dispatch a component identical to its seed (the face rectangle as committed, the identity stage), so only a real edit crosses the wire and 清除個人調整 is the truthful way to drop an override the editors cannot show. Vitest: `never dispatches an untouched official geometry save` plus the two editors now edited before saving. Residual, recorded as WAIVED-WITH-REASON: the editors still cannot DISPLAY a stored override, because the wire row's exact five-key shape is fixed by the `webclient-gallery-panel` delta (adding the effective geometry would need a wire/spec change well beyond this task); the component not edited is never touched, so the residual effect is a missed display, never data loss. The stage modal's 重設 followed by 儲存 is a no-op for a stored stage override (identity is the seed), so 清除個人調整 is the documented reset path.
- **Fixed (minor): the presenter comment claimed one preference read per presentation.** A selection presentation performs two tolerant reads (chain step 4 + the payload's override read), so corrupt stored state is reported once PER READ — the same discipline the tolerant card read follows. The comment now states that; the behaviour was left as-is (per-read reporting matches the shipped `gallery_card_invalid` precedent, and process-global dedupe would be new state this change does not need).
- **Fixed (minor): the clear adapters reported a change for a no-op clear.** A clear of an ABSENT preference is a legal no-op, so its success message now states the resulting state (「目前沒有官方圖片選取。」/「這張官方圖片沒有個人調整。」) while the stable code stays the same; a clear after a real write still claims the change. Test: `test_clearing_an_absent_preference_reports_the_state_it_leaves`.
- **Rejected (minor): delete `resolve_card` as a test-only shim.** It remains the chain module's documented card-only entry point and the oracle the shipped chain suite (twenty call sites) asserts against, and `resolve_display`'s card outcome is pinned equal to it by `test_resolve_card_is_the_card_only_projection`, so the projection cannot drift; the delta text names no function, and migrating twenty shipped assertions for no behaviour change would risk the chain regression net more than the dead-looking surface is worth.
