# Design

## Context

Observed shape.py has only KeywordResponse(keyword,response) and DialogueDefinition(greeting,responses), both frozen. Lore registry must never import rules. This change supplies a complete pure data API and validators without switching live tables; runtime cutover is the next change.

## Goals / Non-Goals

**Goals:** Immutable reusable scenes and complete typed topic declarations. Deliver this runnable slice and its acceptance within one engineer-day.

**Non-Goals:** Unowned runtime/content work, compatibility migrations, new game effects and per-line server stepping.

## Decisions

## Shared contract v2 (proposed APIs, authoritative for this batch)

These are proposed interfaces, not claims about current implementation. Later designs reference this section and implement only their named fields. Static dialogue is a dialogue-specific YAML exception to architecture D9. Lore definitions remain immutable/read-only; world/rules owns dialogue/session/effects, world/narrative owns reading records, and world/quests owns generated package publication and phase authority. Generated scenes share every selection, condition, disclosure, playback and reading contract below. Only unconstrained freeform replies and deterministic service/opening lines keep native line delivery. No executable scripts, per-line server cursor, new quest effects, compatibility adapter or data migration.

### Immutable declarations

Add `world/lore/scenes.py` with frozen `Speech(speaker: Literal["actor","host"], text: str)`, `Narration(text: str)`, `Scene(scene_id: str, revision: str, lines: tuple[Speech | Narration, ...])`. Static scene IDs match `[a-z][a-z0-9_.-]{0,95}`. Generated scene IDs use the namespaced codec below; never apply the static pattern/96-character bound to them. Revisions are explicit nonempty ASCII tokens <=32. Lines are 1..2000 code points and scenes 1..32 lines / <=16000 total code points. All static and generated formal fallbacks/variants begin with a complete actor Speech; narration and consecutive same-speaker lines are legal thereafter. Opening/guild dynamic service scenes need not begin with actor. No interpolation, executable callbacks, embedded HTML, or choices inside a scene. Text is plain data; existing trusted text-output escaping rules still apply to editable greetings.

In `world/lore/dialogue/shape.py`, add frozen `SceneVariant(variant_id, priority: int, when: Condition, scene: Scene)` and `AuthoredTopic(topic_id, keyword, label, fallback: Scene, variants=(), requires=None, unavailable="hidden", refusal=None, predecessors=(), disclosure="qualified")`; `AuthoredDialogue(greeting: str | None, topics: tuple[AuthoredTopic,...])`. These common names cover static/generated definitions. Static topic identity is `<existing dialogue_key>.<ASCII suffix>`, <=96 chars, independent of labels/tone/revision. Existing topic_01..topic_04 identities survive filename/prose changes. Generated IDs use the codec below. Predecessors are IDs in the same static definition or generated phase; reject dangling/cross-phase references/cycles. `disclosure` is qualified or pure_chain. Pure chains require predecessors, no requires/effects including affinity, and public information only; never include qualified descendants in public bundles. Highest unique integer priority selects a complete variant, otherwise unconditional fallback. Variants never alter effects/reading identity. Visible lock requires refusal. Hidden topics may retain a safe operational refusal for post-qualification domain failure; hidden identity/body/refusal never projects while ineligible. Formal topic count <=16 for either source, all scroll-reachable.

### Primitive schema and provider boundary

Add `world/lore/dialogue/codec.py::parse_dialogue(payload, *, identity, references) -> AuthoredDialogue`, `validate_dialogue(definition, *, identity, references) -> AuthoredDialogue`, and pure `dialogue_payload_schema(*, identity_kind: Literal["static","generated_local"]) -> dict`. The schema factory composes one common structure, varying only the ID field grammar/local normalization contract; packages.py reuses its scene/topic fragments. Parser/validator return deeply immutable declarations and import neither ORM nor rules writers. `identity` is frozen StaticDialogueIdentity(profile_key,dialogue_key) or GeneratedDialogueIdentity(package_id,role_id,phase_id). `references` is frozen `DialogueReferences`: a read-only mapping from each of the fixed families `profile`, `preset`, `daypart`, `race`, `social_identity`, `guild_rank`, `quest`, `item`, `skill`, `affinity_stage` to a read-only `{safe_key: public_label}` table, with `empty()`, `keys_for(family)`, `label(family, key)` and `child(family, table)` as its entire API; `child` returns a new frozen instance (no shared-mutable singleton) and a key in a family whose table is absent fails closed. Static profile membership belongs exclusively to the static provider; generated roles require no NpcProfile. Generated input local IDs normalize to full canonical IDs before immutable validation.

Static YAML root is exactly `{schema_version:1,greeting:string|null,topics:[...]}`; greeting <=2000 code points/8192 UTF-8 bytes. Generated phase greeting retains its existing 500-code-point cap. Each topic requires `topic_id,keyword,label,fallback`; optional fields/defaults match AuthoredTopic. Each scene is exactly `{scene_id,revision,lines}`; line forms are the wire forms below. Variant is exactly `{variant_id,priority,when,scene}`. Keywords/labels are nonempty <=32 code points; variant/generated local IDs match `[a-z][a-z0-9_]{0,31}`, <=8 variants/topic and <=16 predecessors. No unknown fields, duplicate topic/scene/variant IDs, bool-as-int, unsafe tags or executable values. Scene IDs are unique per source definition/phase. Every declaration uses JSON primitives before parsing.

Conditions use exact `kind` discriminators `all`, `any`, `race_is`, `social_identity_is`, `guild_rank_at_least`, `quest_is`, `affinity_at_least`, `carries`, `companion_present`, `time_period`, `skill_owned`, `exposure`; other field names match their frozen constructors. Reject extra fields. `CompanionPresent.source_kind` is `preset|profile|package_role`. For package_role, source_key is the role_id in the current authorized package, never a global NPC name. `QuestIs.definition_key` may resolve a canonical permitted quest or the current package's compiled definition. References outside that captured permission catalog fail publication. Phase fact conditions remain the existing separate deterministic phase-selection language, never merged into topic All/Any or supplied as player assertions.

Static provider `world/lore/dialogue/loader.py::load_dialogue_snapshot(content_dir, *, profiles, bindings, references)` scans sorted immediate `*.yaml` files, derives profile key from the stem, rejects symlinks/nonregular entries, and parses safe YAML with duplicate-key rejection, no custom tags/aliases/merge keys and one document. File <=262144 UTF-8 bytes. Missing shipped directory, unknown profile, duplicate binding, schema/reference error rejects the whole candidate. `bindings` derives from existing canonical profile/service metadata, including guild_staff -> altoria_guild_master. Profiles without a distinct existing service/dialogue alias use their own key as dialogue_key; adding a file for a registered profile never needs a new binding/file-list edit. Snapshot freezes every value and returns one MappingProxyType after all files pass. Runtime loads once at registry/startup initialization, migrates 25 old tables then deletes obsolete domain modules/imports. No hot reload/model calls; dbid/display-name filenames reject.

Runtime provider `world/rules/dialogue_sources.py::resolve_dialogue_source(context) -> ResolvedDialogueSource | None` dispatches from trusted host binding, never a client discriminator. Result is frozen `{identity,host_key,dialogue,phase_revision,effects}`. Static reads only the validated static snapshot. Generated reads published noncancelled immutable packages and current package_id+role_id binding/selected phase through world/quests; it never adds private rows to the global static registry or writes source files. Effects are a source-owner validated association keyed by stable topic ID, separate from common prose declarations. Generated-package integration owns replacing the old package provider. Every common consumer uses this result and never predicates shared features on static-registry membership.

### Stable generated identity and reading host key

Define `encode_parts(parts)` as unpadded URL-safe base64 of UTF-8 `json.dumps(parts, ensure_ascii=False, separators=(",", ":"))`, with no normalization or hashing. Generated topic ID is `"g:" + encode_parts([package_id,role_id,phase_id,local_topic_id])`; generated scene ID uses the same tuple with its local_scene_id. They occupy separate typed fields; uniqueness is checked within each field namespace. Full generated IDs are nonempty ASCII <=2048 bytes. Each package/role/phase component retains its current <=64 code-point bound; local IDs have the 32-character bound above. Decode, re-encode and exact-match the captured binding; alternate encodings, delimiter tricks and foreign package/role/phase IDs reject. Never truncate or apply the static lowercase/96-character pattern. Phase revision is separate and does not change topic identity; leaving and returning to the same phase retains its reading.

Stable `host_key` is `s:<NpcProfile.key>` for static owners or `"g:" + encode_parts([package_id,role_id])` for generated roles, ASCII <=768 bytes. World entity dbid remains host_id on the wire and in presence checks; it never determines generated reading identity. `DialogueContext`, server SceneDelivery and session gain server-only host_key and source identity; the generated source identity is exact `{package_id,role_id,phase_id}`. Wire delivery has no private package object or source payload. All topic/scene fields, predecessor lists, selection/completion receipts, narrative topic keys, Python panel/action validators, UMD misc.js validators, constants.js/core.js/store.js envelope checks, Vue view-model admission and completion action validators accept the source-aware ID union. Identity bytes count fully toward existing budgets; no identifier truncation or generic global string-limit relaxation.

`Condition` is the tagged frozen union owned by `world/lore/dialogue/conditions.py`: `All(children)`, `Any(children)`, `RaceIs(race_key)`, `SocialIdentityIs(identity_key)`, `GuildRankAtLeast(rank_key)`, `QuestIs(definition_key, state)`, `AffinityAtLeast(stage_key)`, `Carries(item_key, minimum=1)`, `CompanionPresent(source_kind, source_key)`, `TimePeriod(start_daypart, end_daypart)`, `SkillOwned(skill_key, min_proficiency=None)`, `Exposure(minimum=None, maximum=None)`. Groups have 1..16 children and maximum depth 4; at least one Exposure bound, canonical ordered inclusive comparison. Runtime evaluators arrive in physical/progression slices, with no placeholder evaluator. All declaration keys are validated against the canonical registry in the owning condition slice before shipped conditions use them.

### Context and selection

Add `world/rules/dialogue_context.py::resolve_dialogue_context(actor, host, *, session=None) -> DialogueContext(actor, owner, host, host_key, source_identity, context_id, phase_revision)`. The frozen `DialogueContext` dataclass carries exactly those seven fields: `host_key` follows the stable scheme above, `source_identity` is the same union as the session field below (`None`, `{profile_key,dialogue_key}`, or `{package_id,role_id,phase_id}`), and both are server-only and never serialized to the wire. Ordinary player owner=actor. Possession resolves owner through `world.rules.party_scope.resolve_commander(actor)` and validates `is_companion(actor, owner)`, authenticated driving session when supplied, mirrored possession, actor/host co-location, capability, host schedule and host!=actor. Do not trust a client owner/actor id. Guild/quests/reading and host.relations affinity use owner; race/social/skills/inventory/exposure use actor. Companion membership uses owner and presence uses actor.location. Session remains on the ACTING body's existing db.dialogue_session seam. Switching control invalidates that body's conversation instead of resuming it on another body; durable reading is owner-shared.

`world/rules/dialogue.py::select_authored_topic(actor, host, topic_id, *, selection_id, expected_context_id, session=None) -> SceneDelivery` is the sole static/generated formal/refusal selection path used by command and web adapter. Context, source binding, phase and eligibility are rechecked before effects. The existing web action `explore.talk_scripted` has exact composed payload `{npc_id,topic_id,context_id,selection_id}` for either source; remove the generated keyword payload at generated-package cutover. Text keyword lookup resolves a stable topic in the current source then invokes this function. `selection_id` is <=64 chars, derived from web request identity or fresh per text command. Duplicate same-context selection returns its committed delivery without effects; reuse for another topic rejects. Ordinary eligible informational selection may grant existing host-to-owner talk affinity under current caps. Effect-bearing generated topics invoke their existing deterministic story-effect owner without extra affinity, and only after qualification. Authority refusal delivers permitted refusal/rejection, with no protected formal success body, reading receipt or partial effect. LLM output can propose only the existing allowlisted offer_commission tied to the package's declared role commission; no new verbs, inferred rewards or state authority. Replay/completion apply no effects. Guild 回報 listing stays read-only and explicit turn-in remains in guild service.

### Delivery, replay and wire

Frozen `SceneDelivery(delivery_id, selection_id, context_id, actor_id, owner_id, host_id, topic_id, scene_id, scene_revision, phase_revision, kind, lines, updated_tick)` with kind `formal|refusal|opening|service`; all ids JSON-safe scalars, delivery/context ids opaque <=64 chars. Owner identity is server-only and omitted from the wire. `topic_id` is nullable only for opening/service. Context id changes on new host/control/open/phase invalidation, not on an availability refresh. Scene revision identifies exact authored bytes; a session stores the delivered scene snapshot, never a current line cursor. A replay republishes that delivery_id and bytes beginning at line one without selecting again. Reject obsolete context, invalid host, changed phase, or changed actor/control; do not expose stale lines. Variant stays fixed after equipment/condition refresh while context remains valid. Revocation of eligibility alone refreshes choices; previously authorized playback stays fixed. Existing movement/combat/host departure/deletion clear seams retire delivery and choices together while historical attributed transcript remains.

`open_or_refresh_dialogue` remains the sole session writer. Generated scene selections use its scene form; freeform and deterministic opening/service calls retain the native line form. Selection effects and session publication share one transaction with cached-Attribute compensation, including quest acceptance and process-local registration compensation where the owning story API requires it. Existing action-envelope generation/epoch/revision admission rejects obsolete selections; replay/acknowledgement invoke no effects. Existing story-effect authority remains in its deterministic owner.

Bump the dialogue panel from schema_version 2 to 3 across Python and UMD/Vue validators in one runtime change. Exact available top-level fields are `{schema_version,available,kind,host,actor,bond_stage,context_id,delivery,choices,pure_chain,reading_revision,completed_topic_ids,unlock_batch}`. `host` and `actor` each use existing `{identity,display_name,portrait_ref}` contract with `portrait_catalog_key`; numeric affinity never ships. `delivery` is null or `{delivery_id,context_id,topic_id,scene_id,scene_revision,phase_revision,kind,lines}`; line forms are `{kind:"speech",speaker:"actor"|"host",text}` or `{kind:"narration",text}`. Static/generated topics use complete scenes. Freeform/opening/service text may use native one-host-line presentation. `choices` are <=16 exact `{topic_id,keyword_id,label,availability,requirement_hint,unread,predecessors,action_payload}` rows; keyword_id is the existing bounded localized command alias, never an alternative generated identity. Hidden rows absent, locked rows have no formal scene, open qualified rows have descriptors only until selection. `action_payload` is `{npc_id,topic_id,context_id}` for both scene sources (dispatcher adds selection_id). `pure_chain` contains only public effect-free successor scenes. Defaults before owning slices are `pure_chain:[]`, `reading_revision:0`, `unlock_batch:null`, unread:false and open/no hint. These defaults describe unsupported optional features. Client version 2 is removed. Portraits come from the same committed art snapshot.

### Reading and completion

`world/narrative/dialogue_reading.py` owns the exact Attribute schema below, using SQLite first-SQL guarded UPDATE, raw Attribute merge and cache compensation. `reading_for(owner,host_key)` is pure. `complete_delivery(actor,*,delivery_id,context_id,topic_id,scene_revision,session=None)` accepts only a retained formal receipt in current authenticated context and returns `{status:"saved"|"already_saved",reading_revision}`. Refusal, foreign, stale and undelivered claims reject without reading/effects. Variants/revisions never reset stable-topic completion. Pure-chain acknowledgements require saved formal predecessors; successful complete attributed text emission invokes this service. Generated reading never requires static registry membership or depends on physical materialization dbid.

Completion receipts persist independently of latest playback, including earlier topics. Keep at most two formal receipts per topic (latest and previous), <=32 receipts for <=16 topics; a third reselection retires the oldest unacknowledged same-topic receipt. Replacing the latest scene does not invalidate another topic completion. New context/phase/control clears these receipts. Delivery-bound duplicates remain idempotent across connections and reconnect. Returning to choices locally may reveal only pure-chain successors, with pending acknowledgements queued predecessor-first. Protected qualified successors wait for server-saved reading and eligibility refresh. Post-commit fan-out uses existing watcher/panel-pusher discipline, resolves connections for the OWNER including a currently possessed actor, and refreshes each connection's own live context without copying another body's scene.

### Availability and notifications

`world/rules/dialogue_conditions.py::evaluate_condition(condition,context)` and `condition_hint(condition,context)` share declarations and context's immutable permitted-reference labels. Missing/corrupt authoritative state fails closed with a facade integrity event, no handler materialization. Hints use public stage names, never private affinity numerals. `world/rules/dialogue_availability.py::project_topics(context)` is pure; `refresh_dialogue_availability(owner,*,cause)` runs from committed deterministic seams. Qualified predecessors/requires govern hidden/locked/open. Pure-chain predecessors govern UI reveal/persisted progress only, never effects. Server checks explicit IDs even when UI ordering is bypassed.

Before notifications, projection performs no unlock mutations. Narrative adds `observe_availability(owner,host_key,open_topic_ids,*,initial,context_id)` and `claim_unlock_batch(owner,batch_id)`. First observation of each unseen topic, including a new permitted generated phase, records initially open topics unread/announced without popup and hidden/locked topics ever_open=false. A previously observed locked/hidden topic later opening gets one announcement eligibility while unread. Refusal/variant/relock never reset completion/history. Claim one <=16-topic owner/host batch under owner lock before at-most-once live fan-out; no replay on snapshot/reconnect. Wrap each watcher batch with its current physical host_id/context_id and only currently permitted phase IDs. Client deduplicates in memory, defers until choices, never steals focus and drops retired contexts while durable markers remain.

Frontend pending completion exists only in memory scoped by owner character/control context, no localStorage/IndexedDB/service-worker queue. Retry on same-context transport restoration and explicit retry, serialize pure-chain predecessor acknowledgements, and do not claim saved state before a saved/already_saved response. On refresh/tab close/character exit/context invalidation discard pending state. Reconnect without pending memory replays latest delivered scene at line one; saved server reading wins. Persist no line/page cursor.

### Exact context, session and request composition

This section resolves the whole-batch review and is authoritative over abbreviated descriptions above.

`resolve_dialogue_context` is a pure validator/reader whose context_id is nullable before a session exists. It never allocates IDs. `select_authored_topic` accepts expected_context_id: str | None. Non-null must match the existing body/host/control/phase context. Null is admitted only for a direct text/suggestion entry with no live conversation; selection validates all gates and establishes context plus delivery/effects atomically. A null descriptor replayed after a context exists is stale. Text with a matching live host supplies its current context internally; direct text to a new host explicitly retires the old context and establishes the new one in the same transaction. A normal open starts a fresh context, even for the same host. Reconnect retains the existing opening-line context and delivery identity. A no-live-context suggestion descriptor carries null and uses this atomic direct-entry path; it does not require an undocumented preliminary talk_open.

Exact session fields are `{schema_version:1,kind,npc_id,host_key,source_identity,context_id,actor_id,owner_id,control_key,phase_revision,line,line_delivery_id,delivery,selection_receipts,completion_receipts,updated_tick}`. source_identity is null for freeform-only, `{profile_key,dialogue_key}` for static, or `{package_id,role_id,phase_id}` for generated. For kind line, line is bounded native text, line_delivery_id is stored and delivery is null. For kind scene, line/line_delivery_id are null and delivery includes server-only host_key/source_identity. owner_id, host_key, source_identity and control_key never ship. control_key encodes owner/actor/account/possession since_tick and is checked against lawful control. phase_revision is current generated revision or null for static. Changed binding, cancellation or phase retires context/receipts before replay/projection.

`selection_receipts` is a <=16 list of exact `{topic_id,selection_id,delivery}` rows, latest per topic, where delivery is the immutable committed SceneDelivery. Existing envelope revision/epoch admission rejects an older request after an intervening selection even if its receipt was replaced. `completion_receipts` is a <=32 list of exact `{delivery_id,context_id,topic_id,scene_revision,phase_revision,kind,predecessors}` rows, at most latest and previous formal receipt per topic. Owner/body/host/control are inherited from the parent session. Refusal/opening/service never enter that list. Public successors use kind formal without a selection receipt or effect. A third same-topic delivery retires only its oldest receipt; delayed A-after-B completion remains valid. Both lists survive reconnect and clear with context retirement.

The exact sole-writer signature is `open_or_refresh_dialogue(character,npc,line: str | None = None,*,delivery=None,context=None,selection_receipt=None,completion_receipts=())`. Omitted context on native line calls means validate/reuse a current same-host context or establish a new one inside this deterministic writer. This writer owns context creation, latest playback replacement and receipt merges. Narrative completion changes only reading state; any session receipt retirement goes through this writer.

Projected static/generated scene descriptors contain exactly `{npc_id,topic_id,context_id}`, null context only for no-live-context direct entry. They never contain selection_id. transport.js::dispatchAction passes the descriptor to the envelope builder. dispatcher.py::handle_ui_action injects `selection_id=action.request_id` after duplicate/stale admission and before full validation, rejecting client-supplied selection_id. Projection uses a pure descriptor validator; composed four-field payload uses the registered validator. Freeform remains separate. Generated-packages removes every old generated keyword-payload caller at cutover. This is the explicit exception to byte-identical projected payloads. Deliberate activations have different request IDs; retries preserve their ID.

### Exact populated wire and reading storage

The available v3 field set above contains `completed_topic_ids`, a <=16 unique list of saved formal IDs for this owner and host. It is [] before reading-server lands. `pure_chain` is a <=15 list of exact `{delivery,predecessors}` objects. Each delivery uses the exact wire delivery fields above, kind formal and a non-null topic_id, with a retained server completion receipt before its body ships. predecessors is 1..16 unique same-host IDs. Entries are topologically ordered public successors only, with no qualified descendants or effects. The selected primary delivery remains the server replay target; pre-delivered successors do not create a persisted client cursor.

`unlock_batch` is null or exactly `{batch_id,host_id,context_id,topic_ids}`. Batch/context IDs are opaque <=64 ASCII, host_id is a positive safe integer and topic_ids contains 1..16 unique same-host IDs in declaration order. The owner/host batch ID is stable, but each live watcher receives its own current context_id. Owner O with valid contexts C1 and C2 at host 41 receives batch U wrapped as C1 and C2 respectively. Both connections deduplicate/defer U locally; another character of the same account receives nothing. Snapshots and reconnect never contain U.

Exact narrative Attribute storage is `{schema_version:1,revision:int,hosts:{host_key:{initialized:bool,topics:{topic_id:{completed:bool,ever_open:bool,announced:bool}},pending_batch:null|{batch_id,topic_ids,created_revision}}}}`. Reading-server introduces the whole shape; unread-notices owns observation. First observation is per unseen topic ID, including each newly permitted generated phase's IDs. Insert all its declared IDs, locked/hidden ever_open false, and mark initially open IDs announced without popup. Host initialized alone cannot classify unseen phase IDs as later unlocks. Later locked-to-open creates one pending batch. Claim/merge happens under owner lock before fan-out. Phase retirement suppresses obsolete pending announcements while retaining completion/history; returning to the phase does not reset reading. No persisted recipient context or unbounded queue.

Example: selecting A produces primary D1 and public successor `{delivery:D2,predecessors:[A]}` at C, with completed_topic_ids []. Finishing A queues D1 and can locally reveal D2; qualified Q stays absent. Selecting B records D3 without deleting D1/D2 receipts. Delayed `{delivery_id:D1,context_id:C,topic_id:A,scene_revision:"r1"}` saves A and publishes completed_topic_ids [A] without restarting D3. A later state commit opens Q and claims U; `{batch_id:U,host_id:41,context_id:C,topic_ids:[Q]}` waits until D3 finishes. Reload carries no U and replays D3 at line one with saved [A].

### UTF-8 publication budgets

Additional canonical UTF-8 JSON limits are mandatory: Scene <=8192 bytes, selected delivery plus all public successors <=16384 bytes, complete dialogue panel <=24576 bytes. Validate every authored fallback/variant and worst reachable public bundle before registry publication. No prose truncation or silent successor omission. Dynamic native/service candidates and the complete panel must pass before effects/session settlement; failure is an operational refusal with zero partial effects. Action success.message is a bounded acknowledgement; full prose ships through panel delivery or text emission.

Ordinary envelopes retain 65536 bytes. A snapshot/update carrying an available v3 dialogue panel may use <=98304 canonical bytes only when the same envelope with dialogue removed passes the original 65536 limit and dialogue passes 24576. This dialogue-only allowance reserves publication capacity without relaxing unrelated panel bounds. Runtime updates Python protocol.check_envelope/coordinator full_snapshot and panel_update plus UMD constants/core/store admission in lockstep, including the outer pre-panel byte check. Reconnect uses the same rule. No fragmentation or map-fragment reuse is introduced. Add maximal multilingual chain/reconnect acceptance and oversized pre-effect rejection; all other global string/depth/list bounds remain.

## Batch review resolutions (authoritative)

Every change in the batch reads this section together with Shared contract v2; where an owning change restates an item, the two must agree. These resolve the whole-batch critique and leave no interface decision open.

1. **Loader boundary.** `load_dialogue_snapshot(content_dir, *, profiles, bindings, references)` takes `profiles: frozenset[str]` of registered `NpcProfile.key`, `bindings: Mapping[str, str]` from `dialogue_key` to `profile_key` (derived by the caller from existing place/service metadata; today exactly 25 rows, one per existing table), `references: DialogueReferences`, and returns a read-only `Mapping[str, AuthoredDialogue]` keyed by `dialogue_key`. Every binding MUST resolve to exactly one discovered file and every file MUST name a registered profile, so deleting or renaming a bound file rejects the whole candidate instead of silently disabling a host; profiles that own no dialogue table are not bindings. The loader derives no binding list and no reference family, and caches neither between calls. `world/lore/dialogue/content/` is a tracked shipped directory, never pruned from a checkout or shard.
2. **Reference-catalog ownership.** The frozen `DialogueReferences` type and its family list belong to contracts. `world/rules/dialogue_references.py::static_dialogue_references()` is owned by `authored-dialogue-physical-conditions`, which builds the complete catalog from existing canonical registries after its `authored-dialogue-social-identity` prerequisite; `authored-dialogue-progression-conditions` extends the same builder with the `guild_rank`, `quest` and `affinity_stage` tables. `authored-dialogue-runtime` passes `DialogueReferences.empty()` because the 25 migrated tables declare no conditions, and generated package validation receives the catalog its callers built. No slice keeps a second hand-written key copy.
3. **Web action lockstep.** The composed `explore.talk_scripted` payload is exactly `{npc_id,topic_id,context_id}` as projected, with server-injected `selection_id`; `context_id` is null only for a no-live-context direct entry. Changing it and adding `explore.dialogue_complete` both edit the same registration points together: `web/webclient/presentation/affordances.py::ACTION_CODE_ALLOWLIST`, `web/webclient/presentation/options.py::_ACTION_PAYLOAD_VALIDATORS`, `web/webclient/actions/registry.py::ActionSpec`, the exact-field validator in `web/webclient/actions/exploration_actions.py`, and `web/static/webclient/js/elosern/protocol/constants.js::CONTEXT_ACTIONS_ACTION_CODES`; `web/static/webclient/js/elosern/protocol/panels/skill_descriptor.js` keeps the client-side exact-field mirror. The affordance producer is `web/webclient/presentation/affordances.py`, so it is always in the same change as the validator.
4. **Fail closed before evaluators exist.** Until `evaluate_condition` lands, `select_authored_topic` rejects any topic with a non-null `requires` or a qualified predecessor and delivers nothing: no placeholder evaluator, no protected body reachable through an explicit ID.
5. **Static topic IDs.** A static topic ID is `<existing dialogue_key>.<suffix>`, where the dialogue_key is the existing canonical key and the suffix matches `[a-z][a-z0-9_]{0,31}`; the full ID is ASCII and <=96 bytes. `AuthoredTopic.refusal` is typed `Scene | None`.
6. **Host descriptor fields.** `host` and `actor` use exactly `{identity,display_name,portrait_ref}`, where `portrait_ref` is the existing art-catalog key or null. There is no `portrait_catalog_key` field.
7. **Guild 回報 kind.** A registered adventurer's 回報 turn-in is native `service` delivery with `topic_id: null`, no formal receipt and no unread/completion projection; the authored `topic_04` scene is the informational/registration exchange that does carry a formal receipt.
8. **Legacy generated payloads.** An already-published package whose dialogue parses only to the removed `PhaseTopic.response` shape resolves to no dialogue source, so the host behaves as non-conversable for formal topics, with one `dialogue_source_rejected` boundary event and no partial delivery. No migration and no shim.
9. **Completion refreshes eligibility.** A successful `complete_delivery` commits reading and then queues `refresh_dialogue_availability(owner, cause="reading_completed")` on commit, so a newly eligible qualified successor opens without waiting for an unrelated state change.
10. **First observation trigger.** Every successful open or selection re-projects and calls `refresh_dialogue_availability(owner, cause="open")`; the first call for a host carries `initial=True` into `observe_availability`, so a host's first-ever visit initializes every declared topic ID instead of being mistaken for a later unlock.
