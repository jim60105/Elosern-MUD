# Movement event alignment and settlement ownership

## Context

B compares all candidate publications and D defines snapshots/deltas. Movement commits in `world/rules/movement_settlement.py::settle_movement/settle_relocation`; TerrainRoom objects are pooled across coordinates. `area_map.py` already identifies grid areas by z-map-key, wilderness by WILDERNESS_MAP_ID and coordinate-free areas by the minimum dbref of their connected same-family component. Instance spawn stores origin_room and scene_identity. These authoritative facts must be captured before traversal, never recovered from display labels afterward.

## Goals / Non-Goals

Deliver movement checkpoint classification plus the shared settlement/fact integration used by S. Do not change movement cost, rollback, map knowledge, game-state schemas or command syntax. Never call area_map/world_map presenters to discover identity or force-load them during alignment.

## Decisions

### Authoritative identity

Add read-only `world/maps/area_identity.py::read_alignment_identity(actor) -> AlignmentIdentity|None`, a frozen value containing `(layer, area_key, instance_key)` copied at capture time. Grid/Anchor uses layer=grid, area_key=location.xyz[2], instance_key=None. Wilderness uses layer=wilderness and the registered wilderness map identity/name (the same WILDERNESS_MAP_ID coordinate frame used by area_map), instance_key=None. Coordinates and terrain/district/display labels are excluded. Moving within this continuous wilderness map stays incremental even if a terrain label changes. Grid-to-wilderness and grid map-key changes align.

For plain coordinate-free interiors, share the existing read-only `_room_component` traversal from area_map.py as `world/maps/area_identity.py::room_component` and use `room:<minimum component dbref>` as area_key. Preserve existing same-family filtering/edge semantics; reuse it in area_map rather than establishing two definitions. For InstanceRoom use `instance:<minimum instance component dbref>` as area_key and `(root dbref, root.scene_identity)` as instance_key, with the root's authoritative origin/scene identity captured as plain values. This distinguishes entry/exit/replacement even when labels are equal. Moving within one instance component is incremental. Unknown/unreadable identity returns None and a successful non-comparable transition aligns conservatively. Failure/rollback with no committed traversal emits no event. Test source identity capture before a pooled wilderness room is repurposed.

### Narrow committed fact interface

Add `world/rules/presentation_events.py`, a narrow nonpersistent observer interface dedicated to completed presentation alignment, not a generic game event bus. Frozen `PresentationAlignmentFact(actor_id:int, cause:Literal["movement_boundary","combat_terminal","skip_completed"], source:AlignmentIdentity|None=None, destination:AlignmentIdentity|None=None)` contains IDs/values only and no transport objects, prose or game writers. APIs `register_alignment_observer(callback)` (idempotent registration) and `emit_alignment_fact(fact)` isolate/log observer exceptions through world.observability. Producers register emission with `transaction.on_commit` inside the successful owning transaction. Rollback yields no fact; when outside a transaction emit only after the successful owning write. S owns the latter two cause producers.

`presentation/ingress.py` registers the production observer once beside its existing watcher/coordinator setup. It resolves current lawful watchers for the affected actor using presentation/watchers.py, captures each current coordinator epoch, and calls `coordinator.mark_alignment(cause, expected_epoch=E)`. Retired or absent coordinators are ignored. Text on a Telnet session never gets OOB, while another live lawful WebClient watcher can still receive a committed checkpoint. No cross-character or account-wide fan-out.

### One publication per serialized settlement

Coordinator remains the only publication owner. Add `begin_settlement(expected_epoch)->token` and `finish_settlement(token,context,*,affected_panels=None,result=None)` plus `abort_settlement(token)`. Token is coordinator-local, carries epoch and a unique settlement ID, and may finish once. One active token per session; do not use a process-global flag or a ContextVar left active across a Deferred. Begin it before graphical adapter invocation in dispatcher `_invoke_adapter` and before the actual `cmdhandler(session, txt, callertype="session", session=session, **kwargs)` call in server/conf/inputfuncs.py::text. Pass the explicit token through Deferred callbacks/errbacks and ingress observer; a synchronous completion uses the same finish path. Preserve command's original callback value/Failure. No extra finish at both command.at_post_cmd and input-function observer.

During the token's lifetime, same-session synchronous post-commit pushes queue candidate NAMES (not mutable payload snapshots), and mark_alignment records a deduplicated reason set. On finish, rebuild canonical context once, union queued candidate names with the completion candidates, apply dialogue/mode dependencies, and publish exactly one final fresh snapshot if any checkpoint qualified, otherwise B's delta/no-op. Complete all presentation frames before its action result. Queued push callers receive the final receipt; push logging must not assume synchronous envelope return. This slice changes the shared `publish_panel_update` helper to ALWAYS return `Deferred[PublicationReceipt|None]`, immediately resolved when not held and resolved after finish when held. Migrate make_panel_pusher, art_push, options/state and title_nomination_service result/log consumers to callbacks; no receipt-or-Deferred union or second baseline. Direct coordinator publish remains synchronous outside a held token. Queued push count obeys B's64-intent bound and candidate/reason sets are bounded by registered names/three causes. Unknown scope dominates candidate union. Abort of a retired epoch resolves held push results with None, clears pending reasons/intents and emits no old-puppet state. A domain error after a successful commit still publishes that commit's checkpoint; a rolled-back domain error has no checkpoint and follows existing safe recovery policy.

A fact outside a held settlement schedules one reactor-next-turn publication intent, coalescing multiple reasons for that same committed callback group and rechecking epoch on execution; this is a bounded one-shot scheduling boundary, no periodic timer. Unrelated later asynchronous push remains a separate ordered B publication. Multiple nested domain events inside one token produce one final snapshot. Other watcher sessions have their own independent token/reasons/baseline.

### Production hook inventory

Capture old/new immutable identities at settle_movement's successful compensated boundary and settle_relocation's successful commit. Wilderness/grid/plain/instance Exit traversals, NPC.move_to (including possessed NPCs) and graphical `_move_adapter` use those owners; do not classify requested explore.move as success. PlayerCharacter direct move_to can bypass settle_movement, so add capture in its existing at_pre_move after movement admission and compare in its at_post_move commit callback; use a per-invocation copied source identity, never retain the mutable source room. When settle_movement already owns the traversal, use that owner's capture and suppress the duplicate player hook fact. Failed hooks/rollback/compensation (move_hooks=False) publish none. `typeclasses/characters.py::_schedule_projection_refresh_after_activation` queues ordinary unknown eager candidates under the same token; adding occupants alone is not an area checkpoint. Actual room entry is classified by the movement owner, and login activation is already covered by full baseline establishment. Source and destination cannot be inferred merely from a final location poll. Explicit sync/login/reconnect/puppet/recovery already force snapshots in B and need no checkpoint fact.

Exact owned files are new world/maps/area_identity.py and world/rules/presentation_events.py, movement_settlement.py, area_map.py shared reader extraction, coordinator.py settlement methods, dispatcher.py token plumbing, ingress.py observer/finish path, server/conf/inputfuncs.py token creation, typeclasses/characters.py direct-move capture/activation enrollment, presentation/{push,art_push}.py and server/{option_proposal_service/state,title_nomination_service}.py Deferred receipt consumers. S reuses this contract without redefining it. Preserve active dialogue lifecycle refresh callbacks and their transaction semantics; their same-settlement pushes become candidates under this owner.

## Verification and documentation

New `presentation/tests/test_movement_alignment.py` exercises real deterministic exit traversal through both UI dispatcher and WebClient text input, with synthetic grid keys, identical display names, pooled wilderness reuse, interior components, instance replacement and unreadable identity. Assert one freshly rendered complete eager publication instead of a delta; deliberately omit one panel candidate before checkpoint and prove checkpoint restores it from canonical state. Verify failed move/rollback sends no checkpoint, same-area move stays incremental, unopened map presenter call counts stay zero, and captured old-epoch token cannot publish into replacement. Document authoritative identity and finish ownership alongside the approved design implementation notes. Focused commands are in tasks.md.

## Risks / Trade-offs

Semantic facts cross deterministic/presentation layers only as read-only observer data; web code is never imported by a state writer. Observer registration is idempotent and tests restore registration. Shared room traversal extraction preserves current map behavior without building a map payload. Explicit per-session token plumbing avoids Deferred context leakage and duplicate refreshes.
