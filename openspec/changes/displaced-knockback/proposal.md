## Why

The wind tree (`docs/lore/skill-trees/wind.md`) prices 擊退 on three nodes (`storm_domain` 附加擊退效果, `sky_tempest` 附加擊退控制, `sky_apotheosis` 擊退控制 90 秒), and constitution §4.2 allocates 擊退 to wind as 「位置極性的合法自用」 — but the game has no position primitive at all: in-combat reachability is binary (present vs fled), and every targeting path treats a living present entity as trivially targetable. Future elements will want the same out-of-position fact (any blow, charge, or repositioning effect), so the primitive must be generic element-agnostic mechanic vocabulary — exactly the `terrain-marker` precedent this time on the *position* axis, with zero live rows shipped here.

## What Changes

- **Batch declaration.** This change lands FIRST in the wind wave; `unconditional-multi-strike` and `wind-spell-catalog` follow per `## Batch` below with machine-readable `depends-on:` lines and combat.py hunk-sequencing notes.
- Add a rulebook-declarable **positional-marker buff family**: one validated optional `marker: positional` clause on the `buffs.yaml` definition grammar — the closed `MARKER_VOCABULARY` grows from `{ground}` to `{ground, positional}` — declaring that holding a live instance of the row IS the canonical out-of-position fact. Holding == out of position == melee-unreachable BOTH ways (the supervisor-ratified design, not reopened here): while held, single-target STRIKE (physical-school) targeting is gated in both directions between holder and others — the holder cannot be chosen as the target of another's single-target physical strike, and the holder cannot select another entity as the target of its own single-target physical strike. Area effects and the magic school remain fully reachable in both directions. Generic code reads only the clause and the shipped school/target-shape vocabulary; no element, skill or buff-key branches.
- **Sovereignty is preserved** (index.md §4.2/§4.4): the marker is NOT ice's stillness ladder and NOT thunder's turn denial — the holder keeps full agency: it casts (magic and area included), uses items, moves, acts on its turn. Only the melee-strike pairing between holder and others is unreachable; every existing validator, reject reason and capability path is bit-identical.
- **Self-return rule**: resolving one's own single-target STRIKE against another entity clears the actor's live positional marker immediately before that action resolves (climbing back into position) — a strike attempt is the act of returning; a magic or area cast never clears it. The marker additionally extinguishes through the shipped paths when its holder flees, is knocked out, is defeated, or the combat session ends (the battlefield-exit sweep extends to `positional` rows exactly like `ground` rows; out-of-combat holders keep the row on its own duration clock).
- **Cross-primitive synergy sweep**: applying a positional-marker row to an entity deterministically sweeps that entity's live `ground` marker instances first (being blown off the fissure/lava) before the displaced instance mounts — one ordered side effect inside the shipped `apply_buff` write path, observable, zero damage or revive side effects, non-marker buffs untouched.
- No second rules engine: every seam is a validated extension of the shipped declarative surfaces (`buffs.yaml` marker clause, `spell_conditions` step-4a condition engine, the three deterministic single-target picker filters, `combat_session` exit sweeps; knockback mounts land in `wind-spell-catalog` as direct `buff_apply:` effect components on the consumer skills riding the shipped effect handler → public `apply_buff` entry — verified at 9ca95ba that a reaction-rule mount is impossible for wind nodes: the `hp_loss` dispatch carries `source_tier` but NOT `source_skill` (`world/rules/combat.py:475-477`; `action.py:1820`) and `physical_hit` carries `source_skill` but fires only for physical-school damage, so an `event: hp_loss` + `event_source_skill:` rule can never fire from a wind magic strike; `state_reactions.yaml` needs ZERO change). This change ships ZERO live rows and zero registry rows — inert-but-valid vocabulary, exactly the `terrain-marker` / `dark-erosion-leech` precedent. This change does NOT touch `world/rules/combat.py`'s `_handle_damage` strike loop (the extra-strike hunk belongs entirely to `unconditional-multi-strike`); its only `combat.py` edit is `default_attack_policy`'s candidate filter.

## Capabilities

### New Capabilities
- `positional-marker`: the generic out-of-position marker primitive — validated `marker: positional` clause on the buff-definition grammar, the holding-is-out-of-position fact, the bidirectional single-target-physical-strike reachability gate (with the self-return clear and the magic/area exemptions), battlefield-exit extinguishment scoped to positional rows, and the ground-marker sweep-on-mount cross-primitive rule.

### Modified Capabilities
- `buff-handler-integration`: the buff-definition requirement is extended so the closed marker vocabulary accepts `positional` beside `ground` (strict superset; every existing row loads, applies, ticks and expires bit-identically; a positional row may additionally carry `rate`/`bounds`/`modifiers` like any marker row) and so applying a positional row first sweeps the recipient's live ground-marker instances.
- `spell-effect-model`: unchanged grammar — the STRIKE-class classification this change gates on (single-target + physical-school damage effect) is read through the shipped effect/school/target vocabulary; recorded as a consuming premise, no delta.
- `terrain-marker`: the battlefield-exit extinguishment requirement is restated to cover BOTH marker classes (ground and positional) through the same shipped removal path; ground-row behavior is bit-identical.
- `targeting-validation`: recorded premise, no requirement delta — the displaced gate is NOT a fifth ordered validator (it is skill-shape-dependent, which the four-shape `TargetRequirement` deliberately does not model); it lives in the step-4a spell-conditions seam, which already owns state-dependent target-capability rejection. `resolve_targets` and the four validators stay bit-identical.
- `monster-action-policy`: the target-selection requirement is MODIFIED as a strict superset — the SINGLE-strike candidate sets (monster `_living_enemies`/`_choose_target` path and the delegated `default_attack_policy`) SHALL exclude positional-marker holders for strike-class selection (a monster owning a magic-school SINGLE kit keeps displaced candidates for that magic path; step-4a stays authoritative), falling back to no-target/no-action when no strike-reachable living enemy remains for a strike-class actor, so the resolution gate never strands a scripted action into a guaranteed rejection (the AREA shorthand path keeps displaced candidates; area reachability is unaffected). Resolution-time rejection stays the authoritative gate; filters are selection-hygiene only. Consequence recorded without a delta: `player-combat-session`'s provider requirement sentence stays verbatim — the session's `_basic_attack_request` filter is a candidate-set narrowing inside the already-pinned 「deterministic behavior-policy ActionRequest values」 surface, and the fixed-seed golden tests stay deterministic (state-only, dice-free filter).
