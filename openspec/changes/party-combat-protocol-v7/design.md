# Design: Exact v7 party-command presentation and action protocol

## Context

See `proposal.md` for motivation and the batch contract in `../combat-ratio-mitigation/batch.md` for complete coverage, order and conflicts. Current context_actions is v5; active panel-v6 adds conditions and polarity only. Exact server/client field validators and the parity test require a new version for mandatory party fields.

Inspected boundaries are listed in the proposal Impact section. These are observed starting points; all new behavior below is proposed, with no runtime result claimed. The approved 2026-10-15 document explicitly amends the base engine §6.3 where subtraction, allied autonomy and individual allied flee conflict.

## Goals / Non-Goals

This change owns exact v7 party-command presentation and action protocol. It reuses existing deterministic state owners and exact protocol conventions. Required behavior is defined by its complete delta files. There is no new LLM dependency, compatibility path, data migration, shared inventory, companion equipment-management UI or physical proficiency progression. Detailed stage geometry remains owned by the existing UI batch.

## Decisions

Bump `context_actions` from active v6 to v7 with no compatibility parsing. The combat available form is exactly `schema_version, available, kind, session, participants, root_actions, secondary_actions, actors, choices, draft, suggestions`; retain v6 participant conditions and every skill polarity/scale fact inside the requested actor choices. Remove puppet-level `skills`. `actors` is ordered by allied participant order with at most five entries, each exactly `identity, commandable, reason`. Reason is null or the existing bounded code/message shape; `choices` is exactly `actor_id,skills,items,tactics`, for one requested authorized actor only; a noncommandable actor has no enabled choices. Skill descriptors reuse v6 grouped shape, max 192 for that actor. Item rows are exactly `item_key,label,quantity,enabled,reason,target_spec,targets,hostile,beneficial`; quantity is a nonnegative safe integer, targets reference up to 16 current participants, and target_spec is none|self|single for the caller-supplied target while registry effects still own full item reach. Bound item rows to the registered inventory catalog bound with explicit fail-closed overflow, never truncate owned usable choices. Derive polarity from typed effects using the authoritative classification, including mixed item effects. Tactics are exactly `key,label,enabled,reason,targets`, key defend|dodge|taunt, targets only for Taunt. `draft` is exactly `round_revision,draft_version,required_actor_ids,entries,needs_selection_ids`; entries are exactly `actor_id,command` with closed request union described below. IDs are unique positive safe integers and references must join current party/participants; all subset, count, revision and reason/enabled invariants are mirrored. Session/labels/keys reuse existing bounds, token max 128 codepoints, actors max 5 and participants max 16. Invalid forms fail closed in both validators.

Replace production interactive adapters with read-only `combat.actor_choices` and mutating `combat.command`, `combat.exit_prompt`, `combat.exit_confirm`. Actor-choice query is exactly `{session_id,round_revision,actor_id}` and selects a transport-owned read context without saving a command, charging time or authorizing mutation. Reconnect defaults to first required actor needing a command, otherwise commander. Transport selection is independent from durable draft state. Command payload is exactly `{session_id,round_revision,draft_version,actor_id,command}`; command is `{kind:'skill',payload:{skill_key,...existing TargetSpec fields, optional scale}}`, `{kind:'item',payload:{item_key, optional target_id}}`, or `{kind:'tactic',payload:{key, optional target_id only for taunt}}`. Skill flee is reserved. Exit prompt is exactly `{session_id,round_revision,operation}`; confirm adds `confirmation_token`. Both are session-level and carry no actor. Integers exclude bool/nonfinite/unsafe values; unknown keys reject. Server returns safe pending-draft, needs-selection, round-committed, stale/already-committed or terminal result using the established result envelope, plus canonical panels before result publication. Prompt token and consequence data use a bounded result data object, never prose parsing. Existing exploration `inventory.use` and `inventory.toggle_equip` retain their schemas but inventory.use rejects during active combat, so actorless consumption cannot bypass the draft. Retire combat.cast/flee/forfeit registrations and migrate every producer in dependent client changes as a coordinated cutover. Preserve beat records only for the final confirmation that actually commits a round, never edits, prompts or reconnect. Keep unavailable/exploration exact forms and full terminal refresh semantics.

Keep the 65,536-byte canonical JSON/OOB envelope bound; never emit five full 192-skill catalogs together. A maximal obtainable one-actor catalog plus current registered usable items and 16 participants must fit, with every choice still present; measure the actual fixture. All actor summaries remain visible for progress. Transport selection is invalidated on session/epoch/puppet changes without possession changes.

## Risks / Trade-offs

- [Shared boundary changes] -> Implement only after declared prerequisites, integrate earlier deltas and callsites, and use the batch matrix to serialize overlapping files. No obsolete alias or duplicate implementation remains after cutover.
- [State or capability changes after selection] -> The shared rules boundary repeats authoritative validation; invalid drafts and normal mid-round invalidation follow different documented semantics.
- [Unproven arithmetic, persistence or UI behavior] -> Tasks include focused independent assertions and actual evidence where owned here. A selected constant alone is not measured balance and a fixture-only UI is not runtime acceptance.
- [Estimate depends on existing patterns] -> Scope is bounded to the listed owner and 7.5 hours includes its focused tests/docs/integration. Required downstream behavior is owned explicitly in the batch rather than silently deferred.

## Migration Plan

Pre-release clean cutover only. Implement code, callsites, fixtures, exact schemas and affected canonical requirement annotations together for this slice. No old/new compatibility parser, stored-data migration or deprecated entry path is added. Rollback uses an ordinary revert of the implementation change; proposal authoring performs no rollback, merge, apply or archive. The assembled client/server cutover is accepted only after change 18.

## Verification and documentation ownership

Use synthetic fixtures for independent behavior expectations and the existing real-data calibration boundary for authored roster evidence. Register added/moved Evennia tests and browser methods exactly once in the appropriate shard manifest; annotate tests with canonical `<capability>.<requirement-slug>` IDs generated by the project traceability tooling. If the canonical slug changes, migrate every affected annotation. Update existing affected documentation, both player command documents for syntax/context changes, and focused schema/fixture mirrors for transport changes. Run the focused tests and `uv run --locked python -m tools.contract_gate` during implementation; logging changes also require observability lint and focused event tests. Complete managed browser and traceability-evidence execution stay CI-owned.
