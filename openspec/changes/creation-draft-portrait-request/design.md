# Design

## Context

See `proposal.md`. `request_gallery_image` currently derives the subject from `portrait_policy`, requires canonical ages and calls `description_for(entity, apparent_age, fields, custom_prompt)`. Pending shells need neither a saved complete form nor canonical identity. `finalize_player_portrait` currently writes named policy only during activation. `gallery_job_in_flight` is a read under the shared queue lock; `settle_gallery_generated` already rejects a deleted record or mismatched generation token.

## Goals / Non-Goals

**Goals:** one exact request using validated draft values, early named-policy ownership, and bounded draft-image provenance.

**Non-Goals:** panel version changes, UI/drawer mounting, reset/activation cleanup, altered activated-gallery caps, equipment/appearance selection or a new art worker. No temporary writes of draft identity onto the shell and no fake entity/proxy.

## Decisions

### Exact adapter and shared identity validation

Add `validate_creation_portrait_payload` and `_creation_portrait_adapter(actor, payload, session=None)` in `web/webclient/actions/creation_actions.py`; register only `creation.portrait.generate` in `registry.py`. Payload has exactly `{race, subrace, sex, apparent_age, custom_prompt}`. Race/subrace are nonblank bounded identifiers using `MAX_KEY_CODE_POINTS`; both are required and registered, subrace belongs to race, sex is a concrete shared-vocabulary member permitted by race, apparent age is an integer 0..10000 excluding bool, and prompt is a string accepted by `gallery_prompt.validate_custom_prompt` (including empty/whitespace-only). No `age`, subject, fields, binding, face rectangle, actor or equipment is accepted. Keep dispatcher epoch/revision/request-id and replay checks unchanged. A new request uses the caller’s current form, not the persisted wizard draft.

Add `world/rules/creation_portrait.py` with frozen `DraftPortraitRequest` and `request_draft_portrait(account, character, request)`. Extract the existing identity checks from `character_creation.py` (`_validate_age`, `_validate_sex` and race/subrace resolution) into the pure `world/rules/creation_identity.py`, imported by both creation and this request. The pure module imports only registry/validation dependencies and no art service, avoiding a subjects-to-character-creation cycle. Do not call full allocation/name preflight or manufacture missing fields. Recheck ownership, PlayerCharacter and `creation_pending` inside the synchronous rules transaction. Map errors through `creation_messages.py` to stable safe zh-TW messages. Adapters make no `.db` writes.

### Named policy, receipt and the one enqueue seam

Extract `ensure_player_portrait_policy(character)` into `world/rules/character_creation.py`; it establishes/reuses exactly `{"mode": "named", "stable_key": str(character.pk)}` and rejects a conflicting existing named key. Both request and `finalize_player_portrait` call it. It schedules nothing itself. Snapshot/restore the affected Evennia attribute caches on failed request transactions.

The rules owner alone writes a bounded `creation_portrait` attribute, exactly `{version: 1, image_id: <uuid>, retained_image_id: <uuid or null>, fallback_key: <validated built-in key>}`. `image_id` is the latest admitted request; `retained_image_id` is the last readable creation-owned card when the next request starts. At admission, derive that retained id from the prior receipt’s current/retained ids and actual gallery reads; a failed request id never replaces the retained successful id. Resolve `fallback_key` from the admitted sex/apparent age and the character’s full subject key using change 1’s pure resolver; it supplies ready-descriptor geometry without reading uncommitted identity later. Store no prompt/identity copy here. No ledger grows with repeated failures. The art owner only receives these authorized ids and never changes this character attribute.

Extend the existing `request_gallery_image` seam with an optional typed `draft_values` argument, accepted only for an explicitly pending character and empty fields/no binding/no supplied rectangle. The value is a frozen validated snapshot of race/subrace/sex/apparent age, defined alongside the pure draft description input in `world/art/subjects.py`. Its constructor and service entry revalidate registry membership, compatibility and apparent-age bounds through `creation_identity.py`. Canonical age checks remain mandatory for every ordinary or activated request; the pending path validates its explicit apparent age instead. No generic `skip_age_check` flag or alternate public queue bypass. This is an explicit delta to `art-gallery-autogen`’s previously unconditional canonical-age sentence. Startup automatic recovery explicitly skips pending policies, preserving already admitted jobs without inventing an automatic replacement.

Add a service-owned `serialized_gallery_mutation(subject)` context in `world/art/service.py` that acquires the existing non-reentrant `queue_lock` before any database transaction/read/write in the mutation and yields a subject-bound internal token. It does not write character attributes. In `creation_portrait.py`, add `draft_portrait_mutation(character)` around that context and the rules-owned `transaction.atomic()`. The order is deferred-callback scope → queue lock → database transaction → gallery lock where needed. Recheck pending ownership, reread receipt/cards, choose retained id, establish policy, check in-flight, enqueue, and write receipt inside this single unit, committing before releasing queue serialization. This prevents a worker settling between retained-card discovery and admission. Do not rely on the reactor for worker serialization: `_run_and_settle_batch` settles on its background thread.

Factor queue operations into private already-locked primitives, with existing public wrappers retaining their lock acquisition. The common `request_gallery_image` accepts the subject-bound internal token only with validated draft values and calls those primitives without reacquiring the lock. This is not an alternate validation/enqueue API: all capability/identity/prompt checks still run in the common seam, which mints the image id. Ordinary callers use the unchanged public locking path. Nested same-character rules calls reuse the active unit; a foreign subject/token or use outside its scope rejects. An outer entry must precede any ambient write transaction; reject a foreign preexisting transaction before acquiring queue serialization. No reentrant lock or generic skip-validation flag is introduced.

Commit callbacks must not reacquire queue serialization while it is held. Add `defer_publication_callbacks()` in `world/rules/presentation_events.py`: callbacks registered via `on_publication_commit` become eligible only on a real successful commit, retain their captured publication group, and are drained after the outer deferral scope exits. Nested scopes reuse the outer collector; rollback runs none; successful inner savepoints do not qualify before outer commit. The rules mutation places this deferral scope outside the lock context, so commit occurs under queue serialization but unlinks/publication/automatic ensures run only after lock release. Change `world/art/service.py::schedule_portrait_ensure` from raw `transaction.on_commit` to this existing registration seam, preserving its exception isolation and ordinary no-deferral behavior. Cleanup slice migrates activation's raw arrival callback to the same seam. The policy, job and receipt commit together; on failure restore affected caches before releasing serialization.

### Description and replacement

Add `draft_character_description(values, custom_prompt)` in `world/art/subjects.py`, sharing the `art.character_description` render helper with `character_description`. Resolve subrace to its parent race’s image-recognizable display label and render the submitted apparent age. Sex is validated and used by fallback, but the current template has no sex input; do not add a second prompt schema. Appearance/equipment slots are empty; normalized custom text uses the existing custom slot. Never read a shell name, persona, equipment, actual age or concept text. Preserve the existing registry-driven prompt-unavailable fallback.

The character kind remains uncapped after activation. The draft path stores server-authorized replacement metadata on its existing per-image job, naming only `retained_image_id`. On successful settlement, through service-owned queue/gallery helpers, append the new card, set it as default and remove only that previous creation-owned card in one database transaction under the same queue-before-database-before-gallery order. Collect committed removals, then unlink only after successful commit and release of both locks; do not invoke a lock-taking commit callback inside settlement's lock. Failed generation retains the previous card/default. Existing queued job snapshot values remain authoritative even if the form changes; they never reread form state at settlement.

No cleanup occurs on save, browsing, identity edits or concept fill. `creation-draft-portrait-cleanup` owns reset and activation disposition; the receipt/queue metadata are its concrete input.

### Action echo and unchanged confirmation

Add the action to `web/static/webclient/js/elosern/command_echo.js` and its literal coverage manifest with a bounded action label. No typed-command alias exists. Echo contains neither prompt nor draft identity. Local opening remains silent. Update Python registry/catalog equality tests. The portrait adapter never calls `_confirmed_success`, `_invalidate_confirmation`, `_store_proposal`, `_clear_proposal` or a draft save. A portrait result cannot open activation confirmation.

### Connectivity authority and offline behavior

Intentionally amend `art-service-connectivity-surface`'s current diagnostic-only contract for **only** owned pending `creation.portrait.generate` admission. Approved design §§7.3/12 require offline rejection and a server-provided unavailable reason before submission. The recovered handoff line described the current main specification; the supervisor explicitly superseded treating it as an immutable predecessor decision. This proposal is the explicit amendment permitted by `AGENTS.md`, not a deviation from the approved offline UX. Keep the historical requirement title for strict-validation identity; its body names the sole exception.

After structural/domain validation and a read-only ownership/pending check, but **before** acquiring queue serialization or opening the mutation transaction, `request_draft_portrait` calls existing `connectivity.probe(force=False)`. A false verdict rejects with stable, distinct `portrait_service_unavailable`, mapped through `creation_messages.py` to a bounded safe retryable reason. A true verdict proceeds to the serialized unit, which still rechecks ownership/pending. No actor policy, receipt, portrait state, draft, confirmation or queue entry is written on refusal. Return the ordinary rejected result with `affected_panels: ("creation",)` so the existing coordinator publishes changed availability before its correlated result. Do not mark it result-only, attach a retryability wire field, or store a durable unavailable lock.

Add `connectivity.read_cached_probe() -> ProbeResult | None` as a pure snapshot reader. It uses the existing configuration fingerprint and cache-validity rules, returns an immutable copy of a current verdict, and returns null for absent/expired/mismatched entries without probing, extending cache life or writing it. Invalid effective settings yield the existing safe internal-error verdict without a cache write. Share the validity calculation with `probe`, not a second cache. `world/rules/creation_portrait.py` is the only additional production importer and exposes `read_portrait_service_availability()` for the panel; only its request path calls `probe`. Presenter/drawer never probe. Neither endpoint/host, credentials, raw exception nor probe timestamps enter the player payload; use safe named-code mapping only.

The panel slice projects a current failed verdict into existing `portrait.status: unavailable` plus `reason`; unknown/expired verdicts do not manufacture unavailability. Its disabled generation control is display-only: a stale or tampered browser that submits still receives server refusal. To recover without a stored lock or automatic probing loop, the integration slice exposes explicit status refresh through existing `store.requestPresentationSync("manual")`/`ui_sync`. A fresh panel reads the cache again; expiry/config change removes the stale display refusal, allowing a new explicit generate attempt to obtain a fresh bounded verdict. An unexpired failed cache can legitimately keep the reason until refresh observes expiry or a newer successful server diagnostic. No automatic replay or client-side clock authorizes generation.

All gallery/on-demand noncreation requests, automatic ensure/autogen, queue and worker behavior remain exactly ungated. No production `world/art/` module except `connectivity.py` imports connectivity; neither queue, worker nor service adds a probe branch. Once admitted, a job is attempted even if a later verdict fails. The creation gate has genuinely different outcomes (refuse or enqueue), never two continue-anyway branches. Portrait stays optional: offline art/LLM cannot prevent preset/custom creation, activation or deterministic gameplay.

## Risks / Trade-offs

The canonical-age exception is intentionally limited to the new owned pending input; tests must reject raw character subjects, invalid typed inputs and activated callers trying it. Per-draft replacement adds job metadata rather than changing global character-kind caps. Existing gallery/default semantics and policy-free preview builders stay unchanged.

## Acceptance and documentation

Add `world/rules/tests/test_creation_portrait.py`; extend `web/webclient/actions/tests/test_creation_actions/test_payload_validation.py` and `test_adapter.py`, `world/art/tests/test_service/test_gallery_request_seam.py`, `world/art/tests/test_subjects.py`, queue settlement tests, action-catalog coverage and command-echo tests. Test synthetic forbidden sex/race combinations, missing/invalid values, ownership/pending rejection, two-session in-flight admission, failed-write rollback, shell identity disagreement, empty prompts and repeated regenerations with unrelated card controls. Use an injected fake art client, never a live endpoint. A failed probe must reject before writes and preserve any existing card/receipt; a successful probe followed by a real generation failure must still use ordinary worker failure handling. Offline preset/custom activation and ordinary gameplay remain available.

Extend `world/art/tests/test_connectivity.py` for pure cache reads, configuration mismatch and expiry using patched `_now`, never elapsed-time assertions. Keep its whole-art-package import prohibition and failed-verdict/worker-success integration test; amend the production-importer allowlist only to add `world/rules/creation_portrait.py`. Assert the request's probe runs before queue lock/transaction entry, false and true verdicts have different outcomes, a stale client cannot bypass refusal, no receipt/queue state is written on refusal, and a later fresh successful verdict admits explicit retry. No repeated recovery timer or force-probe per render.

Add barrier-controlled threaded regressions, not sleeps or latency assertions: (1) pause request B at retained-card discovery while settlement A contends, then release and prove either B rejects A in-flight or retains A's committed card; (2) contend a worker holding queue serialization with a rules mutation before its first database write, proving the mutation holds no database writer while waiting. Capture post-commit callbacks and assert their bodies run only after both lock contexts are released; include real outer-commit failure and nested savepoint rollback cases in `web/webclient/presentation/tests/test_publication_settlements.py`. The exact card/file sets, callback ordering and completed thread outcomes are the oracle; timeout values are harness safeguards, never asserted timings.

Update `docs/development/webclient-synchronization.md` for the action and draft receipt; update `finalize_player_portrait`’s docstring to distinguish activation-created policy from preexisting draft policy. Do not change blueprint policy schemas; their reserved player `str(pk)` namespace already matches this design. Keep `creation-activation-gating` unchanged; tests exercise that gate with a portrait request between save and activation.
