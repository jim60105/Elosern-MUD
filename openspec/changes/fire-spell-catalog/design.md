## Context

Data-only integration of the fire wave: the 12-node tree of `docs/lore/skill-trees/fire.md` authored into `world/skills/registry.py` + the fire rulebook rows over vocabulary that is ALL READY SHIPPED at master 0cede4c. ### D2 — The ignite rides the reaction table with a `buff_active` holder gate (consumed generic #1)

### D3 — The lava magnitude/duration lore gap (catalog-owned authored decision)

fire.md's `lava_burst` row prices the hazard qualitatively only (「每回合額外承受一次灼燒 DoT 判定」) — no magnitude, no duration. The data authority is silent, so the catalog records the derivation now: **`fire_lava`: `marker: ground`, rate hp −12 per 10 s, duration 60 s, tick_interval 10, polarity debuff.** Rationale: (a) the tree's own burn-DoT ladder is −8 (wave/ignite) / −12 (燔祭自灼) / −20 (紅蓮自灼) / −40 (紅蓮對敵) — lava is a MASTER-tier hazard and −12 is the ladder's next rung above the 術師 −8, keeping the ladder monotonic with no invented rung; (b) §3.3's 大師 band prices sustained damage at exactly −12/10 s; (c) duration 60 s follows the direct earth precedent (`earth_fissure`: marker −12/10 s, 60 s — the same master-tier ground hazard shape) and the node-table convention that lingering fields ride the tree's standard 60 s buff band. 「每回合額外承受一次灼燒判定」 is realized as the shipped marker row's per-10 s rate tick while the standing-on-it fact is true (the game's only recurring-DoT clock), exactly how earth's fissure delivers the same qualitative lore. If the lore owner later prices different numbers, this is one row edit with zero engine work; implementation authors D3's values, not re-derives them.

- **`sacrificial_flame`'s `self_heal` deletion is the wave's only verb removal** — repo-wide census found no shipped item, quest, spawn, preset or doc outside frozen history referencing it; implementation re-runs the census before editing.
- **All consumed primitives are shipped and already exercised live** (earth fissure rows + carapace rule at HEAD) — if any fails fit at implementation it is a defect in the owning archived surface, fixed there, not re-proposed here.
