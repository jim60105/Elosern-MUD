## Why

The web client is today a hand-rolled jQuery + GoldenLayout 1.x shell: about 30 `<script>` plugin files that build the entire UI imperatively over Evennia's WebSocket transport, plus a bespoke state reducer and keyboard router. It works, but the UI is hard to evolve, preview, or review, and it cannot be designed component-by-component. A complete, validated single-screen design (the Elosern 設計稿) now exists, and building to it as another pile of jQuery DOM code will not scale. We migrate the **view layer** to a Vue 3 SPA (Vite bundle + a reactive store) on top of the *existing* Evennia WebSocket transport and the *existing* DOM-independent logic modules, so the deterministic game, Telnet parity, offline behavior, and every protocol contract stay intact while the UI becomes a maintained, previewable, component-testable codebase.

- **BREAKING** – replaces the GoldenLayout + jQuery runtime shell and retires the frontend's `no npm runtime dependency` rule: npm becomes a dev/CI-time toolchain (Vite/Vue/Pinia/Storybook). The *built* page is still served entirely from the project origin and makes no remote runtime request, so the player-facing offline invariant is preserved.

## What Changes

- **New Vue 3 SPA view layer** replaces the GoldenLayout + jQuery DOM plugins. It is a Vite-bundled, self-contained application mounted into the WebClient template and uses Pinia as the strict/atomic state store. It **reuses** the existing DOM-independent logic (protocol reducer, narrative-markup pipeline, command echo, local-map model, keyboard router, choice-point and option-card logic) through ES-module wrappers; those modules and their dependency-free Node tests are kept, not rewritten.
- **Evennia WebSocket transport retained.** `evennia.js` remains the socket/transport; the Vue app subscribes to the existing OOB protocol and dispatches through the unchanged action-dispatch + allowlist. The text-only fallback path (ordinary text commands always playable) is retained for bootstrap failure and pre-JS.
- **Storybook component showcase built first.** Before any live wiring, every UI component is designed and built in isolation in a Storybook — each with documented props/events/states and a note of its 設計稿 alignment — so the full component set is divided and reviewed before the live app exists.
- **Design 設計稿 committed to `docs/`.** The validated static single-screen showcase is copied into the repository docs as the design-draft reference and linked from the docsify sidebar.
- **Build + tooling.** New `package.json` (npm, dev dependencies only: Vue, Vite, `@vitejs/plugin-vue`, Pinia, Storybook for Vue, Vitest + Vue Test Utils), a Vite config, build output served from the project origin, and mandatory CI gates for `npm ci` + build + component tests + Storybook build.
- **Shell/DOM.** The GoldenLayout mount container is replaced by a Vue mount; the page loads the Vite bundle (no jQuery, no GoldenLayout, no remote runtime request). Existing DOM contract hooks that the OOB/browser contract depends on (e.g. the focused `#action-dock` target, `target-` / `action-` item keys, panel ids) are preserved where feasible to limit browser-test churn; the rest are re-mapped to `data-testid`.
- **Text fallback.** A small dependency-free vanilla-JS text console that talks directly to the retained `evennia.js` transport is always loaded and is the authoritative text path — hidden once the Vue app mounts, retained when the Vue bundle fails to load or the OOB channel is incompatible — so the game is always playable by text and no longer depends on the jQuery `default_out`/`history`/`webclient_gui` plugins.
- **Public-contract bridge + Phase-0 contract audit.** The Vue app re-exposes the stable public façades the existing specs and browser tests depend on (`window.Elosern.narrativeInput`, `window.Elosern.actions.submit`, the keyboard-router consumption contract). A Phase-0 audit enumerates every implementation-bound contract (public façades, the WebClient plugin `onKeydown` path, DOM ids, layout-persistence keys, input path) across `openspec/specs/webclient-*` and the Playwright suite and classifies each as preserve-via-bridge or delta; the audit finalizes the exact façade surface and any additional `MODIFIED`/`RENAMED` deltas before wiring.
- **Truthful data scope.** The app surfaces exactly what the current OOB panel allowlist (art, status, context_actions, local_map, services, creation, exploration, character) and the text stream deliver. UI-only surfaces in the 設計稿 that lack a backing read model today — a dedicated Party/companion panel (bond/affinity/follow), the intimate/adult collapsible, a full inventory bag, and the event-log Toasts surface — are OUT OF SCOPE for this migration and deferred to separate OOB changes; no component invents data.
- **Amends the engine design doc.** Design decision D13 and the webclient rows that reference the GoldenLayout shell are amended to a Vue SPA on the same Evennia extension points; Telnet remains fully playable as text.
- **Docs.** `docs/` gains the design-draft page plus a frontend developer guide (build, dev server, Storybook, component testing) and sidebar entries.

## Capabilities

### New Capabilities
- `webclient-vue-application`: the Vue 3 SPA — an offline Vite bundle served from the project origin (no remote runtime request); a Pinia strict/atomic store that wires the preserved DOM-independent protocol/keyboard/markup/map logic; the Vue component tree, its mount point, and the degraded text fallback; desktop-only viewport bounds (1440×900 / 1280×720); and the preserved Evennia WS transport with text-command parity.
- `webclient-component-showcase`: the Storybook component showcase — every UI component documented and exercisable in isolation with props/events/states; a mandatory CI gate that builds the Storybook and verifies each required component is registered and documented; the designated home of the component-design phase, completed before live wiring.

### Modified Capabilities
- `webclient-desktop-shell`: the shell requirement changes from "loads a local desktop GoldenLayout shell (jQuery + GoldenLayout, `hasHeaders: false`, `.lm_header` absent)" to "loads a local Vue SPA shell (Vite bundle, component tree, self-identifying surfaces)". Every *behavioral* shell requirement is retained (required surfaces, menu-first keyboard routing, command-drawer text control, versioned browser persistence, accessible theme/controls, connection-loss control lock, narrative as the authoritative text surface, input-line divider, viewport bounds, offline load); only the mount/fallback and tab-strip scenarios are reworded from GoldenLayout to the Vue mount.
- `webclient-browser-verification`: the DOM-independent Node gate keeps zero npm dependencies (it stays dependency-free), and the mandatory quality-gate steps gain `npm ci`, the Vite build, the Vue component (Vitest) tests, and the Storybook build as required, non-suppressed steps alongside the unchanged Node gate, serial managed Playwright browser tests, the Evennia/top-level Python suites, traceability verification, and aggregate coverage.
- **Audit-driven additions (Phase 0):** beyond the two above, the Phase-0 contract audit settles any additional `MODIFIED`/`RENAMED` deltas for implementation-bound contracts it finds in other `webclient-*` capabilities (candidates: the `window.Elosern.*` façades in action-choicepoints and options-surface, and the keyboard/plugin contract in pointer-activation, the desktop-shell keyboard-routing requirement, narrative-markup, and character-creation-ui). The complete delta set is finalized by the audit before implementation.

## Impact

- **New:** `package.json` + lockfile, `vite.config.*`, `.storybook/`, a Vue source tree (components, store, ESM wrappers over the pure logic, design-system styles), Storybook stories, and the built assets directory. Node 24 is already provisioned in CI.
- **Modified:** `web/templates/webclient/base.html` (drop jQuery/GoldenLayout/plugin loads; keep `evennia.js` + the small vanilla text console + the Vite bundle) and `webclient.html` (Vue mount), `web/static/webclient/css/*` (design system from the 設計稿), `.github/workflows/quality-gate.yml` (npm build/test/Storybook gate **and** the `dist` build in the browser workspaces), `Containerfile`/`docker-entrypoint.sh` (a Node build stage so the served image has the `dist`), `AGENTS.md` (frontend build/test entry points and the Python-vs-npm split), `docs/` (sidebar, design draft, frontend guide), the engine design doc's webclient row, and — as finalized by the Phase-0 audit — the façade/persistence deltas in the touched `webclient-*` capabilities.
- **Preserved:** Evennia WS transport (`evennia.js`); the DOM-independent `js/elosern/*` logic and its Node gate; all OOB-protocol / action-dispatch / panel-allowlist *protocol* requirements; the managed Playwright runtime and localhost/determinism rules; Telnet parity; the offline-playable game.
- **Python coverage gate unaffected.** The aggregate 80% branch-coverage gate is Python-scoped to `commands`, `server`, `typeclasses`, `web`, `world`; JavaScript is covered by its own Node/Vitest/Storybook gates, so the Python gate is not diluted by JS. The only Python-side change is the template/Django wiring.
- **At-risk / effort:** the ~28 managed Playwright tests assert current DOM ids/selectors **and** the `window.Elosern.*` façades/keyboard contract; mitigated by the façade bridge + preserved contract hooks + `data-testid` re-mapping, with the Phase-0 audit settling the exact set. The `dist` must be produced in every serving environment (CI browser workspaces and the container image) or the page 404s the bundle. The largest single effort is re-expressing the imperative dock/`elosern_ui` views as Vue components bound to the shared store.
- **Deferred (separate OOB changes, not this migration):** a dedicated Party/companion data panel, the intimate/adult collapsible, a full inventory bag, and the event-log Toasts surface — none have a backing OOB read model in the current allowlist, so this change does not invent or fake them.
