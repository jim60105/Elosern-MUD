## Context

The architecture source of truth is `docs/superpowers/specs/2026-07-29-ai-mud-engine-design.md`, especially D4, D13, D14 and the single-writer boundary. Main specs are current contracts; the only other active change at proposal creation is `equipment-condition-hud-attention` (0/10 tasks).

`SkillBook.vue` currently emits practice intents only. `AppClient.vue` mounts it with no cast binding; the field-use flag renders the literal `combat`. The combat dock already supplies target cardinality, allowed-scale selection, disabled detail, keyboard navigation and cancellation. `combat.cast` rejects without an active session, so reusing that action for exploration would fail. Text `CmdCast` already routes monster targets into `initiate_field_combat`, otherwise uses `settle_out_of_combat_cast`, and rejects damaging field casts aimed elsewhere. Field settlement accepts explicit targets only. AREA monster initiation uses the named monster as an anchor and expands to all living room monsters in sorted identity order.

The HUD main spec explicitly requires a cast-syntax footer and forbids drawer-hosted router frames. This proposal replaces the footer requirements and keeps the single router by transferring cast selection to the action dock. Practice stays a bounded drawer sub-screen. Existing character descriptors remain informational; their static field-use flag is insufficient to authorize a cast.

## Goals / Non-Goals

**Goals:** A complete SkillBook-to-OOB-to-rules path; truthful preview and target identity; identical core settlement/routing semantics; accessible target selection; committed mode/resource refresh; an actual SkillBook redesign chosen and verified by the apply worker.

**Non-Goals:** New skill effects or field permission, command syntax changes, general menu redesign, a second combat router, arbitrary multi-monster/mixed-set initiation, server persistence of UI selections, a visual mockup, or any change to equipment attention/provenance.

## Decisions

### D1. Preview one selected skill through existing dispatch and publication

Add `explore.skill_preview` with exactly required `skill_key` and optional `scale`. Keys use the existing cast-key bounds (1..64); scale uses the existing closed numeric scale validator, excluding booleans, defaulting to 1.0. It selects only a `(skill_key, scale)` pair in the existing transport-and-puppet presentation sequence. The session is used solely for presentation targeting via the fixed adapter ABI, never to select a game actor. Copy the pair into presenter read context; do not expose the transport session to presenters. A direct preview-adapter call without a presentation session returns a bounded rejection without a game mutation.

This action uses the existing dispatcher lock, stale/revision guard and dedupe, and publishes `skill_use` before its result. It never casts, rolls, creates a clock/session, awards practice, or advances time. An owned active skill with unavailable use still yields a successful preview selection and an available panel with disabled reasons. Unowned/unknown/passive keys or invalid mode reject safely. Selecting an allowed scale recomputes the same panel. The browser waits for the matching result revision and matching selected skill/scale before enabling confirmation; opening and reading choices never imply execution.

The selected pair is ephemeral, reset on new epoch/puppet, and ignored outside exploration. Rebuilding a snapshot recomputes its preview from canonical state, rather than caching authorization. Closing the local flow need not send a server mutation; a retained pair can influence only an unused read model, never authorization. No preview token is required to cast. Current domain validation is always authoritative.

A full catalog-by-scale-by-target panel would multiply wire size and preview work. One selected skill fits the existing OOB envelope, while the unchanged character panel supplies book browsing. No new transport message or envelope version is needed.

### D2. Version-1 `skill_use` read model

Available form is exactly `{schema_version: 1, available: true, kind: "skill_use", skill, scale}`. `skill` contains exactly `key`, `label`, `description`, `target_spec`, `usable_out_of_combat`, `cost`, `enabled`, `disabled_reason`, `targets`, `openings`, plus optional `freeform_scales`. Labels/description and resource costs use existing bounded skill-descriptor definitions. `enabled` means at least one legal confirmation exists at the selected scale (or the NONE/SELF cast is legal); false requires a stable `{code, message}` reason, true requires null.

`targets` is the deterministic, unique list of ordinary explicit field candidates, each exactly `{identity, label, enabled, disabled_reason}`. Positive JavaScript-safe identities identify the actual present entities, including self where permitted; label is 1..128 characters; reasons use the shared bounded reason shape. NONE has an empty list; SELF has only the authenticated actor display binding and sends no target field. SINGLE/AREA list ordinary candidates in identity order with candidate-specific reasons; living co-located monsters appear only in `openings`. Do not invent ally/enemy relations for a room context.

Each opening is exactly `{identity, label, target_ids, enabled, disabled_reason}`. `identity` names the anchor monster; `target_ids` is the server-authored effective selected-target preview, one ID for SINGLE and the current full living monster set for AREA. Its label must disclose combat initiation; AREA disclosure must state that all listed living room monsters participate, not merely the highlighted anchor. No monster openings exist for NONE/SELF. A monster identity cannot be combined with ordinary target toggles. Target/opening lists and target-ID lists are bounded to 64, never silently truncated; bound/byte failures yield the common unavailable panel. The serialized full snapshot and update must stay within the existing 65,536-byte and depth-8 limits, including all other panels. Test an upper-bound selected preview in a full envelope.

`freeform_scales`, when entitled, reuses the exact existing `{scale, label, mp_cost}` descriptors and ascending unlocked-rung order. It is omitted for ineligible/non-entitled skills, with no selector or scaling hint. `cost` is the adjusted selected-scale cost, calculated on the server. Candidate and opening availability is recomputed at the selected scale, so lower-cost permitted rungs can be used when the base rung is unaffordable. Static metadata may be displayed from character descriptors; it cannot override this panel.

Common unavailable form applies before selection, outside exploration, after ownership loss or on presenter failure, with safe localized reasons. Register server schema metadata and mirrored browser versions/allowlists together, retaining every existing panel version, including whichever status version the equipment proposal lands.

### D3. One deterministic field-routing boundary

Introduce a narrow public field-cast entry under `world/rules/` and a pure field preview seam. Reuse/extract the existing command routing only where necessary; migrate `CmdCast`'s ordinary field branch and the new adapter to this entry so routing gates do not diverge. Preserve the command's trusted context handling and all existing text behavior; the browser never supplies context. No broad resolver refactor is needed.

For ordinary targets, preview/revalidation uses `RoomActionContext` and existing `preview_skill`, `revalidate_submission` and final resolver gates. For monster openings, expose a side-effect-free candidate preparation/preview from `combat_initiation.py`, sharing its explicit field permission gate, `_room_monsters`, candidate roster/context, submission shape validation and preflight with initiation. Never use a room-only preview to advertise damage, or engage temporarily to obtain a preview. Never manufacture missing effect-context values; report the existing rejection.

The public entry accepts a skill, scale and exactly one target form. It resolves ordinary lists through field settlement; monster anchors through existing initiation. A living co-located monster in a SINGLE explicit list normalizes to the opening route for trusted text parity; browser requests use the explicit anchor form described below. Monster-containing AREA lists without an anchor are rejected before settlement, not treated as arbitrary mixed engagement. The public entry enforces damage-requires-monster-target before any settlement/clock access. Final core gates remain authoritative, including explicit field permission for candidate battlefields. Do not special-case heal/buff/sexual effects to avoid combat when the anchor is a monster.

### D4. Exact `explore.cast` forms and mutation-time validation

Payload requires `skill_key`, optionally `scale`, and either no target field, `target_ids`, or `opening_target_id`. These last two are mutually exclusive. NONE/SELF carry neither; SINGLE ordinary carries one ID; AREA ordinary carries 1..64 distinct IDs in presenter order; monster opening carries exactly one anchor ID for SINGLE/AREA. Unknown fields, actor/context/cost overrides, `target_shorthand`, empty/duplicate ID lists, boolean/nonpositive/non-safe identities and nonmember scales are malformed. TargetSpec-dependent mismatches reject through shared domain validation. Reserve `flee` for its existing graphical route.

The adapter obtains only the authenticated puppet, rejects current non-exploration mode or an active combat session, re-resolves IDs from current co-located candidates using existing access/visibility boundaries, and invokes the public field entry. A tampered ordinary list containing a living monster is rejected rather than normalized by the browser adapter. No guessed key parsing, `sendText`, command execution, or globally looked-up remote targets. A stale request never reaches the adapter; a matching revision still rechecks ownership/kind, field permission, scale entitlement/resources, capability, handlers/context, target shape/presence/alive/range/faction and current mode immediately before mutation.

Preserve existing AREA filtering inside the core for present but now-invalid candidates, including rejecting an empty surviving set. A missing/remote submitted ID that cannot be safely re-resolved is rejected at the adapter boundary. Rebuild the current AREA monster line-up on initiation; never use displayed `target_ids` as a frozen roster. Revalidation can change that line-up, and the committed publication must disclose the actual outcome. Only the anchor ID is submitted.

### D5. Settlement and refresh are complete at one committed revision

The ordinary route calls `settle_out_of_combat_cast` and inherits atomic effects/resources/proficiency/coercion/planner writes plus one COMMAND-time charge and cache rollback. The monster route calls `initiate_field_combat` and inherits engagement/opening-action atomicity, skip-safety/cache restoration, and accumulated COMBAT time without a separate COMMAND charge. A rejection performs no roll, resource/time spend or session creation.

Render normal field EventLogs/notifications and combat opening/terminal results only after the relevant outer commit, using existing safe renderers and offline plain-text fallback. Use a full snapshot for `explore.cast` completion, including rejection/error recovery, rather than guessing its affected panels: time advancement and initiation/terminal settlement can touch status, character/proficiency, party, objectives/quests, exploration, services, local_map, art, context_actions and mode. Publication precedes the result and the shared lock waits for its declared revision. Preserve ordinary combat action partial-update behavior.

When initiation returns an ordinary round, pass its frozen round record to the existing `combat_beats` presenter in that completing snapshot as the combat adapters do. For this new field action, use ordinary narrative paging and canonical values without beat autoplay; the existing beat contract autoplays only `combat.cast`, `combat.flee` and `inventory.use`. Do not add a new playback trigger or infer pre-round HP for participants first seen in this snapshot. Later combat actions continue their existing beat behavior. Instant terminal initiation remains exploration and shows terminal aftermath with no transient fabricated combat view.

### D6. One cast navigation owner; concrete UI design belongs to apply

SkillBook remains the character-backed browsing/practice surface. In exploration its use intent opens the authoritative preview and transfers the cast flow to the existing dock/router, closing the modal book before the dock owns focus. The exploration scene-overview root and ordinary root inventory remain unchanged; this is an entry handoff from the book, not a new root skill menu. Cancellation/back restores the book and invoking skill focus when still valid, without executing. No dock renderer or second router is hosted in the drawer. NONE/SELF still require explicit final confirmation; SINGLE/AREA and any allowed scale are selected using server choices. Arrows, Enter, Space for AREA toggles, and Escape/back must have one active owner and a truthful hint. Apply chooses the detailed focus transitions and exact composition within these ownership constraints.

In combat, book use closes the book and focuses the existing combat Skills entry; it neither emits `explore.skill_preview`/`explore.cast` nor submits `combat.cast`. The combat dock thereafter supplies its own descriptors/selection/scales. Do not auto-select or cast a remembered book key. In other modes field use is unavailable, while normal browsing/practice mode rules remain unchanged.

The apply worker MUST read `skill://game-ui-design`, `skill://ui` and `web/webclient-app/AGENTS.md`, then document its concrete visual/interaction design before editing UI. It owns layout, styling, component composition and detailed interactions; there is no proposal-time mockup. The outcome must visibly improve skill discovery, readable details and use-versus-practice distinction, preserving active/passive tabs, bounded search, authored category/group ordering and empty/unavailable semantics. Respect existing shared opaque drawer/header, no art column, tokens, reduced motion and desktop geometry. Remove or reconcile duplicate `.elosern-root` CSS overrides. Truthful field capability uses Traditional Chinese wording such as `可於戰鬥外使用`; it is independent from enabled state and any monster-opening warning. A permitted-but-disabled skill must not look currently executable. Passive or unknown rows never dispatch a cast.

### D7. Lifecycle and verification ownership

Transport loss, epoch/puppet change and invalidating committed mode changes clear local cast targets, confirmations and preview association. A newer panel removes vanished candidates and invalid scale/skill choices; confirmation never proceeds while a newly selected scale preview is pending. Shared locks apply to practice and casting, and rejection remains readable exactly once through the existing action feedback path. Reconnect adopts canonical state without automatic resubmission, including uncertain-outcome notice after a lost cast result.

Add synthetic behavior tests beside their owners, dependency-free Node protocol/router tests, component/story coverage and isolated localhost Playwright journeys. Test NONE/SELF/SINGLE/AREA, scales (including synthetic field-eligible scalable skills), ordinary and monster routes, duplicate names with distinct identities, disabled/stale/tampered requests, rollback, normal/instant-terminal handover, practice, combat handoff and reconnect. No live AI/image requests. Register every new/moved non-browser module in exactly one `.github/evennia-shards.json` shard and every new browser method/class in `.github/browser-shards.json`. Obtain canonical traceability IDs with `tools.spec_traceability list` once deltas are synchronized; annotate substantive tests without guessed IDs or skipped stand-ins.

## Risks / Trade-offs

- On-demand preview adds a read-only round trip before use and when changing scale. Use the existing pending lock and bounded feedback, without predicting permission locally. It limits wire size and shares stale/deduplication behavior.
- Monster AREA opening differs from ordinary multi-selection. Show the complete server-defined enemy set and consequence; never describe an anchor as the sole affected monster.
- Field settlement can change many surfaces. Full completion snapshots deliberately favor correctness over a fragile partial affected-panel guess.
- Current rule preview and initiation code need a narrow pure candidate seam. Extract only that seam and routing authority; broader mechanics and cleanup remain outside this change.
- Shared files with `equipment-condition-hud-attention` require hunk reconciliation. This change does not alter provenance, status version or condition attention; cast-caused resource/condition changes must render through whichever canonical status contract is present.

## Cutover and Open Questions

Cut over registry, schemas, client consumers, fixtures and footer contracts in one feature delivery. No migration, compatibility alias or old graphical cast path remains. Text casting is intentionally unchanged. There are no unresolved gameplay/API questions; concrete visual and detailed interaction decisions are explicitly owned by the apply worker and must be recorded before implementation.
