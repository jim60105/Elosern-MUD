# Spec Delta

## ADDED Requirements

### Requirement: Actual party combat acceptance completes skills items drafts and reconnect
A deterministic localhost runtime journey SHALL use the actual UI to command multiple actors, execute a companion own skill and item, revise an earlier confirmed choice, resolve on the final confirmation and observe a fresh next round. It SHALL reconnect with an unfinished persistent draft and prove no missing commands or prior intent are replayed.

#### Scenario: Full member journey
- **WHEN** the runtime browser journey selects and revises member commands across skill and item rounds
- **THEN** canonical state shows actor-local resource/item use, final-only automatic resolution and restored unfinished progress without extra time

#### Scenario: Existing UI contracts
- **WHEN** the journey runs at both accepted desktop viewports
- **THEN** the centered card/stage target/warning contracts remain intact and companion SELF uses the commanded figure


### Requirement: Actual party exit acceptance covers cancellation committed outcomes and text parity
Isolated real-runtime encounters SHALL exercise retreat and surrender cancellation and committed outcomes, stale/repeated confirmation, carried downed companions, failed-retreat enemy/upkeep behavior and hostile/exam consequences. An exercised text-client path SHALL demonstrate explicit actor command and exit confirmation parity.

#### Scenario: Party exit runtime evidence
- **WHEN** browser and text journeys cancel and confirm exits in isolated encounters
- **THEN** cancellation preserves the whole draft, accepted outcomes affect the whole party and time/settlement apply once with existing aftermath

#### Scenario: Complete batch acceptance
- **WHEN** all implementation changes request assembled feature acceptance
- **THEN** missing companion items/tactics, missing text/browser paths or absent selected real weapon/encounter evidence blocks acceptance; full managed browser and complete trace evidence remain CI-owned
