## Context

See proposal.md for motivation. The in-process txt2img client already builds request dictionaries with omit-when-default sampler, scheduler, and styles fields. A1111/Forge accepts request-scoped top-level `do_not_save_samples` and `do_not_save_grid` boolean fields (default false). The current main capability owning txt2img behavior is `internal-art-worker`, so its delta owns the new request contract; `settings-environment-overrides` also needs a delta because its env-backed inventory is explicitly exact.

## Goals / Non-Goals

**Goals:** Suppress sd-webui's own generated sample and grid copies when requested, while retaining the engine's normal art processing and storage and existing typed environment semantics.

**Non-Goals:** Change the engine's art-store policy, delete existing server outputs, enforce a remote server's implementation, add a player command, alter compose wiring, or introduce compatibility layers or migrations.

## Decisions

1. Declare `ART_SD_SERVER_RETAIN_IMAGES = _env_bool("ART_SD_SERVER_RETAIN_IMAGES", True)` immediately after `ART_SD_PREPIN_SAMPLES_FORMAT` in `server/conf/settings.py`. Positive naming follows `ART_REMBG_ENABLED`; `True` preserves current request behavior. Reuse the boolean helper's case-insensitive word families, empty/unset defaults, named invalid-value error, and existing default < environment < secret-settings precedence.
2. In `build_txt2img_request()`, only when the setting is false, add `request["do_not_save_samples"] = True` and `request["do_not_save_grid"] = True`. When true, omit both entirely rather than sending explicit false values. These fields are request controls, not `override_settings` members. Leave the existing PNG override, response validation, conversion, and store path untouched.
3. Never mutate `/sdapi/v1/options` for this switch. Unlike `ART_SD_PREPIN_SAMPLES_FORMAT`, whose opt-in pre-pin persistently mutates a shared server's samples-format default, retention is scoped to each txt2img call and cannot change another client's persistent server settings.
4. Add the variable to `server/conf/test_settings.py`'s env-pop list. Extend the existing request-builder tests with default omission and false-to-both-true cases; extend the subprocess tables in `server/conf/tests/test_env_overrides/_support.py` and their existing default/coercion/error tests in `test_defaults_coercion_and_fail_closed.py`. Extend `test_seam_precedence_derived_and_sanitization.py` for inherited false and invalid-word bootstrap isolation. Reuse an existing successful-generation/store test under disabled retention, and annotate establishing tests using `covers_requirement`. The package layout replaces the originally planned single-module path without adding a test module.
5. Add a commented entry to `.env.example`'s sd-webui tuning section and increment the header variable count. Add type/default/behavior documentation near `ART_SD_PREPIN_SAMPLES_FORMAT` in `docs/development/settings-and-environment.md` and `docs/gm/prompts.md`, preserving both tables' existing zh-tw language style. State that only server copies are affected and settings changes require the usual restart. `compose.yaml` already uses `env_file: .env`, so no explicit `environment:` entries are needed. No player commands or new test modules means no command-doc or shard-manifest changes.

## Risks / Trade-offs

- An exotic server may ignore the fields: the fallback is current server retention, not lost engine art. This switch requests suppression; it is not a guarantee of remote deletion or a privacy enforcement mechanism.
- The server still returns generated bytes to the engine, which persists them normally. Disabling server retention does not disable local storage.
- Shared settings/test/doc inventories must stay synchronized; the environment delta includes the complete existing requirement so archive-time synchronization preserves all unrelated contracts.
