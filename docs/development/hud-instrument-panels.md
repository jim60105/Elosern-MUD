# HUD 儀表式面板設計準則（無框面板）

本文件定義 WebClient 的「儀表式面板」樣式。這種面板沒有外框與不透明底色，以羽化的墨色底、黃銅掛件與細筆畫資料呈現，視覺上固定在舞台結構上。重構其他 HUD 面板時，請依本文件的規則套用同一套樣式。

**參考實作：** 生命值面板（vitals dock），由 `web/webclient-app/components/` 的 `StatusPanel.vue`、`ConditionChips.vue` 與 `VitalsTrack.vue` 組成，來自 OpenSpec 變更 `vitals-bar-redesign`。
**適用範圍：** 疊在舞台上的 HUD 面板。視窗類介面（隊伍視窗、商店、圖庫）使用共用視窗基礎元件，不適用本文件。
**優先順序：** 變更專屬的 OpenSpec 工件與 `web/webclient-app/AGENTS.md` 的設計方向優先於本文件。

## 設計前提

HUD 面板是安裝在舞台上的儀表，設計時把它當成舞台的一部分。動手調整樣式之前，先回答三個問題。

1. 玩家看一眼要讀到什麼？只有這項內容使用最高亮度。
2. 哪些文字能改用形狀或色相表達？把它改成圖示或顏色，文字移到無障礙名稱。
3. 哪些內容玩家只在需要時才看？放進 hover 與 focus 觸發的提示框，或放進可展開的區塊，不常駐在畫面上。

生命值面板的答案如下。數值是一眼要讀到的內容，所以放大顯示。「這是哪一條量表」由圖示形狀與色相表達，「生命」「魔力」「耐力」三個標籤移到無障礙名稱。狀態細節放進提示框。

## 輪廓：不使用方框

面板本體不使用完整邊框、圓角矩形與陰影。帶髮絲線邊框的矩形看起來像網頁表單。

底色使用共用的面板墨色 `var(--panel)` 與共用的背景模糊，再用遮罩羽化。內容起點（脊線）處最濃，往開放側逐漸變淡，讓場景從邊緣透出來。

```css
.panel { position: relative; isolation: isolate; }

/* Chrome lives on a pseudo-element so the content stays unmasked. */
.panel::before {
  content: ""; position: absolute; inset: 0; z-index: -1;
  background: var(--panel);
  backdrop-filter: blur(calc(9px * var(--ui-scale)));
  -webkit-mask-image:
    linear-gradient(90deg, #000 0 52%, rgba(0, 0, 0, .55) 78%, transparent),
    linear-gradient(0deg, #000 0 62%, transparent);
  -webkit-mask-composite: source-in;
  mask-image:
    linear-gradient(90deg, #000 0 52%, rgba(0, 0, 0, .55) 78%, transparent),
    linear-gradient(0deg, #000 0 62%, transparent);
  mask-composite: intersect;
}
```

淡出方向要背對錨定邊。生命值面板立在底部訊息帶上並貼著左側留白，所以往右、往上淡出。右上角的面板則往左、往下淡出。

面板刻意採用不對稱輪廓，錨定側是有結構的硬邊，開放側是羽化的軟邊。

## 黃銅掛件（唯一的裝飾）

每個面板都掛在一組黃銅配件上。配件沿用訊息帶既有的裝飾語彙，讓整個 HUD 讀起來是同一件物品。

- 菱形飾件 `var(--band-ornament)` 放在兩條錨定邊交會的角落，生命值面板放在左上角。
- 一條 1px 的頂線從菱形沿上緣延伸，顏色由 `var(--band-edge)` 經 `var(--band-edge-dim)` 漸變到透明，在寬度約 70% 處結束。
- 一條 1px 的脊線從菱形沿錨定側往訊息帶延伸，逐漸淡出。
- 三者以 `background` 圖層畫在同一個 `::after` 虛擬元素上。內容的內距要避開脊線，生命值面板的脊線在 15px，左內距為 26px。

規則有四條。線條只用 1px 髮絲線。金色只取自 band-edge 系列的設計標籤（design token）。每個面板最多一個菱形。裝飾不得跨過內容。

## 以筆畫呈現資料

- 量表是 4px 的細線，彼此幾乎貼齊，只留 1px 接縫。不使用 10 到 16px 的圓角長條。
- 每條線的遠端收成尖角，寫法為 `clip-path: polygon(0 0, calc(100% - 10px) 0, 100% 50%, calc(100% - 10px) 100%, 0 100%)`。
- 後面的線依序略短，生命值面板的魔力線短 5%，耐力線短 10%。整組線條像筆畫一樣散開，不會齊頭結束在同一條硬邊上。比例仍在各自的線條內計算，數值不會被誤報。
- 空的底槽是低透明度的紙色暈染，使用 `rgba(paper, .07–.16)` 的漸層，不使用深色方塊。接縫由整組線條上的一個 `drop-shadow` 產生。
- 色盲使用者需要的差異保留在紋理上，例如耐力線的斜紋，不能只靠色相區分。

## 數值

- 筆畫上方放一列讀數，順序與筆畫一致。整列從脊線開始靠左排成一句話，間距約 18px，不使用 `space-between` 撐滿寬度。
- 每筆讀數依序為圖示、目前值、最大值。圖示為 11px，帶形狀與該量表的色相。目前值使用 `--paper-50`、`--text-sm`、`--f-mono`、字重 600，並設定 `tabular-nums lining-nums`。`/ 最大值` 退到 `--paper-500`、10px。
- 文字加上 1px 的深色陰影 `0 1px 1px rgba(0, 0, 0, .8)`，在任何圖片上都能維持邊緣銳利。
- 警示狀態要同時改變文字與顏色。目前值轉為 `--crit`，讀數旁加上一個帶印章框線的小標籤「危險」。不得只靠顏色表達。
- 數值異常變長時，整列換行，不得溢出。

## 圖示與按需顯示的細節

狀態圖示是只有字符的按鈕，沒有膠囊外形、填色與邊框。嚴重程度以色相加上不同形狀表達（▲ ◆ ▽ ▼ ✕）。點擊區為 22px。靜止時 `opacity: .86`，hover、focus 或展開時為 `1`。作用中的圖示下方有一條 10px × 1px 的黃銅短線，顏色為 `--gold-500`。筆畫較細的字符（例如 ✕）使用較重的字重，讓每個字符的視覺份量相同。

圖示列要做視覺對齊。點擊區內部有留白，所以圖示列以負邊距往左、上、下收回（`margin: -3px 0 -2px; margin-left: -5px`），讓字符中心對齊下方的讀數圖示。

提示框沿用導覽列的墨色底板，使用 `--surface-panel`、`--band-edge-dim` 髮絲線邊框與 `--radius-sm`，並有一個指向來源圖示的金色小尖角。內容第一行是襯線字體 `--text-sm` 的標題與字符，接著是使用等寬數字的細節行。

提示框的行為請照下列規則實作。

- 作用中的控制項帶有 `aria-describedby`，提示框帶有 `role="tooltip"`。
- hover 與 focus 都能開啟。
- 指標離開、失去焦點、按下 Escape、捲動或視窗縮放、資料消失、父面板隱藏時都要關閉。
- 只有在提示框開啟時才攔截 Escape。
- 面板位於捲動容器或帶 transform 的祖先元素內時，使用 `<Teleport to="body">`，並依控制項的 `getBoundingClientRect()` 以 `position: fixed` 定位。

圖示數量超過上限時，只顯示上限內的圖示，再加一個 `+N` 圖示。點開後，其餘項目以髮絲線分隔的列直接排在面板的版面流中，內容與提示框相同。

## 版面與幾何

- 面板錨定在所屬的舞台結構上，並往遠離該邊的方向成長。生命值面板立在訊息帶上緣，以底部為錨點，受 `max-height` 限制，超出時內部捲動。
- 寬度是一個設計標籤，例如 `--vitals-dock-w: 25vw`。共用同一條邊的相鄰元件要從同一個設計標籤推導位移，例如指令列的起點是面板寬度加 32px。同一個數字不得手動複製到兩個地方。
- 維持既有的圖層順序，島狀元件為 4，訊息帶為 5，指令列為 6。不得為了避開裝飾而提高面板的圖層，面板要和裝飾互相配合。
- 幾何定義有兩份，分別在 `HudFrame.vue` 與 `styles/app-shell.css`，兩者必須同步。新增一個同時讀取兩份原始碼的單元測試來固定這項關係。

## 動態

- 面板從錨定邊出現。底部錨定的面板往上升起，在 enter-from 與 leave-to 使用 `translateY(+shift)`。頂部錨定的面板往下落。
- 只使用設計標籤，包含 `--motion-reveal`、`--motion-shift-sm` 乘上 `--motion-travel`、`--ease-enter` 與 `--ease-exit`。不使用彈跳與過衝。圖示透明度、黃銅短線、提示框淡入這類小型回饋使用 `--motion-fast`。
- 動態等級為 `reduced` 時保留淡入淡出並移除位移。等級為 `off` 時沒有 CSS 過渡階段，寫法為 `:css="motionLevel !== 'off'"`。

## 設計標籤紀律

- 顏色只使用既有的設計標籤，或既有設計標籤顏色的 `rgba()` 形式。`--ink-950` 為 11, 13, 16；`--paper-100` 為 231, 224, 209；`--gold-400` 為 228, 200, 142。不新增色相。
- 每個長度都寫成 `calc(Npx * var(--ui-scale))` 或視埠相對單位。1px 髮絲線維持 1px。
- 會留在畫面上的標題與標籤使用 `--f-serif`，數字使用 `--f-mono`，內文使用 `--f-sans`。
- 由 script 設定的 CSS 自訂屬性，在樣式表中要帶備用值，例如 `var(--tip-tick, 50%)`。Node 閘門會拒絕未定義的屬性。

## 無障礙檢查清單

- 每移除一個可見標籤，就把該標籤移到無障礙名稱，使用 `role="group"` 加 `aria-label`，或按鈕本身的 `aria-label`。
- 裝飾圖層使用虛擬元素（`::before`、`::after`），或加上 `aria-hidden`，例如尾端的裝飾線。
- 指標能到達的項目，鍵盤也都能到達。焦點顯示全域的金色雙環。
- 隱藏的面板使用 `display: none`，讓它離開 Tab 順序。隱藏之前要先把焦點移到其他位置。

## 實作流程

1. 先建立結構與測試。`data-testid` 保持穩定，內容搬移時 `data-testid` 跟著移動。
2. 執行 Storybook，在 1920×1080 與 1280×720 兩種尺寸下，對元件的 story 與完整外殼的 story 截圖。使用 `agent-browser` 截圖，再用 PIL 裁切放大檢查。
3. 以視覺判斷結果。檢查字符周圍的留白（點擊區會帶來看不見的內距）、邊緣對齊，以及最小文字在最亮填色上的對比。
4. 以小幅度反覆修飾。在程式碼註解中寫下每個選擇為什麼比較好讀。
5. 通過所有閘門，包含 `pnpm test`、Node 閘門、`openspec validate --strict`、`tools.contract_gate`、`build-storybook` 加 `showcase-coverage`，以及 `git diff --check`。新增的瀏覽器測試方法必須登錄在 `.github/browser-shards.json`。

## 套用到其他面板的步驟

1. 選定錨定邊，在該處放脊線與菱形，往開放側羽化。
2. 移除方框，包含邊框、圓角、陰影與不透明填色。
3. 減少文字。標籤改為圖示加無障礙名稱，細節移到提示框或可展開區塊。
4. 把數量改寫成收尖的細筆畫，加上一列等寬讀數。
5. 作用中的項目以黃銅短線標示。金色只用於髮絲線。
6. 動態從錨定邊出發，只使用設計標籤。
7. 截圖，以視覺判斷修飾，並在註解中記錄理由。
