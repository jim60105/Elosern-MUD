# 技能系譜設計總覽

本分類與 [魔法技能體系](/lore/magic-system) 共同構成魔法系統唯一、完整、最新的設計。前者交代世界觀框架與各屬性的核心哲學，本分類逐一列出每個屬性、每個節點的名稱、前置條件、熟練度門檻、資源消耗與威力數值，是下一階段程式實作要直接對照寫入 `SKILL_REGISTRY` 的權威資料。

角色卡（`tmp/story_settings/character/`）中屬於特定角色的專屬魔法（例如各種「主宰」稱號技能），已納入對應屬性頁面的系譜之中，以「神格節點」的形式呈現它們在系譜樹上的位置與所需熟練度。例外是**自創型神之秘法**（如悠奈的性愛系統）與**單節點既知秘法**（狀態偽裝、統御術）。兩者同屬系譜外的孤立節點，由取得事件直接授予，見 [神之秘法系譜樹](/lore/skill-trees/divine-mystery) §0。

## 1. 系譜樹的機械規則（複習）

以下規則已經由 `world/rules/progression.py` 實作，設計新節點時必須遵守，才能在下一階段直接落地：

- **成長只有一種貨幣**：技能的「使用熟練度」。每次實際使用一個主動技能，該技能自身累計 `SKILL_PRACTICE_XP_PER_USE`（現行值 1.0）× 種族學習倍率（人類 1.0、獸人 1.0、精靈 10.0）× 屬性親和倍率（親和屬性 1.1、非親和屬性 0.9、非元素技能 1.0）× 當下的成長加成（如統御術授予的加成）。熟練度等級 `= floor(累積 XP / 50)`。
- **前置條件（`SkillPrerequisite`）**：`(skill_key, min_proficiency)`。要使用某技能，除了要「擁有」它本身，還必須擁有其宣告的每一個前置技能，且該前置技能的熟練度 ≥ 門檻值。擁有（ownership）本身不受此限，匯入角色、NPC 建構、統御術授予都可以直接給予 ownership；受限制的是「能不能實際使用」。
- **結構是可分支、可匯合的 DAG**：一個技能可以同時是多條分支的前置（一個節點養出兩個、三個甚至更多下一階段技能），一個技能也可以同時要求兩個以上的前置（多條分支匯合成一個節點）。兩種語意的機械規則完全相同，不特別區分。
- **樹冠上限（cap）**：任一節點的熟練度上限 = 消耗它的所有邊之中，`min_proficiency` 的最大值；如果沒有任何技能以它為前置（樹冠／葉節點），上限固定為 `PROFICIENCY_TIP_CAP`（現行值 10）。熟練度衝頂後練習不再累計，介面顯示「見頂」。
- **同一時鐘刻只計一次**：同一施法者、同一技能、同一目標，每個世界時鐘 tick 只累計一次熟練度，避免對著空氣重複施放刷等。
- **五個位階稱號（學徒／術師／大師／賢者／主宰）現在只是資料標籤**，已經退出機械門檻；解鎖條件完全由系譜前置決定，不再看角色的全域魔法等級。理論上一個角色可以先點滿某條分支的「主宰」節點，卻完全不會使用其他屬性的「學徒」節點，只要他滿足的是系譜前置而非全域等級。
- **精通被動屬於系譜外被動**：`fire_mastery` 這類「屬性精通」被動技能屬 PASSIVE，沒有任何東西會「使用」它，因此不計入前置系譜，只能透過匯入、劇情授予或統御術取得。
- **例外：神之秘法走「鑽研制 + 消化節拍」**（設計拍板，尚未在 `world/rules/progression.py` 實作）：神之秘法的使用零資源成本（精神力未數值化），為防止連發刷穿解鎖，其**節點取得**改由自主鑽研的時間推進授予、**深化熟練度**每個秘法每日只有第一次「有意義使用」累計。詳見 [神之秘法系譜樹](/lore/skill-trees/divine-mystery) §0.1。

### 1.1 熟練度等級 ↔ 實際使用次數換算

每個節點表格裡的「前置條件」只寫 `Lv.N` 這種抽象標籤，要回答「玩家得把上一階魔法打幾次才能解鎖下一階」，就得套上面的公式反推。達到 `Lv.N` 需要累積 `50 × N` 點原始 XP，除以對應的倍率就是需要的使用次數（無條件進位，因為當次使用未滿一次也要算一次施放）。下表列的是本分類八屬性系譜實際用到的四個門檻值（Lv.3／5／8／10），換算成兩種代表性情境。「人類，對該屬性沒有親和」是最保守、最常見的情境，「精靈，對該屬性有親和」則是最快的情境：

| 門檻 | 累積 XP | 人類／獸人・無親和 | 精靈・有親和 |
| --- | --- | --- | --- |
| Lv.3 | 150 | 167 次 | 14 次 |
| Lv.5 | 250 | 278 次 | 23 次 |
| Lv.8 | 400 | 445 次 | 37 次 |
| Lv.10（樹冠上限） | 500 | 556 次 | 46 次 |

也就是說，一個對火屬性沒有親和的人類冒險者，要把「火焰箭」打滿 167 次才能解鎖「火球術」；換成對火屬性有親和的黑暗精靈，只要 14 次。這個十倍以上的差距，就是「精靈學什麼都快」在系譜樹上的具體樣貌。

上表只適用於人類、獸人、精靈都能學習的元素魔法。[神之秘法系譜樹](/lore/skill-trees/divine-mystery) 只有精靈能學，不存在「人類版本」的換算，該頁換算只用精靈的學習倍率（×10.0），不套用上表。

## 2. 節點資料表欄位定義

以下欄位是每個系譜節點必須交代清楚的完整規格，各屬性頁面的表格都採用同一組欄位：

| 欄位 | 說明 |
| --- | --- |
| Key | 技能的英文識別碼，供未來寫入 `SKILL_REGISTRY` 時直接使用 |
| 名稱 | 正體中文顯示名 |
| 前置條件 | `技能名 Lv.N`，多個以「＋」連接代表匯合（AND）；無前置代表樹根 |
| 解鎖所需使用次數 | 把前置條件的 `Lv.N` 換算成實際施放次數（見 §1.1），格式為「人類／獸人・無親和：N 次｜精靈・有親和：N 次」；樹根節點寫「無前置，取得即可用」 |
| 位階 | 學徒／術師／大師／賢者／主宰／神格，資料標籤（神格是本分類新增的第六個標籤，見 §4） |
| 目標 | 單體／範圍／單體(自)／範圍(友) |
| MP | 施放消耗，落在 §3 的位階成本帶內 |
| 威力係數 | 見 §3.2，套用在傷害／治療公式上的倍率；自我增益／控制技能改標「效果」欄描述數值 |
| cap | 由消耗此節點的邊反推的熟練度上限；樹冠固定 10 |

## 3. 數值公式

現行 `world/rules/combat.py` 的傷害公式是：

```
命中判定通過後：
攻擊值 = 施法者 magic_power（含裝備加成）
基礎量 = round(攻擊值 × 命中倍率) − 目標防禦力
最終傷害 = max(基礎量, 傷害下限)
```

這個公式本身**沒有反映「哪一個法術」**。同一位施法者的學徒級火焰箭和主宰級焚世之焰，在命中判定完全相同時打出的數字會是一樣的，差別只有 MP 成本。位階越高的法術除了更貴之外，理應更強，因此本設計引入「威力係數」：

```
基礎量 = round(攻擊值 × 命中倍率 × 威力係數) − 目標防禦力
```

治療沿用既有公式（同樣套用威力係數）：

```
治療量 = round(攻擊值 × 治療倍率 × 威力係數)
```

| 術師 | 16–30 | 20–28 | 26–34 |
| 大師 | 31–70 | 35–48 | 45–60 |
| 賢者 | 71–90 | 65–85 | 80–110 |

| 位階 | 單體係數 | 範圍係數 |
| --- | --- | --- |
| 學徒 | 1.0 | 0.7 |
| 術師 | 1.4 | 1.0 |
| 大師 | 2.0 | 1.4 |
| 賢者 | 2.8 | 2.0 |
| 主宰 | 4.0 | 2.8 |
| 神格 | 5.5 | 3.8 |

「處決級」「毀滅級」等既有法術描述詞維持原意，處決級代表對單體套用威力係數後**無視防禦力扣減**（直接以基礎量作為最終傷害，對高防禦目標特別有效）；毀滅級代表對範圍套用威力係數的同時額外附加一個小比例（10%）的最大生命值傷害，代表這類法術連堅固的防禦也無法完全抵消。

### 3.3 控場／增益數值帶

現行 `buffs.yaml` 的減益／增益數值大多是不分位階的固定值（例如任何來源的灼燒都是每 10 秒 −5 HP）。本分類統一補上位階級距，供之後改寫 `buffs.yaml` 時對照：

| 位階 | 持續性傷害（每 10 秒） | 屬性增減益上限（如防禦、敏捷） | 控制效果持續時間 |
| --- | --- | --- | --- |
| 學徒 | −5 | ±3 | 15 秒 |
| 術師 | −8 | ±5 | 20 秒 |
| 大師 | −12 | ±8 | 30 秒 |
| 賢者 | −18 | ±12 | 40 秒 |
| 主宰 | −28 | ±18 | 60 秒 |
| 神格 | −40 | ±25 | 90 秒 |

持續性傷害的 `tick_interval` 一律沿用既有的 10 秒；控制效果（束縛、麻痺、凍結、定身、恐懼）的 `duration` 用上表最右欄。

## 4. 戰鬥資源配給制（動詞獨佔憲法）

八棵屬性樹共用同一組戰鬥動詞（傷害、增益、減益、控制、治療……）。若不做配給，動詞會在多棵樹之間無聲漂移（防禦四家、控制六家、速度增減三家、治療三家），玩家從效果數字根本分不出屬性身分。本節把配給寫成憲法，**所有新節點設計（含神格節點、〔提案〕被動、未來分支）都必須先過本節的配給檢查**。

### 4.1 四條憲法條款

1. **傷害與命中判定是公共財**。每棵樹的根節點都是傷害法術；命中／迴避的判定層是引擎既有規則。公共財不發牌照、不佔獨佔額度。
2. **每個屬性恰好獨佔一個動詞**（見 §4.2 配給表）。其他屬性只能把該動詞當修飾語（一句話附加效果），不得當本體（成條的支線）。
3. **同軸雙極合法**。同一資源的己方極與敵方極歸同一主：風同時擁有加速與減速（時速兩極）、雷同時擁有己方額外行動與剝奪敵方行動（回合兩極）、風同時擁有己方命中與敵方命中減（命中軸兩極）。同軸雙極不算重疊。
4. **每棵樹保留 1 個離經額度**。允許一個跨動詞的敘事節點（現行使用者：光的聖裁路線，光自願放棄的動詞是對不死系的處決）。離經節點必須在該樹頁面明文標記，不得作為漂移的藉口。

| --- | --- | --- | --- |

### 4.3 命名風格規範

本作的語域是西方奇幻 JRPG（劍與魔法、教會與神祇、精靈與龍），不是武俠、仙俠或日式中二。節點名稱（含未來一切新節點、神格節點、〔提案〕被動）必須落在這個語域內：

| 禁止語域 | 例 | 替代方向 |
| --- | --- | --- |
| 武術／仙俠招式的階級後綴（「·壞」「·絕」「真·」「·宗師級」） | 疾雷連擊·壞、暗影劍舞·絕 | 用位階欄表達強度，名稱只留意象：「碎雷連擊」、「暗影終劍」 |
| 華語宗教／刑律／節氣／古典詞彙 | 業火、凌遲、冥府、歡喜、霜降、永夜、護體 | 譯入奇幻語域：地獄之火、之刑、冥界、至福、凝霜、長夜、護罩 |
| 日式漢字直譯腔 | 真·○○、○○改（如「Photon Drive」式的漢字堆疊） | 名稱＝意象＋法術類型（湮滅、審判、詛咒、庇護） |

判準一句話：**把它唸給一個只玩過《Dragon Quest》《Final Fantasy》與《 DARK SOULS》中文版的人聽，不會覺得這招該出現在《金庸群俠傳》裡。** 既有節點已全數照此規範重排；中文名稱與英文 Key 的語意同步（例：`frost_mire` 凝霜泥沼、`void_annihilation` 虛空湮滅）。

### 4.4 三項邊界裁定（已拍板）

- **牆歸冰**：牆的本質是限制動作（擋路、強迫繞行、困難地形標記），歸冰的動作動詞；一切固定防禦數字只從土樹與其附魔產出。
- **燃身換爆發**：治療為光的獨佔動詞。燔祭焰與紅蓮神格以「點燃自己」施展：對施法者掛灼燒 DoT，換取當擊威力係數上浮。
- **恐懼留暗**：物理性靜止歸冰、心理性靜止歸暗，兩者本質是 buffs 層的獨立狀態鍵，玩家從敘述即可分辨來源。

## 5. 「神格」：本分類新增的第六個位階

原始設定沒有交代「主宰」之上是否還有更高的境界，但精靈的壽命、獸人的部族傳說與人類的宗教，都暗示著三位曾經真實存在的神祇留下了血脈之外的痕跡。每個屬性系譜樹在兩個既有的「主宰」節點（單體與範圍）之上，都新增一個**神格節點**。同時把兩條主宰路線都磨練至系譜上限（Lv.10），是匯合出這個屬性真正極限型態的唯一條件。神格節點是本分類新增的內容，目前沒有任何已知角色達到這個境界，正好呼應世界觀「精靈中的異數」與「未解之謎」的敘事空間，留給劇情揭曉誰、或是否有人，曾經觸及神格。

## 7. 非魔法分支

以下分支的技能形狀與元素魔法不同，有的走 SP 而非 MP、有的屬 PASSIVE 等被動形態、有的完全無法習得，因此頁面結構各自對應其性質，不強行套用同一套系譜模板：

| 分支 | 頁面 | 性質 |
| --- | --- | --- |
| 武藝 | [martial-arts](/lore/skill-trees/martial-arts) | 完整系譜樹，消耗 SP、位階詞彙獨立於魔法（見習／熟練／精鋭／名家／巨匠／傳奇） |
| 身心強化 | [enhancement](/lore/skill-trees/enhancement) | 全 PASSIVE，無系譜，改列取得條件，含「跨系譜自動授予」設計 |
| 身法 | [movement](/lore/skill-trees/movement) | 混合：風元素自我增益走系譜、飛行術／瞬步是 PASSIVE、空間扭曲走神之秘法系譜 |
| 天賦異能 | [innate-gift](/lore/skill-trees/innate-gift) | 完全無法習得，改列已知類型與取得條件 |
| 雜學秘術 | [utility](/lore/skill-trees/utility) | 三種族可學的技術系譜：鑑定／儲物兩條小型系譜（狀態偽裝、統御術已改歸神之秘法） |
| 情慾秘術 | [sexual-act](/lore/skill-trees/sexual-act) | 僅說明分類位置與解鎖骨架，不展開招式內容 |
