# 跨系譜解鎖：通用規則表

系譜前置（`SkillPrerequisite`）回答的是「**這條樹裡面**，要爬到下一個節點需要什麼」。它天生只能在一棵樹內部連線，而且只管「能不能用」，不管「有沒有」。

本頁定義的是另一個軸：當一個角色在**某幾條系譜**上累積到一定深度，敘事上他自然而然會獲得某些東西——可能是一個被動精煉，也可能是**一整條新的系譜樹**。這個機制刻意獨立於 `SkillPrerequisite`，用一張獨立維護的規則表描述。

## 1. 為什麼一張表就夠

兩種看起來不同的需求：

- 「劍術練到一定程度，自然悟出劍術精通」→ 授予一個被動技能
- 「水魔法與風魔法都練到一定程度，開啟霧魔法系譜」→ 開啟一整條樹

機械上其實是同一件事。[總覽與機械規則](/lore/skill-trees/index) §1 已經把「持有（ownership）」與「能用（usability）」徹底分開：前置條件限制的是後者，而 ownership 可以由匯入、劇情、統御術直接授予。因此「開啟一條新系譜」在引擎裡就等於「**授予那條系譜的根節點 ownership**」，根節點沒有前置，拿到就能開始練，整棵樹隨之變成可爬的。

兩種需求收斂成同一個動作：**把一組 skill key 加進持有集合**。所以不需要兩套機制，一張規則表覆蓋全部。

## 2. 規則表的形狀

每一條規則由「條件」與「授予」兩半構成：

| 欄位 | 說明 |
| --- | --- |
| `id` | 規則的穩定識別碼，與被授予的技能 key 無關（一條規則可以一次授予多個 key） |
| `requires` | 條件子句陣列，**全部滿足**才觸發（AND 語意） |
| `grants` | 觸發後授予 ownership 的 skill key 清單 |

每一個條件子句：

| 欄位 | 說明 |
| --- | --- |
| `scope` | 從哪些節點取樣。以 `category` 界定分支，可再以 `group`（元素 key）或 `line`（路線名）收窄 |
| `group_by` | 以什麼維度分群計數。元素魔法以 `group`（＝元素）分群，武藝以 `line`（＝路線）分群 |
| `distinct_groups` | 需要**幾個不同的群**各自達標。`1` 是「任一條」，`2` 是「任兩條不同的」 |
| `min_level` | 每個達標的群裡，至少要有一個節點的熟練度達到這個等級 |

示意（實際 YAML 欄位名由實作階段拍板，本頁只定義語意）：

```yaml
- id: precise_mana_control
  grants: [precise_mana_control]
  requires:
    - scope: { category: elemental_magic }
      group_by: group
      distinct_groups: 2
      min_level: 5
```

## 3. 現行規則（三條）

這三條規則授予的都是 [身心強化](/lore/skill-trees/enhancement) 的被動精煉技能。效果欄位是這些被動在 `combat_modifiers` 裡的**實際**數值，不是形容詞：

| id ／ 授予 | 條件 | 實際效果 | 人類・無親和所需次數 | 精靈・有親和所需次數 |
| --- | --- | --- | --- | --- |
| `blade_art_mastery`（劍術精通） | 武藝「劍術」路線任一節點 Lv.3 | 命中 +5 | 150 次 | 15 次 |
| `magic_circle_comprehension`（魔法陣理解） | 任一元素系譜樹任一節點 Lv.5 | 命中 +5 | 278 次 | 23 次 |
| `precise_mana_control`（精準魔力控制） | 任兩條不同元素系譜樹各有節點 Lv.5 | MP 消耗 −10% | 2 × 278 次 | 2 × 23 次 |

次數換算見 [總覽與機械規則](/lore/skill-trees/index) §1.1。武藝技能不套元素親和倍率，所以人類的劍術路線是 `50 × 3 ÷ 1.0 = 150` 次。

「劍術」路線指武藝系譜樹的九個節點：`basic_swordplay`、`flowing_strikes`、`tendon_sever`、`whirlwind_slash`、`thousand_blade_art`、`blade_storm`、`blade_saint_arts`、`thousand_army_slash`、`true_sword_saint`。**不含**影流刀術路線。影流是基亞蘭的暗屬性刀術，敘事上不會讓人悟出正統劍術的精通。

### 平衡意圖

`precise_mana_control` 是唯一一條要求**兩條不同元素樹**的規則，這是刻意的：元素親和倍率（親和 1.1、非親和 0.9）本來就懲罰廣度、獎勵專精，讓一個什麼都碰一點的施法者練得比專精者慢。這條規則正是那個懲罰的對沖，讓願意付出雙倍練習成本走廣度路線的角色，換到一個專精路線拿不到的通用增益。兩種玩法因此各有終點，而不是專精無條件較優。

## 4. 未來擴充：開啟新系譜

同一張表也能開樹。以「水魔法與風魔法都達到 Lv.3 之後開啟霧魔法系譜」為例（霧魔法目前不存在，僅示範規則形狀）：

```yaml
- id: open_mist_lineage
  grants: [mist_mastery, mist_bolt, mist_veil]   # 精通被動 ＋ 該樹的全部根節點
  requires:
    - scope: { category: elemental_magic, group: water }
      min_level: 3
    - scope: { category: elemental_magic, group: wind }
      min_level: 3
```

兩個子句、各自指名一個元素群，AND 成立才開樹。授予內容是**該樹的精通被動加上它的全部根節點**，精通被動讓這個元素真正成為角色的屬性（`element_mastery`、自由施法），根節點則讓整棵樹變成可爬的。根節點以上的每一層照舊由 `SkillPrerequisite` 把關，開樹不會跳過任何一階。

## 5. 硬性約束

以下是規則表必須遵守的機制邊界，違反任何一條的規則都應該在載入時就失敗，而不是在遊戲中默默失效：

1. **單調性：授予後永不撤銷。** 熟練度可能因為 cap 調整、資料修訂而在不同版本間變動，但已經授予的 ownership 不會被收回。否則一個角色可能在戰鬥中途失去技能。
2. **只授予持有，不授予熟練度。** 被授予的節點熟練度從 0 起算，一樣要自己練上去。開樹不等於跳級，授予被動也不等於送滿練度。
3. **門檻必須可達。** 節點的熟練度上限（cap）由消耗它的邊反推（見 [總覽](/lore/skill-trees/index) §1），元素樹的根節點 cap 普遍只有 3。因此 `min_level: 5` 的子句，其 `scope` 內**必須至少存在一個 cap ≥ 5 的節點**，否則這條規則永遠不可能觸發。載入時應直接檢查。
4. **只有 ACTIVE 節點能當條件來源。** 熟練度只在「使用」時累計，PASSIVE 技能沒有任何東西會使用它，永遠停在 Lv.0。`fire_mastery` 這類精通被動因此**不能**出現在條件的取樣範圍內——取樣時必須排除 PASSIVE。
5. **不得形成環。** 一條規則 `grants` 的 key，不得成為任何規則（包含自己）條件的取樣來源。否則會產生連鎖解鎖：開了霧魔法樹，練一練又自動開出第三棵樹。每一次開樹都必須是獨立的、由玩家自己付出練習成本換來的決定。
6. **與直接授予並存無衝突。** 匯入、角色模板、劇情授予都可以直接給予同一個 key 的 ownership。規則表只做加法，重複授予是無操作（no-op）。薇歐蕾特的角色模板一開始就持有 `magic_circle_comprehension` 與 `precise_mana_control`，這不影響規則表對其他角色的判定。

## 6. 實作掛載點

`world/rules/progression.py` 的每次練習授予路徑上，已經存在一個現成的鉤子：該函式在 `award_practice_xp()` 前後對「可能因此解鎖的候選技能」做一次 before／after 快照，把新變得可用的技能收集到 `unlocks_out`，由呼叫端轉成「新技能可用」的通知。

跨系譜規則表的評估應該掛在同一個位置，理由有三：

1. **熟練度只在這條路徑上變動。** 熟練度的唯一寫入者是 `award_practice_xp()`，所以規則表的條件只可能在這裡從不成立變成成立，不需要輪詢，也不需要在讀取路徑上重算。
2. **通知管道已經存在。** 「你悟出了劍術精通」「霧魔法系譜已開啟」與現行的「新技能可用」是同一種事件，可以共用同一條交付管道與同一套交易邊界（先提交再送出）。
3. **讀取路徑必須保持零副作用。** 持有集合（`SkillHandler.owned_keys()`）被戰鬥預覽、狀態查詢等唯讀路徑大量呼叫，把規則評估放進去會讓一次預覽產生持久化寫入。規則表必須是**寫入時觸發（push）**，不是讀取時推導（pull）。

同一條路徑上還有一個既有約束值得沿用：練習累計受「同一施法者、同一技能、同一目標，每個世界時鐘 tick 只計一次」限制，因此規則評估的頻率天然有上界，不會因為連續施放而反覆觸發。
