# 物品圖鑑：伊洛瑟恩大陸

本文件是「世界觀設定」分類下的物品專篇，統整伊洛瑟恩大陸目前已知的所有物品資料，供劇情撰寫、任務設計與物品資料落地時共同參照。閱讀本文前建議先讀過[世界觀總覽](/lore/overview)與[魔法技能體系](/lore/magic-system)，物品的產地、效果與定價都建立在那兩篇的地理、種族與魔法設定之上。

與 `docs/development/adding-items.md` 不同，本文記錄的是「這件物品在世界觀裡是什麼」的設定真相，而非資料落地的操作步驟；兩篇文件描述的是同一套資料模型，前者負責意義、後者負責流程。目前 `world/lore/items.py` 中的 `ITEM_REGISTRY` 是開發初期為了跑通系統而暫定的資料，數量與設定深度都遠不及本文。本文才是物品資料的世界觀設計來源，之後落地或調整程式碼資料時，應以本文為準，不能反過來拿現有程式碼限制本文的內容。

所有標示為「設計參考值」的數字，都是尚未經過遊戲測試調校的世界觀合理值，正式數值以落地時的確定性 rulebook（`world/rules/rulebook/*.yaml`）為準，兩者不一致時不需要回頭改動本文去遷就實作。

## 物品資料模型

伊洛瑟恩的物品資料分成五層，身分與外觀住在不可變的物品清單，所有可調數值分別住在四份獨立的確定性規則表。這個「身分與數值分離」的設計，讓劇情設定與遊戲平衡可以各自演進而不互相牽制。以下逐層列出系統目前定義的每一個欄位。

### 第一層：識別與可交易性

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `key` | 字串 | 物品的唯一識別碼，英文小寫加底線，例如 `healing_potion`；一旦發佈不可更名 |
| `display_name_zh` | 字串 | 玩家看到的正體中文名稱 |
| `price_table_key` | 字串 | 指向下方價格帶表的分類鍵，決定這件物品的合理成交區間 |
| `sellable` | 布林值 | 是否可以在商店買賣；「信物」一律為否 |

### 第二層：外觀呈現（presentation）

三個欄位都是封閉詞彙，任何新增值都必須先擴充列舉才能使用，行為規則一律不得從這三欄推測。

| 欄位 | 封閉詞彙成員 |
| --- | --- |
| `kind`（物品類別，純視覺分類） | 食物 `food`、藥劑 `potion`、武器 `weapon`、防具 `armor`、飾品 `accessory`、性玩具 `toy`、彈藥 `ammunition`、工具 `tool`、素材 `material`、雜物 `misc` |
| `icon_key`（圖示鍵，Vue 端自行映射 SVG） | 與 `kind` 使用同一組詞彙，兩者通常取相同值 |
| `rarity`（稀有度，僅供視覺呈現與裝備數值預算，不影響售價或掉落機率） | 普通 `common`、稀有一階 `uncommon`、稀有 `rare`、史詩 `epic`、傳說 `legendary` |

性玩具 `toy` 是本文相對於現行程式碼唯一新增的成員，落地時必須同步擴充伺服端的兩個列舉與 Vue 端的圖示映射表，兩邊缺一不可。彈藥 `ammunition` 則相反：列舉早已保留，但本文沒有任何物品使用它（原因見〔未來擴充方向〕）。

`summary_zh` 是每件物品的一句話介紹，必須非空、不超過 128 個字元、單行純文字、不含 `<` 符號、不含網址、不含表情符號。本文下方每張物品表的「簡介」欄都遵守這個限制。

### 第三層：機制（三選一）

一件物品只能是下列三種形狀之一，機制欄位互斥，`kind` 不會影響機制。

| 形狀 | 欄位組合 | 適用類別 |
| --- | --- | --- |
| 可使用 | `use_mechanics = { consumable, combat_allowed }`（使用「做什麼」由使用效果規則表依物品 `key` 宣告，見第六層） | 藥劑、性玩具（可用型） |
| 可裝備 | `equipment_slot` + `modifier_key`（必須成對出現，且 `modifier_key` 的值必須等於物品自己的 `key`） | 武器、防具、飾品、性玩具（配戴型） |
| 純觀察 | 兩者皆無，只能持有、檢視、買賣 | 食物、工具、素材、雜物、多數信物 |

`equipment_slot` 的封閉詞彙是主手 `weapon_main`、副手 `weapon_off`、護甲 `armor`、飾品 `accessory`（飾品槽共用五件上限）。`modifier_key` 是每件已註冊裝備各自專屬的鍵，全大陸目前已命名的裝備鍵見下方各分類表。

### 第四層：貨幣與價格帶

大陸通用貨幣是「1 金 = 100 銀 = 10000 銅」，物品的 `price_table_key` 指向下表其中一列，決定合理成交區間的上下界；商店的實際成交價（`buy_copper`／`sell_copper`）必須落在這個區間內才會通過驗證。

| 價格帶 | 中文名稱 | 下限（銅） | 上限（銅） | 說明 |
| --- | --- | --- | --- | --- |
| `meal` | 普通餐食 | 5 | 10 | 一份普通餐食 |
| `specialty_food` | 特產食品 | 10 | 100 | 各地名產與精製食品 |
| `potion` | 魔法藥劑 | 50 | 500 | 常見魔法藥劑 |
| `plain_sword` | 普通劍 | 100 | 500 | 一般冒險者的入門劍 |
| `mundane_weapon` | 普通兵器 | 100 | 2000 | 非魔法鍛造武器 |
| `magic_weapon` | 魔法武器 | 100000 | 無上限 | 附魔武器，起價十金 |
| `armor` | 防具 | 200 | 5000 | 身體與副手防具 |
| `jewelry` | 首飾 | 100 | 5000 | 一般配戴的首飾 |
| `magic_accessory` | 魔法飾品 | 10000 | 100000 | 附魔的穿戴飾品 |
| `intimacy_tool` | 情趣器具 | 50 | 20000 | 聖所、浴場與匠作流通的情趣道具 |
| `tool` | 魔法工具 | 30 | 300 | 常見附魔實用工具 |
| `material` | 魔法素材 | 20 | 無上限 | 稀有素材開放定價 |
| `relic` | 信物 | 999999 | 無上限 | 不可交易的絕版物件與身分證明 |
| `inn_stay` | 普通旅館一晚 | 20 | 20 | 住宿服務定價，非物品分類 |
| `commoner_annual_income` | 平民年收入 | 50000 | 100000 | 世界觀經濟基準，非物品分類 |
| `adventurer_annual_income` | 冒險者年收入 | 100000 | 1000000 | 依公會等級而定，非物品分類 |

最後三列不對應任何物品，分別是住宿服務的定價與換算購買力時的世界觀基準，收錄於此是為了讓「物品清單」與「所有已定義欄位」完整對齊。每張物品表的「參考買價」都已逐列核對過所屬價格帶的上下界，商店驗證不會退件。

### 第五層：商店流通欄位

每家商店的每筆進貨資料獨立於物品身分之外，欄位有成交買價 `buy_copper`（必須落在價格帶區間內）、成交賣價 `sell_copper`（只要求非負且不超過買價，不受價格帶下限約束）、庫存上限 `max_stock`、初始庫存 `initial_stock`、每次補貨量 `restock_quantity`。本文各物品表列出的「參考買價／賣價」即依循這組欄位定義給出設計參考值。

### 第六層：使用效果欄位（item_effects）

可使用物品的 `use_mechanics` 只聲明「能否使用、使用是否消耗、能否在戰鬥中使用」三件事；使用「做什麼」是一組有序的型別化效果條目，以物品 `key` 為鍵住在使用效果規則表（`world/rules/rulebook/item_effects.yaml`），由 `world/rules/item_effects.py` 的載入器驗證。

| 欄位 | 說明 |
| --- | --- |
| `consumable`（物品清單欄位） | 使用後是否消耗掉這件物品 |
| `combat_allowed`（物品清單欄位） | 是否能在戰鬥中使用 |
| `items:`（規則表） | 以物品 `key` 為鍵，每件可使用物品恰好一筆、至少一個效果條目；每個條目恰好聲明一個動詞欄位（`stat`＋`amount`／`apply_status`／`remove_status`），可選 `scope`（五檔封閉詞彙：`self` 預設／`single`／`all-allies`／`all-enemies`／`all`，見下方範圍說明） |
| `scope`（效果條目欄位） | 效果觸及誰：`self` 只觸及使用者；`single` 需要玩家指定一個在場實體（缺少目標以穩定原因拒絕）；`all-allies`／`all-enemies`／`all` 是群體範圍，由規則書固定、玩家不可選——戰鬥中依戰場名冊的敵我與擊倒狀態展開，戰鬥外展開為在場所有實體（敵我關係在戰鬥外全視為友方，`all-enemies` 因此沒有可觸及的對象而拒絕）。目標解析走技能共用的目標解析器（在場／存活／距離／陣營同一條驗證鏈） |
| `stat` | 計量條封閉詞彙：生命 `hp`、魔力 `mp`、體力 `sp`、快感 `pleasure` |
| `amount` | 帶號非零整數，絕對值上限 9999；正值抬升計量條，負值消耗且到零停止（日誌回報實際降幅） |
| `apply_status` | 一個具體狀態鍵（狀態規則表的定義鍵）；選擇器不接受 |
| `remove_status` | 具體狀態鍵，或選擇器 `all`／`positive`／`negative`（淨化不帶量級） |
| `item_use_seconds`（規則表全域欄位） | 非戰鬥狀態下使用一件可用物品耗費的世界時間，目前設計值為 6 秒 |

載入器在啟動時做**雙向封閉檢查**：規則表的物品鍵集合必須恰好等於已註冊可使用物品的鍵集合，任何一邊缺條目即啟動失敗。結算依宣告順序逐條執行；單獨無效的步驟（目標計量條已滿、狀態遭裝備免疫擋下、移除選擇器沒命中任何狀態）會被跳過，只有全部步驟都無效時整個使用才被拒絕並退還物品。

群體範圍的一次使用只消耗一件物品：結算在單一交易內為「每個有效效果×每個有效目標」各規劃一個步驟，事件日誌每個實際寫入的步驟各列一條 `item_used`；回滾日記按被觸及的每個實體各自捕獲計量條、狀態與性狀態，復原時逐實體走過同一條快取丟棄路徑。

目前四件可使用物品的設計參考量級：治療藥水 `healing_potion` `hp +40`、強效治療藥水 `greater_healing_potion` `hp +120`、魔力藥水 `mana_potion` `mp +40`、受洗聖水 `baptismal_holy_water` `remove_status: negative`。

過去掛號的「解毒」「回體（`sp`）」「持續回春」「催情（`pleasure`）」如今都是單純的規則表資料——計量條調整（含負值與快感）、施加具體狀態（如既有狀態鍵 `item_regen_light`）、移除狀態（含 `negative` 選擇器）全是現成動詞，新增不再需要效果鍵列舉擴充；以一個假想解毒補劑為例：

```yaml
items:
  # 假想範例：解毒（移除中毒）＋回血＋定神，純 YAML 即生效
  antidote_tonic:
    effects:
      - remove_status: poisoned
      - stat: hp
        amount: 20
      - apply_status: focus
```

要把它綁定到具體藥劑（新增物品或改寫既有效果）仍是設計決定，但機制層面不再卡規格。

### 第七層：裝備效果欄位（equipment_effects）與稀有度預算

裝備的數值同樣不住在物品清單，而是由 `modifier_key` 綁定到裝備效果規則表的一筆條目。

| 欄位 | 封閉詞彙／型別 | 說明 |
| --- | --- | --- |
| `adjustments` | 平值欄：攻擊 `atk_phys`、防禦 `defense`、魔力 `magic_power`（皆為整數）；百分比欄：施法耗魔 `mp_cost`、動作耗體 `sp_cost`、快感增益 `pleasure_gain`、治療增益 `heal_gain`（皆為 `+N%`／`-N%` 字串）；敏捷 `agility` 兩種型別皆可 | 這件裝備對各項數值的調整方向與幅度 |
| `exposure_bias` | 整數 | 露出偏向。它與 `adjustments` 平行，是條目自己的頂層欄位，**不寫在 `adjustments` 裡** |
| `gauge_caps` | 生命 `hp`、魔力 `mp`、體力 `sp` 的資源上限加值，正整數，單筆上限 9999 | 只在穿著期間存在，卸下即失效且可能造成即時封頂損失 |
| `immune` | 狀態鍵列表 | 穿著期間對列出的負面狀態完全免疫 |
| `attached_buffs` | 增益狀態鍵列表 | 穿著期間持續掛載的增益，卸下即消失 |

`budgets` 依裝備自身的 `rarity` 決定每欄可用的數值上限，稀有度因此只是「這件裝備能塞多少數值」的預算門檻，不是效果好壞的直接保證：

| 稀有度 | 平值上限 `flat` | 百分比上限 `percent` | 軟百分比上限 `soft_percent` | 露出偏向上限 `bias` | 資源上限加值 `gauge` |
| --- | --- | --- | --- | --- | --- |
| 普通 common | 4 | 5% | 10% | 0 | 5 |
| 稀有一階 uncommon | 6 | 8% | 15% | 1 | 10 |
| 稀有 rare | 8 | 10% | 20% | 1 | 15 |
| 史詩 epic | 10 | 12% | 25% | 2 | 20 |
| 傳說 legendary | 12 | 15% | 30% | 2 | 25 |

各欄對應的預算欄位是固定的：`atk_phys`／`defense`／`magic_power` 與平值型的 `agility` 走 `flat`，`mp_cost`／`sp_cost` 與百分比型的 `agility` 走 `percent`，`pleasure_gain`／`heal_gain` 這兩個社交向欄位走較寬鬆的 `soft_percent`，`exposure_bias` 走 `bias`，`gauge_caps` 走 `gauge`。

普通裝備的露出偏向上限是 0，這屬於刻意設定。世界觀上，量產的入門裝備不該左右親密系統的判定，露出偏向是稀有以上裝備才夠格擁有的敘事重量。

| 信物 | `sellable = false` 的不可交易物件：獨一無二的絕版品，或不可轉讓的身分證明 | 普通至傳說 | 王室、精靈鍛造、冒險者公會 |

## 食物

食物是三國日常生活最普遍的物資，價格帶依定位分成兩檔。最常見的日常餐食掛 `meal`（5～10 銅），對應〔世界觀總覽〕「平民年收入 5～10 金」的購買力基準——一介平民不吃不喝也要工作一整年才存得下一千頓飯的錢，這個比例讓「一頓飯」在敘事上始終是輕量級的存在。各地名產與精製食品則掛 `specialty_food`（10～100 銅）：吃得起是一種小小的奢侈，但仍遠遠買不起任何一件裝備。

食物目前全是純觀察物件，不掛 `use_mechanics`。要讓某件食物「吃了回體力」在機制上早已沒有障礙（`stat: sp` 是現成動詞），那只是一道還沒做的設計決定。

| 名稱 | 稀有度 | 產地／文化 | 價格帶 | 參考買價／賣價（銅） | 簡介 |
| --- | --- | --- | --- | --- | --- |
| 普通餐食 `meal` | 普通 | 三國通用 | `meal` | 10／5 | 供旅人充飢的普通餐食 |
| 王國黑麥硬麵包 `kingdom_rye_hardtack` | 普通 | 王國西部丘陵 | `meal` | 8／4 | 礦工下坑必帶的黑麥硬麵包，耐嚼且扛餓 |
| 冒險者攜行口糧 `adventurer_field_ration` | 普通 | 冒險者公會 | `meal` | 10／5 | 公會統一配發的壓縮口糧，D 級以下常見裝備 |
| 帝國蜜漬果乾 `imperial_candied_fruit` | 普通 | 帝國東南港口 | `specialty_food` | 15／8 | 東南港口特產的蜜漬水果乾，耐放又香甜 |

> 「靈露」是〔素材〕「精靈體液」的下游製劑，呼應〔世界觀總覽〕與〔魔法技能體系〕「體液可用於製作高階藥劑」的設定。流通鏈設計為：**精靈村落內部不販售體液——原因不是禁忌，而是每個精靈都能自產，村內不存在買賣需求（見〔聚落地點指南〕）；原料流出人類社會的常態管道是「贈與」，數量極少，而村外的精靈要不要拿去賣則世界觀刻意不規定（對精靈是零成本自產物，對外界是天價素材，留給個別角色的劇情處理）**。液態原料又必須保持鮮活，保鮮門檻進一步壓低能撐到帝國鍊金坊工房的新料數量，因此市面上買到的永遠是二手精製品。參考買價掛 `material` 價格帶（開放定價）而非 `potion` 帶，反映單價遠超一般藥劑的事實。
>
> **催情定位的世界觀依據**：精靈體液的核心效力是極強的催情作用，這與〔光屬性系譜樹〕的裡設定「快感與生命力是同股魔力」直接同構——〔聖禮〕節點「女神之乳」本就以口唇相接的體液交換施為，並附帶快感推進。靈露「飲下後傷口高速閉合」的傳聞因此不是另一個效果，而是催情效果的下游結果：興奮被推到高位後，既有的興奮→回復恩寵規則（`combat_modifiers.yaml` 已實裝）自行接手。機制上「快感推進」已是現成動詞：`stat: pleasure` 的正向計量條調整在結算時走情慾系統的共享快感寫入器（`world/rules/pleasure.py` 的 `apply_pleasure_gain` 唯一入口），複用既有的興奮→wetness→high .CASCADE 判定，不新造增量；溫和／中等／強烈三檔直接取 `stimulus_applied` 幅度帶（`+8..+14`）的三段設計值，也就是 `+8`／`+11`／`+14`。催情一律以這組快感條目表達，不新增任何狀態鍵。「迷情藥」是效力溫和的人類製品對照組，靈露的「極強」正是相對於它的台階。兩者的副作用（成癮、理性判定、對親密系統抵抗判定的影響）都屬於文末留白待填。

## 未來擴充方向

比照〔世界觀總覽〕的「尚待擴充的謎團」，物品清單也刻意留下幾條路。

- **彈藥的消耗機制**：`ItemKind`／`ItemIconKey` 早已保留 `ammunition` 成員，但 `EquipmentSlot` 沒有彈藥槽、系統也沒有「消耗箭矢」的戰鬥承接。本文因此不收錄任何箭矢與投擲物——沒有機制承接的一整個分類只會是死資料。等射擊消耗機制設計出來，再連同分類與資料一併補上。
- **藥劑效果的具體綁定**：解毒、體力回復、持續回春、催情（快感推進）在型別化效果模型下都是規則表現成資料（`remove_status`、`stat: sp`、`apply_status: item_regen_light`、`stat: pleasure`），缺的只是決定哪件藥劑掛哪組條目的設計審查；〔藥劑〕表中標為「候補效果」的迷情藥與靈露就是在等這一關，催情牽扯情慾系統（`stimulus_applied` 幅度帶、共享快感寫入器入口、親密抵抗判定）的判定交互也要連同定案。
- **性玩具分類的落地**：〔性玩具〕段的效果側已是規則表現成資料（`stat: pleasure` 條目），剩下的是 `ItemKind`／`ItemIconKey` 新增 `toy` 與 Vue 端的圖示映射，即可進入資料落地流程。
- **獨立商店通路的落地**：〔性玩具〕與部分精靈商品的敘事通路是聖所器具商店與精靈村商店，但目前全大陸只有阿爾托利亞雜貨商店一家已落地的商店。新開一家店要連同店主 NPC 與所在地點一起設計，屬於物品資料之外的獨立工作。
- **不進商店物品的取得管道**：〔武器〕龍之巢穴戰利品劍、〔素材〕古龍心臟這類標為「不進商店」的物品目前只能登錄身分，沒有掉落或任務獎勵的管道承接。
- **冒險者公會等級徽章**：已落地的只有公會見習徽記一件，F～A 各級徽章與晉升時的授予流程仍待設計。
- **迷宮素材與怪物的真正對應表**：本文的素材分類只依〔世界觀總覽〕的魔獸分級給出合理範例，尚未與正式的怪物資料庫逐一對應掉落來源。
- **精靈體液煉金的上限**：〔世界觀總覽〕提到精靈體液是稀有魔法素材，但煉金能做到什麼程度、有沒有副作用，目前仍是留白，供未來的鍊金相關任務發揮。〔藥劑〕分類的「靈露」是第一個掛號的衍生製品，其催情強度階梯（相對黑市迷情藥）、副作用（成癮、理性判定、親密抵抗判定）都屬於這條留白待填的內容。
